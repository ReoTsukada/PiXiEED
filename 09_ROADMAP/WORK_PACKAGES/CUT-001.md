## Canonical role

Execute a separately authorized production cutover only after qualification and explicit Owner authorization. This definition is subordinate to `00_START_HERE/WORK_PACKAGE_REGISTRY.json`; the Registry owns status, dependencies, routes, write scope, and handoff truth.

## Blocked boundary and preconditions

CUT-001 is `BLOCKED` until a named Owner gives explicit written authorization for the exact scope, date/window, artifact hashes, host/routes, data domains, and rollback authority. Before any action, all G0-G9 required gates, WP-990 decision packet, independent review, legal/accounting approvals where applicable, backup/restore proof, current-route fallback, kill switch, monitoring, and rollback artifact must be valid and unexpired. Authorization for one scope does not authorize another.

No production write, route switch, migration, store submission, native deploy, publish, real payment/payout, current PiXiEEDraw retirement, or cutover occurs from this definition alone.

## Acceptance and evidence

- `CUT001-AUTH-001`: Verify Owner authorization signature/identity, exact scope, artifact/source/config/storage hashes, maintenance window, named operator/reviewer, allowed commands, stop criteria, and expiration. Reject absent, broad, stale, or mismatched authorization.
- `CUT001-DRYRUN-001`: Execute a production-equivalent dry-run with the same artifact/config/commands; verify preflight, backup, schema/storage/provider checks, flag/route plan, current fallback, and expected no-op/write set. Record raw output and prove no Production mutation during dry-run.
- `CUT001-ROLLBACK-001`: Verify rollback artifact and commands against the exact release, kill switch, route fallback, backup restore, and operator access. Define abort at preflight, partial write, error threshold, security event, reconciliation mismatch, or monitoring loss. Rollback is a tested procedure, not a text-only plan.
- `CUT001-RECON-001`: Before and after the authorized window, reconcile Project/Asset/PXD/PiXiSYNC, URL/Product/File, Entitlement/License, Money/Royalty/Ledger, event backlog, and notification identity. Require exact integer money totals, zero unexplained missing/duplicate events, and explicit handling of `確認中`; never substitute false zero.
- `CUT001-OBSERVE-001`: Observe the agreed window with privacy-safe telemetry, route/flag/latency/error/memory/event/reconciliation dashboards, support trace, and current fallback checks. Record continue/abort/rollback decision, operator/time, post-window backup, and independent review. If observation is unavailable, status is `UNTESTED` and cutover cannot be complete.

## Evidence contract

Each record contains authorization reference, environment/window, exact artifact/config hashes, command/protocol, redacted raw output, before/after reconciliation, rollback result, observation samples, reviewer, timestamp, and status. No JWT, email, secret, Project content, personal request content, payment credential, or private key may be recorded. Any unmeasured, synthetic, stale, or unavailable item remains `UNTESTED`; it cannot be promoted to PASS.

## Stop rules

- Preserve current Market, PiXiSYNC, URLs, data, production fallback, and dirty worktree until explicit authorized completion.
- Stop immediately on authorization mismatch, backup/restore failure, non-zero money mismatch, event gap/duplicate, security/privacy issue, threshold breach, monitoring loss, rollback failure, new baseline failure, or operator ambiguity.
- Never commit, push, publish, or automatically start another package. A rollback or abort must leave the current fallback usable and be reconciled before resumption.

## Handoff

Complete only after authorized execution, dry-run, rollback, reconciliation, observation, Checkpoint, and independent review are recorded. The next package is `none`; `autoStartNext: false`. Wait for explicit Owner instruction.
