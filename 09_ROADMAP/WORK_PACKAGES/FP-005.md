## Objective

Implement one privacy-safe, tenant-scoped storage and input boundary for the isolated Core. Every
accepted value is classified before persistence; every locator is validated before access; every
diagnostic is redacted before logging. The policy is fail-closed and does not change existing
production Storage, database rows, routes, Market, PiXiSYNC, PXD, or user data.

## Prerequisites and canonical inputs

- FP-004 is independently approved and its bounded Event/Inbox/Outbox records are the only event
  inputs accepted by this package.
- Use `02_ARCHITECTURE/STORAGE_PLACEMENT_AND_SYNC.md`, Project/Asset/Package Registry contracts,
  FP-001 AuthorizationProofV1, and the current Core identity/tenant/resource vocabulary.
- Define a versioned `StoragePolicyV1`, `InputLimitPolicyV1`, `RedactionPolicyV1`, and
  `RetentionPolicyV1`. Limits may only change with a schema/ADR update, never per caller.

## Canonical storage placement

| Data class | Canonical location | Forbidden placement |
|---|---|---|
| active raster/audio/game state, selection, tool state | Memory | treating memory as durable |
| Journal, index, queue, checkpoint metadata, small settings | IndexedDB | large raw blobs or secrets |
| large tiles/chunks, audio bytes, waveform/build/preview cache, large checkpoints | OPFS | authority metadata or unvalidated paths |
| owner, membership, rights, revision, dependency, hash/size/type metadata | Server Database | raw media/package bytes in rows |
| immutable asset/media/package/backup/thumbnail blobs | Object Storage | caller-selected bucket/path or mutable overwrite |

The implementation must return a typed locator and hash/size/MIME metadata, not expose arbitrary
provider handles. A local locator is never accepted as a server locator and vice versa.

## Invariants and initial reference limits

1. A value has exactly one canonical placement and a typed owner/tenant/resource binding. Cross-
   tenant access, unscoped locator, path traversal, or authority mismatch is denied.
2. Structured input is limited by versioned policy: `maxEnvelopeBytes=262144`, `maxJsonDepth=16`,
   `maxCollectionItems=10000`, `maxStringBytes=65536`, and `maxPathBytes=1024`.
3. File/path policy allows relative normalized paths only: `maxPathSegments=32`; reject empty,
   absolute, `..`, encoded traversal, NUL/control characters, backslash ambiguity, and duplicate
   normalized paths. Archive policy rejects more than 100000 entries, expanded bytes over 2 GiB,
   a compression ratio over 100, symlinks, active content, and nested archives.
4. Reference blob limit is `maxBlobBytes=536870912`; callers cannot raise it. Product-specific
   smaller limits are allowed only as a named policy version. Quota exhaustion fails before write.
5. Logs and diagnostics contain no JWT, cookie, Authorization header, secret, email, phone,
   address, payment data, raw project body, pixel/audio bytes, or private commission content.
   Stable opaque ids and hashes are allowed.
6. Retention and deletion are explicit policy decisions. Queue/checkpoint/cache cleanup cannot
   delete canonical authority or purchased/entitled bytes, and cleanup is tenant-scoped.

## Attack and failure matrix

| Fixture / injection | Required assertion | Evidence |
|---|---|---|
| Memory value marked durable | Reject or route to the correct durable class | `FP005-STORAGE-001` |
| Raw blob inserted into IndexedDB/DB metadata | Reject placement and emit redacted diagnostic | `FP005-STORAGE-001`, `FP005-PII-001` |
| Cross-tenant Project/Asset/locator | Deny before provider read/write; no existence leak | `FP005-STORAGE-001` |
| `../`, absolute, encoded traversal, NUL, symlink, duplicate path | Reject normalized path/archive | `FP005-PATH-001` |
| Oversized/deep/cyclic JSON, huge collections/string, zip bomb | Reject within bounded work; no allocation of unbounded input | `FP005-INPUT-001` |
| SVG/HTML/script/macro/active archive or MIME/content mismatch | Reject or quarantine; never execute | `FP005-INPUT-001` |
| Missing/expired/revoked AuthorizationProof | Deny before access; no fallback Boolean | `FP005-STORAGE-001` |
| Quota full, interrupted write, truncated blob, hash/size mismatch | Preserve prior valid record; return typed failure; recover safely | `FP005-STORAGE-001` |
| Telemetry containing JWT/email/secret/private content | Redact/drop fields; test serialized output | `FP005-PII-001`, `FP005-TELEMETRY-001` |
| Retention cleanup with another tenant or entitled asset | No cross-tenant or protected deletion | `FP005-STORAGE-001` |

## Performance, security, privacy, and compatibility

- Measure validation time and peak memory for 1 KiB, 256 KiB, 1 MiB rejected, and archive-limit
  fixtures. Large-byte hashing/streaming must be bounded and must not block the editor hot path.
- Security is deny-by-default: re-resolve current tenant/resource authority before provider access,
  never trust caller bucket/path/MIME/size, and never reveal whether another tenant's object exists.
- Privacy is retention-aware and minimum-data: evidence stores hashes and opaque fixture ids, not
  real private content. Diagnostics are deterministic enough to compare without payload disclosure.
- Compatibility is contract-level only. Existing PXD/PiXiSYNC/Market data is read-only out of
  scope; legacy locators require a named adapter and explicit migration plan, not silent coercion.
