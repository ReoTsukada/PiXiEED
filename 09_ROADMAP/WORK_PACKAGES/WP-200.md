## Scope authority and provenance

The earlier WP-200 work-package file was not present in the repository. This definition is
reconstructed from the approved roadmap, the supplied WP-200 audit direction, the PiXiGame and
PiXiRuntime product specifications, the Build/Export Pipeline, the Integrated PiXiPackage and
Asset Graph contracts, the Cost-aware Realtime Policy, and the existing WP-160 Runtime/Build
contracts. The reconstruction is recorded in `ADR-20260809-WP200-game-runtime-bridge.md`.

This Work Package implements an isolated Core Bridge. It does not claim a shipped PiXiGame Editor,
public Runtime, native exporter, or production Build service.

## Canonical objective

Connect the existing Core references into one deterministic Game Project / Runtime boundary:

```text
Draw2 Asset Revision ─┐
                      ├─ Game Project Revision → Package Dependency Lock → Build Plan
PiXiAudio Revision ───┘                                      ↓
                                                   verified Runtime Artifact
                                                              ↓
                                                    isolated PiXiRuntime
```

The bridge must use the existing typed IDs, Asset Revision/Hash/Dependency semantics, Package
lock, License/Provenance boundary, Feature Flag/Kill Switch rules, and WP-160 Runtime/Build
contracts. It must not create a parallel identity or operation system.

## Required implementation

- Game Project Revision with deterministic Scene/Entity/Component and Input Action data.
- Draw and Audio references as `Asset ID + Revision ID + Hash + provenance`, never silent copies
  or raw Blob bytes in the Core contract.
- Basic bounded behavior representation suitable for Beginner/Event Sheet/Advanced modes to share
  one canonical state. Arbitrary script execution is not part of this Work Package.
- Runtime Preview adapter using the existing WP-160 Runtime boundary, semantic controls, and
  capability profiles for keyboard, pointer, touch, and gamepad.
- Safe preview revision update: LIVE may update at an explicit safe boundary; PINNED or incompatible
  dependencies are rejected; failed updates restore the previous valid session.
- Versioned Runtime Save State kept separate from editable Game Project state and Dependency Lock.
- Game Build Plan and artifact provenance containing Project Revision, Package, Dependency Lock,
  Runtime, target, configuration, and deterministic cache identity.
- Build security checks for unauthorized/quarantined/missing/cyclic/mismatched dependencies,
  unsafe paths/URLs/active content, unsupported versions, and unverified artifacts.
- Explicit cancellation/recovery states. Failed, cancelled, partial, or unverified output cannot
  become `READY`, executable, published, or sold.
- Lazy/editor/build/runtime bundle boundaries. Game Editor and Build tooling must not enter the
  Draw2 Initial Editor bundle; Runtime must not load Editor UI, Workspace, Audio Editor, or full
  Registry clients.

## Explicit non-scope

- Current PiXiEEDraw replacement or route cutover.
- Current PXD mass conversion, user-project migration, or PiXiSYNC migration.
- Production Database/Storage, Market, purchase, entitlement, royalty, Stripe, or public publish.
- Native C++/C#/Unity/Blender export, unrestricted user-script execution, cloud Build, or Store
  submission.
- Full PiXiGame UI. UI integration remains an isolated/lazy follow-up boundary and unavailable
  surfaces must not be presented as implemented.

## Acceptance gates

1. Game Project fixtures validate deterministic IDs, scenes, entities, components, controls, and
   Draw/Audio locked references.
2. Preview maps device input to semantic Actions and preserves Runtime state across compatible LIVE
   revision updates; PINNED/incompatible updates fail closed with recovery diagnostics.
3. Build Plan and artifact provenance are deterministic and include the exact Dependency Lock and
   Runtime/target/configuration identity.
4. Security, unsupported-version, missing dependency, cycle, hash, cancellation, and unverified
   output fixtures pass.
5. Default-off flags and kill switch prevent execution without an explicit isolated test decision.
6. Runtime, Build, Game Core, Audio, and Draw2 Initial Editor bundle boundaries are measured
   separately using the WP-190 definitions. No production Runtime or current route is modified.
7. Existing approved Baseline Failure Identity remains 14/14 with new identity count 0. WP-000
   through WP-190 implementation suites are not re-run.
