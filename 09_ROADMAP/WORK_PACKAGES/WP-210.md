## Canonical objective

Define and test an isolated, read/validate/reconcile bridge for the existing Market and rights
contracts without connecting Draw2, Game Runtime, Package Registry, or a new UI directly to
payment or entitlement mutation:

```text
Package identity + locked revision
              ↓ reference only
Market Product projection (MATERIAL | COMPLETED_WORK)
              ↓ existing server-authoritative checkout boundary
Purchase → Entitlement → License Snapshot → signed delivery
              ↓
Royalty / Ledger compatibility projection
```

`MATERIAL` and `COMPLETED_WORK` are the only Market content classifications in this package.
Package kind, publication method, license rights, price, purchase, entitlement, royalty, and
payout are separate concepts. Published and purchased material is PINNED; LIVE is authoring-only.

## Required implementation

- A typed Market Product projection containing only Package ID/version/hash/dependency/license
  references and Market-owned publication/price/status metadata; no raw Blob, JWT, PII, or project
  body.
- A read-only legacy Product/Order/License adapter preserving IDs, URLs, status, package refs, and
  historical amounts. Conflicts quarantine instead of silently remapping or reusing an ID.
- Deterministic, idempotent purchase, payment-event, entitlement, license, royalty, and ledger
  reconciliation fixtures. Duplicate events are no-ops; invalid transitions fail closed.
- Purchased-package survival: source deletion/tombstone does not invalidate an existing locked
  purchase package or license snapshot. Subscription access remains separate from purchase
  entitlement.
- A provider/Stripe command boundary that creates typed opaque commands only. It must not call
  Stripe, Supabase, Edge Functions, Storage, or a current route.
- A local rollback/shadow projection that restores the last valid snapshot without applying a
  production mutation.
- Default-off flags, unknown-flag fail-closed behavior, kill switch, security-safe diagnostics,
  and audit-safe redaction rules.
- Lazy Market adapter/bundle evidence. It must not enter Draw2 Initial Editor, WP-160 Runtime,
  WP-200 Runtime, or the current Market route.

## Acceptance gates

1. Product projection accepts exactly `MATERIAL` or `COMPLETED_WORK`, preserves Package/Asset
   references, rejects raw media and financial-body leakage, and distinguishes publication from
   rights.
2. Legacy Product/Order/License mapping preserves historical identity and URLs; ambiguity,
   missing locks, unsafe paths, and ID reuse are quarantined.
3. Purchase → payment confirmation → entitlement/license → delivery projection is deterministic,
   idempotent, subscription-independent, and safe under reverse/restore/tombstone cases.
4. Royalty/ledger records remain integer minor-unit/currency values with no historical recalculation
   or floating-point conversion.
5. Provider commands contain no secret, JWT, email, checkout token, raw webhook, or project body;
   rollback is local/shadow-only and explicit.
6. Market lazy bundle is outside Initial Editor and Runtime baselines; current routes and data are
   untouched; existing WP-200 bundle baselines remain unchanged.
7. Approved Baseline Failure Identity remains 14/14 matched with new identity count 0. Prior
   packages are not re-executed.
