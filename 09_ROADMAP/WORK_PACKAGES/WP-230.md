## Canonical objective

Implement an isolated, deterministic social/community projection that connects references to Core
entities without replacing current SNS, Market, PixFind, Creator, or public URL paths:

```text
explicit Share Command
  → Post reference
  → Comment / Reaction / Mention projections
  → Creator / Community / My Page projections
  → trusted Event reference
  → Notification / Search / Public URL adapters
```

`Message ≠ Post ≠ Comment ≠ Follow ≠ Reaction ≠ Mention ≠ Market Card`. A Market Card is a
reference to a Market Product/Package; it does not create a Product, Purchase, Entitlement, License,
Royalty, or Payout. Direct Work Agreement, Delivery, Acceptance, Rights, Payment, and Ledger remain
WP-220 records and are never replaced by social text.

## Required implementation

- Typed Post, Comment, Follow, Reaction, Mention, Community, Creator Page, My Page, and Market Card
  references with stable IDs and explicit visibility/lifecycle states.
- Post creation only through an explicit Share Command with server-resolved Creator authority.
- Asset/Revision/Package/Market/PixFind references and content hashes; no raw public-media bytes,
  Base64, Data URL, private body, JWT, Email, Secret, or payment data in the Core.
- Server-scoped visibility and permission decisions for PUBLIC, UNLISTED, PROJECT_MEMBERS,
  CREATOR_PRIVATE, and PRIVATE resources; client-side filtering is never authorization.
- Comment, Reaction, Follow, and Mention idempotency/conflict fixtures. Mention and notification
  references contain IDs and presentation metadata only, not comment/Post bodies.
- Market Card bridge that can reference an existing Product/Package and preserved URL without
  creating or mutating Market commerce state.
- Creator Page and My Page projections that keep public Creator identity separate from legal Seller,
  Account, Purchase, Entitlement, Direct Work, and private profile data.
- Community membership/resource scope and public URL candidates without route redirect or cutover.
- Trusted Event and Notification reference adapters with bounded, sanitized payloads. Notification
  failure never rolls back Post, Comment, Follow, Market Card, or Creator state.
- Finalize a Core Card-only Social content boundary: explicit snapshot policies, no raw media or
  markup, read-time `CONTENT_UNAVAILABLE` redaction, duplicate Share idempotency, and Search public
  visibility eligibility.
- Default-off responsibility-specific flags, unknown-flag fail-closed behavior, kill switch, and
  local shadow rollback.
- Synthetic fixtures, targeted type/test/benchmark/bundle checks, and current-system evidence.

## Acceptance gates

1. Post creation requires an explicit Share Command and references Core entities without raw media.
2. Post, Comment, Follow, Reaction, Mention, Community, Creator Page, My Page, and Market Card
   remain distinct records and authority boundaries.
3. PUBLIC/UNLISTED/Member/Creator-private/Private visibility is server-scoped and fail-closed.
4. Duplicate/conflicting Comment, Reaction, Follow, Mention, and Share identities are deterministic;
   unauthorized references do not leak existence or private content.
5. Market Card sharing never creates Product/Purchase/Entitlement/License/Royalty/Payout state.
6. Trusted Event and Notification references are bounded and sanitized; delivery failure has no
   transaction rollback effect.
7. SNS lazy bundle stays outside Initial Editor, Runtime, Market, and current routes. WP-220 Direct
   Work lazy baseline remains unchanged.
8. Approved Baseline Failure Identity remains 14/14 matched with new identity count 0. WP-000
   through WP-220 are not re-executed.
