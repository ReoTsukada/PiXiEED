# コア合成と戦闘契約

## 1. 固定ルール

上から0始まりの行をr、左から0始まりの列をcとする。

```text
digit[r,c] = (digit[r+1,c] + digit[r+1,c+1]) mod 10
M[r,c] = (1 + ampGain[r+1,c]) × (1 + ampGain[r+1,c+1])
own[r,c] = rolledOwn[r,c] × M[r,c]
ampGain[r,c] = rolledAmpGain[r,c] × M[r,c]
output[r,c] = output[r+1,c] + output[r+1,c+1] + own[r,c]
```

最下段は子がないため `output=own`。通常効果の合成は効果種ごとの強度ベクトルの加算。ampGainは直接の親で一度使う局所信号であり、outputの通常効果へ加算しない。下段から順に一度計算し、最上段の出力を戦闘仕様に変換する。戦闘中に45枠を再帰走査しない。

## 2. 経路を重複排除しない

共有された子コアの効果は別経路として両親へ伝わる。根への寄与係数は `C(r,c)`。9段最下段は `1,8,28,56,70,56,28,8,1`、45枠全体の係数の和は511になる。物理アイテムは45個、計算上の寄与が511単位という意味であり、所持品を511個へ複製するわけではない。

基礎威力+4%のコアを9段中央へ置くとコモン・個体値100%・隣接増幅なしなら `4%×70=+280%`。射撃頻度-0.6%の代償も中央なら-42%。良い効果だけを増幅しない。

`npm run audit:puzzle` は全ての合法な数字配置を列挙する。9段は左右反転込み160通り、反転をまとめて80通り。頂点の数字0〜9はそれぞれ16通り。これは数値条件についての計算であり、能力・レア度・個体値・物理個体の選択を数えたものではない。

## 3. コア定義と個体を分ける

```js
// 定義
{ id:'pierce', name:'貫通針', mods:{pierce:0.06}, ... }
// 個体
{ id:'unique-id', digit:7, type:'pierce', rarity:'rare', rolls:{pierce:10321} }
```

数字と能力は独立。レア度は5段階、能力ごとの個体値は95〜105%。高レアはプラスを強く、代償を小さくする。抽選値は保存され、取引や装着で変化しない。詳しい倍率、負数、増幅の連結、旧セーブ互換は`RARITY_AMPLIFIERS.md`を正本とする。

## 4. 最終変換

| 効果 | v0.3での合成後の扱い |
|---|---|
| 威力・射撃頻度 | 同種は加算、最終的に基礎値×(1+合計)。負値による破綻防止に基礎の5%が下限 |
| 追加弾 | 小数を射撃ごとに累積し、1を超えた分の追加弾を発射 |
| 貫通・反射・分裂 | 整数部分＋小数部分を確率として追加1回/1個 |
| 爆発 | 回数を70個複製せず、合計強度で威力と半径を計算 |
| 放電 | 合計強度で威力・対象数・到達範囲を計算 |
| 会心 | 確率100%超過分は会心倍率へ変換。超過を捨てない |
| 鈍足 | 敵速度÷(1+合計強度)。停止しないが積むほど減速 |
| 腐食 | 同一対象で毎秒ダメージを合計強度から算出。再命中で3秒へ更新、重ねて無限スタックしない |
| 吸収 | 過剰ダメージを除く実ダメージ×合計吸収率を回復待ちに入れ、最大HP8%/秒で処理 |
| 回復装填 | 実回復HP÷10×合計強度を蓄積し、1以上で追加弾 |
| 防護・修復・機動・回収 | 弾丸プログラムに付随する射手の補助値として適用 |

端数の扱いとイベント権限は図鑑にも表示する。初期値はバランス仮説であり、確定版ではない。

## 5. イベントの権限

```text
自動射撃 → 直接弾
直接弾の命中 → ダメージ / 吸収 / 爆発 / 放電 / 腐食 / 鈍足 / 分裂
分裂 → 子弾（再分裂禁止）
回復 → 回復装填の蓄積 → 追加弾（吸収・再回復禁止）
爆発・放電・腐食 → ダメージのみ（命中連鎖を再発火しない）
```

分裂子弾は爆発・放電・腐食・鈍足を引き継ぐ。回復装填由来の弾の子も `noHeal` を引き継ぐ。回復装填の弾が爆発や放電を起こしても、それらは元から吸収を起こさない。

無限に自分を誘発する処理は許さない。ただし連射・多弾・広範囲の相乗は許す。`GameEngine.tick` で生成された子弾は次tickから更新し、同じスタックで再帰実行しない。

## 6. 配置による違い

v0.3では隣接する増幅によって「自身の数値」が変わるため、同じ経路数でも接続先次第で結果が異なる。全体の計算は下から上の1回の走査で終わる。

増幅を計算した後の各コア自身の数値×頂点への経路数を合計すると、再帰合成結果と一致する。増幅指示をその経路数でさらに掛けたり、その倍率を70乗したりしない。途中の合成順序だけで属性が変化する別ルールは未導入。

## 7. UIとテスト

各枠に経路数、個体の数字・能力・レア度・個体値・抽選範囲・増幅後の値を表示。増幅コアを選ぶと直接の対象を強調する。成立していない箇所は赤色、出発ボタンは無効。仮置き自体は許し、編集不能な状態を避ける。数値の自動書き換え・通常モードの自動解答は設けない。

新能力追加時は単独効果、経路重複、他の効果との相互作用、無限連鎖しないこと、小数処理をテストする。ダメージ表示は理論値と実戦値を区別する。
