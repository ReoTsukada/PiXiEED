# CORE DESCENT v0.4 — 攻略記録・無限ボス

## 方針
ユーザーの希望により、直接PvPとPvPvEの新規開発計画を撤回し、PvEの記録を比べるランキングを採用する。目的は、他プレイヤー向けに火力を均すことではなく、収集・数字パズル・局所増幅で作った強いビルドを試すこと。レア度と個体値を標準化しない。v0.3のPvE係数を維持した。

**今回実装したのは、二つの挑戦モードと、この端末内での自己記録。ログイン・実プレイヤーの順位・サーバーによるスコア検証は未実装。**

180秒、ボスの行動、フェーズ、順位の細かな条件は実際に試すための初期提案であり、ユーザーが確定した仕様とは区別する。

## 1. 二つの部門

|部門|主スコア|同点|強みが出る構成|
|---|---|---|---|
|深層チャレンジ|攻略済み最高階層|その階の攻略までにかかった戦闘時間が短い方。それも同じなら同順位|継続火力・集団処理・回復・移動・生存|
|無限ボス・180秒|ボスに実際に与えた総ダメージ|同点は同順位|単体火力・射線・発射頻度・会心・条件付き強化|

別の性質の強さなので、両者を足して総合点にはしない。メインは所持品を使う無制限部門。実験室の貸出品は別記録であり、所持品の順位に混ぜない。段数は3〜9段を受け付け、段数と出発時の編成を記録する。少ない段数で同条件を競う部門は将来追加候補で、現状の試作には専用リーグを作っていない。

## 2. 深層チャレンジ

通常探索はこれまでどおり毎回のランダムマップ。記録用チャレンジは1階から開始し、固定のマップ生成シード `20261117` を使う。シードは乱数生成の出発条件であり、手作りの固定マップへ置き換えたわけではない。

20秒生存と規定数撃破（`min(30,6+2×階層)`）の両方を満たして出口が開いた瞬間、その階を攻略済みとして保存する。

例：100階を攻略して101階へ入り、そこで死亡した場合は100階攻略。101階へ入っただけで101階クリアとは扱わない。同階層の比較は出口へ帰った時刻ではなく、攻略条件の達成時刻を使う。出口の前で放置しても記録が有利にならない。

死亡・任意終了でも、既に攻略した階層は終了時の記録に残す。今回の戦利品は緑の帰還陣に戻ったときだけ確保し、死亡・探索放棄では失う。出発前のコアは失わない。この二つを分け、記録を失いたくないために帰還するしかない設計を避ける。

ローカル試作ではページ再読み込み・クラッシュ時に進行中の記録を確定しない。通常探索はランキングに登録しない。深層チャレンジを専用ボタンから開始する。

## 3. 無限ボス・180秒

- 戦闘時間180秒、探索レベル1固定、編成は開始時に固定。
- 所持コアのレア度・個体値・数値をそのまま使用。PvPの標準化や追加弾35%補正は適用しない。
- ボスは倒れない単体・静止・半径36px。防御0。実際の弾丸の移動と衝突でダメージを計算する。
- プレイヤーは移動可能。四角いアリーナは1116×828px、外周に壁。初期位置はボスから250px。
- 4秒ごとに切れ目付きの円形衝撃波。速度145px/秒、安全な切れ目は±0.7rad。次の切れ目をボス周囲に表示する。
- 波のダメージは0〜59秒で12、60〜119秒で18、120〜179秒で24。近接接触は既存エンジンの1階値7。被弾後0.55秒無敵を維持する。
- ボスからの経験値・通貨・コア・撃破報酬は発生しない。雑魚敵なし。
- 死亡・途中終了はその時点までの総ダメージを記録。残り時間ぶんを推定して補完しない。完走への架空ボーナスを加算しない。
- この試作では一時停止と非表示時の停止が可能。戦闘時間のみが進む。オンライン部門の中断ルールは今後別途実装・検証する。

### HP無限と条件付き能力

数値のInfinityをHPに設定して引き算すると、数値不定や回復・過剰ダメージ処理が曖昧になる。試作では有限の状態値を保持し、ボスへの有効ダメージを別カウンターへ加算する。ボスは死亡せず、ダメージを残HPで打ち切らない。

「追い撃ち」が無意味にならないように、0〜119.999…秒はHP100%判定、120〜180秒はHP25%判定とする。実際のHPを削り切るわけではなく、条件判定用の固定フェーズ。与えた量によってフェーズが早まることはない。追い撃ち強度をx、ほかの要因が一定と仮定した場合、180秒全体の平均寄与は概ね `1+x/3`。ただし実際には命中率・静止・被弾・射撃時刻の違いがあるので、実測の総ダメージが正本。

吸収は実際の有効ダメージから既存の係数で回復し、最大HP8%/秒の処理速度を維持。満タンから追加弾を生まない。回復装填由来の弾が再び吸収を起こさないルールも維持。

### スコア

```text
総ダメージ = 制限時間内にボスへ入った直撃・爆発・放電・腐食のダメージの合計
確定記録 = 上記合計を小数第3位に丸めた値
表示参考値（180秒換算DPS）= 総ダメージ / 180
```

現在の単体ボスでは、爆発と放電は「直撃対象以外」を狙う既存仕様なので追加分は0。子弾も発生元の敵へは再命中しない。これらを架空の単体ダメージとして加算しない。腐食は実際に発生した時間ぶんだけ合算する。画面の全弾命中DPSに180を掛けて登録する方式ではない。

ボス中のHUDは経過時間で割った平均DPSも出す。これは参考表示で、順位判定には使わない。例として10秒で10万ダメージの途中終了は、180秒で15万ダメージの記録を上回らない。

ボスへ∞、NaN、負のダメージを与える状態、または合計が小数3桁を安全に扱える範囲を超えた場合は無効記録とし、巨大な偽スコアを記録しない。これはゲーム内の火力制限ではなく、現在の数値表現の異常検出。将来その範囲を正規ビルドが超えるなら、精度・単位を変更したルールを別バージョンで設計する。

## 4. 記録の保存と画面

「記録」タブから現在の編成を使用して挑戦できる。自己ベストと上位10挑戦の履歴を表示。各記録は種目、ルール版、チャレンジID、シード、通常/実験室、段数、出発時の全コア個体、終了状態、攻略済み階、攻略時間、総ダメージ、内訳、時刻を保存する。

`verified:false` を固定し、他プレイヤーの名前や架空の世界順位を表示しない。同じ挑戦IDの重複登録を防止する。古いルールの記録は同じ表へ混ぜない。

所持品保存キーは `core-descent-v4`。v3/v2/v1は読み取り移行元とし上書きしない。既存の所持品スキーマはversion2のまま互換維持。記録は別キー `core-descent-records-v4`。保存不可の環境ではメモリー内で使い、「記録を書き出す」でJSON化できる。記録JSONの再インポート画面は未実装。ローカル記録は将来の正式スコアには取り込まない。

## 5. オンライン化する場合の提案（未実装）

期間ランキングは、最初は4週間ごとのシーズンと部門別の自己最高を候補にする。通常の所持コア・通貨はリセットしない。毎週の固定シードチャレンジは追加候補で、プレイヤー数や更新頻度を見て導入する。異なるシード・期間・計算式の結果を同じ順位へ混ぜない。バランス変更は可能なら期間の切替で行う。安全性の修正で途中更新が必要なら旧版の記録を保管し、新版を別集計する。

ラン開始時にサーバー側で所有権、編成、個体値、能力定義、マップシード、開始階を確定。入力列と権威あるシミュレーションから結果を計算し、ブラウザーが送った総ダメージや到達階をそのまま受理しない。改造セーブ、途中の編成変更、低速時計、重複送信、別シード、レベル差、無敵化、他人の個体ID、不正な終了状態を拒否するテストを追加する。

終了したラン1件につき確定結果1件。公表時は各プレイヤーの期間ベスト1件だけを本順位へ載せ、同じ人が上位欄を埋めない。詳細な45個の編成公開は、本人が選ぶ方式を候補とする。数値検証用のスナップショットは非公開でもサーバーへ保持する。

順位報酬はまず称号・フレーム等の見た目を中心に検討。上位限定の圧倒的な火力アイテムを配り続けて、順位格差が自動拡大する構造は避ける。「全アイテム取引可」は維持し、アカウント実績と取引可能な現物アイテムは区別する。現段階では順位報酬を発行していない。

## 6. 未解決のバランス

単体ボスで不利な集団攻撃・鈍足・回収を、むりやり全種目で最強にしない。深層部門での役割を先に確認する。必要になれば、後から固定出現パターンの群体ボス部門を追加する。最初から多数のランキングへ分散させない。

市場で強いコアを入手した人が有利になる点は、持ち込みランキングの意図した特徴。操作とパズルだけの比較が必要になった場合に限って、所持品の総合部門とは別に貸出コア部門を検討する。メイン順位の火力をこっそり標準化しない。

無限階層は攻略に長時間を要する可能性がある。途中保存・安全な再開、長時間耐久・負荷・バランスの評価は未実装/未検証。ボスの180秒は固定長の別の競争機会になる。
