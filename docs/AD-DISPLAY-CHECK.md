# 広告表示と画面内の操作

## 通常広告と報酬型の区別

AdSenseのディスプレイ広告・全画面広告と、Ad Managerの報酬型広告は独立しています。通常の全画面広告が出ても、報酬型に配信対象の広告がある証拠にはなりません。通常広告の表示からパスを付与しません。

報酬型はGPTの `OutOfPageFormat.REWARDED` を使用し、`/23379831154/pixieed_rewarded` を呼び出します。Ad Managerの動画タグ生成画面でVASTタグ・説明URLを追加する必要はありません。ウェブ報酬型の配信では広告ユニットサイズは影響しません。

## 失敗時の確認

案内画面は、読み込み失敗、配信対象なし、端末で表示できない状態、準備のタイムアウト、途中で閉じた状態を区別します。診断用DOMの `.px-pass-backdrop` に `data-ad-phase` と `data-ad-result` を記録します。端末の個人情報や広告応答の内容を外部へ送る独自の診断通信は追加しません。

| 最後のphase | 意味・次の確認 |
| --- | --- |
| `script-error` | GPTを読み込めない。通信・広告ブロックを確認。 |
| `unsupported` | GPTがこの画面で報酬型スロットを作れない。viewportと標準表示倍率を確認。 |
| `unfilled` | 自分のスロットの `slotRenderEnded.isEmpty` がtrue。Ad Managerの配信対象・広告申込情報を確認。 |
| `display-failed` | 広告の準備はできたが、表示に失敗。端末・ブラウザーの状態を確認。 |
| `timeout` | 準備が30秒以内に完了しなかった。通信やGPTの診断を確認。 |
| `api-error` | GPTの呼び出しで例外。ブラウザーのコンソールを確認。 |
| `visible` / `granted` | 表示できた／Googleから報酬成立のイベントを受けた。閉じた後に1時間を追加。 |

GPTスクリプトの読み込み待ちは10秒です。読み込み中の既存タグは重複追加せず、そのload/errorを待ちます。広告準備待ちの30秒タイマーは表示開始後に解除し、視聴中に終了させません。

`?dfpdeb` を付けたページでは、配信対象なしのスロットを最大5分保持してPublisher Consoleで調査できます。`?ads=test` はGoogle公式サンプルの報酬型ユニットへ切り替える既存の診断機能です。本番の在庫を証明するものではありません。日次無料分を受け取れる日は先に無料分が提示され、次の明示的な広告操作でのみ広告を開始します。

Ad Manager側で見る場所は「広告申込情報」です。この広告ユニットを対象にした適切な形式の広告申込情報と、その広告・配信元を確認してください。広告ユニットの「有効」は配信できる広告があることまでは保証しません。予約動画は1×1v、Ad Exchange広告申込情報はディスプレイ1×1というGoogleの設定案内に沿って確認します。利用できる配信元はアカウントの状態によるため、サイトコードだけでは確定できません。

## 結果画面の広告

画面いっぱいのツールでは、結果画面もヘッダーと下ナビの間に収めます。プレビューは領域に合わせて縮め、操作ボタンは48px以上を保持します。広告は操作から24px以上離れた別の行に配置し、ページの縦スクロールを増やしません。

カメラは撮影直後のプレビューに掲載します。描画・音楽は書き出し後、ジグソー・間違い探し・もの探しは完成・終了後です。幅1100px以上で高さにも余裕がある結果画面では2枠を横並びにし、それ以外は1枠まで。複数の枠は既存ユニットを共有し、各枠のリクエストは1回だけです。

通常のホームはヒーロー直下とツール一覧後、ツール一覧ページは制作ツール群とゲーム群の間・ゲーム群後に各2枠です。スクロールで近づいた枠のみリクエストします。

広告を置く領域と操作領域が収まらない場合は、広告の要素作成・リクエストより前に掲載を見送ります。高さ360px以下、または横向きで高さ480px以下では操作を優先して広告を掲載しません。表示後の回転も、Googleが認めるレスポンシブ広告のメディアクエリによるサイズ別除外を使用し、作品や結果は維持します。広告を再リクエストしません。スクロールするホーム・ツール一覧・説明ページの広告は従来の本文内配置を維持します。

## 今回の確認範囲（2026-09-29）

- Google公式サンプルの実広告で、準備・表示・報酬条件達成・閉じる・1時間追加まで確認。本番ユニットの配信在庫とは区別する。
- Publisher Consoleのスロットオーバーレイは広告操作を覆う場合がある。視聴操作を試すときはConsoleを閉じてからページを再読み込みする。
- かんたんドットの実際のPNG保存後に、390×844／320×568／844×390／1280×800／568×320を確認。ページの縦横スクロールなし、操作と広告の重なりなし。共通の結果画面を全6ツールで使用するが、各ツールの実機での終了操作は未検証。
- 追加した2枠を1280×720の実際のPNG保存後に確認。各578px幅、24pxの間隔で横並び、ページ寸法も1280×720。390×844では2枠目の広告要素・リクエストを作らず1枠に制限。広告の掲載枠と応答は確認したが、ローカルの通常枠には広告クリエイティブが配信されていない。
- 本番の公開HTML・設定・ads.txtは取得でき、報酬型ユニットパスも一致。Ad Managerアカウントの広告申込情報・需要設定は今回未確認。
- 所有者のAdSenseアカウントの「サイトごと」一覧を確認。`pixieed.jp` の自動広告は現在「オフ」、ページ除外6件、自動最適化「オン」。現在は自動広告の追加設定を変更する必要はない。アカウント設定は読み取りのみで変更していない。

操作中の画面にAdSenseの自動広告が入る場合は、AdSenseのページ除外・エリア除外も設定してください。サイトの手動枠だけで、AdSense管理画面で有効にした自動配置を制御することはできません。画面サイズによる公式のレスポンシブ除外以外で広告を任意に隠したり、広告の中身を切り取る対策は使用しません。

将来自動広告をオンにする場合は、AdSense「広告」→ pixieed.jpの編集 →「ページ除外」で次を登録し「サイトに適用」します。これは自動広告の設定で、今回配置した手動広告・Ad Managerの報酬型は別に管理します。

- ページのみ: `https://pixieed.jp/pixel-camera.html`、`https://pixieed.jp/globe-prototype.html`
- セクション全体: `https://pixieed.jp/draw/`、`https://pixieed.jp/audio/`、`https://pixieed.jp/jigsaw/`、`https://pixieed.jp/spot-difference/`、`https://pixieed.jp/hidden-object/`、`https://pixieed.jp/play/`、`https://pixieed.jp/globe/`、`https://pixieed.jp/telescope/`

この管理画面の変更は今回未実施。クエリ付きURLや `#` 付きURLを除外として登録しない。Googleの案内では設定の反映に最大1時間かかることがある。
