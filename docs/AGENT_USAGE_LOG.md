# PiXiEED agent usage log

目的: 品質を落とさず、モデル・委任・ツール利用を必要最小限にする。数値はCodexが取得できた実測値だけを記録し、開始値がない作業の消費量を推測で確定しない。

次回のモデル選択、残量別の運転モード、検証回数は [AGENT_EFFICIENCY.md](./AGENT_EFFICIENCY.md) を正本とする。このファイルは実測履歴に限定する。

## 記録ルール

各実装スライスの開始時と終了時に、次を記録する。

- 日時と作業名
- 主担当モデル
- サブエージェントのモデル、人数、用途
- 画像生成など別課金になり得るツールの回数
- 5時間枠と週間枠の使用率（開始 / 終了 / 差分）
- 実行したテスト、ブラウザ確認回数
- 無駄だった再実行と、次回の改善策

チャット単位の表示はサブエージェント、画像生成、バックグラウンド処理を完全には含まない場合があるため、請求額や厳密な全消費量とは扱わない。

## 運用方針

1. SOLが設計、範囲、受入条件を先に固定する。
2. 通常実装はLunaへ、互いに独立した作業だけを委任する。
3. Astraは難しい設計判断、重大リスク、最終の高難度監査に限定する。
4. 同じ調査をSOLとサブエージェントで重複させない。
5. 長時間の委任は途中で範囲を増やさず、縦切りが完成した時点で終了させる。
6. ブラウザ確認は代表画面をまとめて行い、修正ごとの不要な再起動を避ける。
7. 実装前にキャッシュ、描画、データ構造を決め、試行錯誤による全面作り直しを減らす。
8. 公開・実機・本番確認が不要な段階では、純粋テストと独立プロトタイプに限定する。
