# ドットカメラのジオラマ効果：ローカル確認

2026-10-05時点の検証記録。設定名はユーザー了承済みの「ジオラマ」、補足は「上下をぼかして、模型のような風景に」。ローカル実装・検証のみ。commit、push、deploy、公開、本番DBへの書込みは行っていない。

## 使い方と挙動

カメラ下部の「色味」→「その他」→「ジオラマ」でON/OFFを切り替える。初期状態はOFF。既存の6つの設定カテゴリ、シャッター、タップでの色選び直し、既存のピント要求、長押しでのライブ色統合を維持する。効果自体はハードウェアフォーカス・奥行きAI・実距離測定を使わない。

中央の高さ20%を鮮明に保ち、その上下の片側40%でぼかしを徐々に増やす。最大σは処理画像の高さ0.6%。強度下限は設けない。行ごとにσを変える分離ガウスぼかしを使い、両端の一次・二次微分がゼロになる5次イージングで広く滑らかに遷移させる。強いぼかし画像を原画像へ透明合成する方式は使わない。帯位置のドラッグ等も追加していない。

色調整のリセットは従来どおり色味だけを戻し、ジオラマのON/OFFは保持する。効果はOFFにすれば解除できる。カメラ再読込み時の初期状態はOFFで、撮影済み画像の後から効果を切り替える機能は追加していない。

## 現行処理を保った挿入位置

1. 元動画を既存の比率・デジタルズームと同じ範囲で切り取る。
2. **ジオラマONのときだけ**、切り取り映像のコピーを作業用Canvasへ読み、行ごとに連続的なσを持つぼかしを適用。作業画像の長辺は最大512pxで、選択中の16～256pxのドット数とは独立している。OFFではこの段階を完全に通らず、元動画を直接従来のサンプラーへ渡す。
3. 従来のサンプラーで前面カメラの反転・選択中のドット数への縮小・Canvas色味フィルターを適用。既存のぼかし0.45px、基本コントラスト+15、基本彩度+20、ユーザーの各スライダーは変更していない。
4. 従来の `processLensFrame` で内部補正・減色・ディザ・面整理を適用。内部彩度1.02、コントラスト1.04、暗部補正（60未満に+4）は変更していない。
5. 完了画素を表示。撮影は表示済みの画素を固定し、従来の共通画像保存条件と整数倍PNG書出しへ渡す。

元映像の段階でぼかしてからドット化するため、完成したピクセル画像やCSS表示の輪郭をにじませない。元動画は変更せず、原画像用と処理結果用のCanvasを分け、毎フレーム元映像から処理する。ぼかしは累積しない。ライブの `sourceData` は従来どおり減色前のサンプルを保持する。完成PNG/PXDには従来どおり処理済み画素を保存し、元動画を保存する機能は追加していない。

当初のドット化後の処理と、低解像度での強度下限は、ユーザーの「ぼかしが急に強い」「元画像をぼかす」という指摘に従って取り下げた。最新の確認画像・記録は元映像側の弱い可変ぼかしに差し替えている。

グレーモードはライブで16色を超える階調を持つ一方、従来の撮影保存時には共通画像の16色（既存条件によって32色）制限が入る。ジオラマONでは、その既存の最終減色をライブにも適用して、撮影時の画素変化をなくした。撮影後のプレビューは固定された保存画素を描画するよう修正した。OFFのライブ画素と保存処理の色数規則は維持する。新しい彩度+12%・コントラスト+4%は追加していない。

## 変更ファイル

- `js/pixel-lens/miniature.mjs`：入力を保持する可変ぼかし処理。中央帯の無加工、端の画素延長、作業バッファ再利用。
- `js/pixel-lens/app.mjs`：ドット化前の処理接続、ON/OFF、グレーの保存条件との整合、保存画素の撮影後表示。
- `pixel-camera.html`：既存の色味設定内にジオラマON/OFFと補足を追加。カメラJS/CSSの読込rev更新。
- `css/pixel-lens-camera.css`：既存のスライダー領域と同じ位置・高さにON/OFFを表示。
- `tests/pixel-lens/miniature.test.mjs`：原画素・OFF・中央帯・端・作業解像度の上限・反復・新画像・サイズ変更の検証。
- `scripts/camera-miniature-browser-harness.mjs`：実UI、変更前アプリとの比較、合成動画、PNG復号照合、画面・性能検証。

`js/pixel-lens/engine.mjs` は変更前のSHA-256と一致。開始時にカメラ関連3ファイルには未コミット差分がなく、作業中の音楽・地球儀・書籍等の変更には手を入れていない。適用対象のAGENTS.md、ローカルの `.agents/skills` は見つからなかった。

## 検証結果

- Node：カメラ関連105件PASS、失敗0。新規6件を含み、色味・パレット・ディザ・ズーム・ジェスチャー等の既存検証も実行。
- Mac Chromium：19項目PASS。128px/1:1/写真色/彩度0、256px/9:16/写真色/彩度+38/市松ディザ、32px/16:9/グレー/彩度-40、16px/1:1/GBの4条件で、変更前の実アプリとOFFの全画素ハッシュが一致。
- 各条件でON/OFFを3往復し、OFFへの復帰・寸法維持・色フィルター不変を確認。ぼかしが出力ドット数より大きい原映像の作業画像に適用されることも確認。景色変更、色調整リセット、ONでのタップ色選択・長押しライブ色統合を確認。
- ONでの表示画素と撮影固定画素が一致し、保存PNGを復号して全画素を整数倍の表示画素と照合。4条件とも不一致0。
- 320×568、390×844、844×390、1280×800の表示を確認。ON/OFFは48px以上で、狭い画面でもタップ到達可能、横はみ出しなし。
- 元映像の270×480切り取りに対するぼかし単体は、現在のMac Chromiumで中央値4.8～4.9ms、p95は最大約5.1ms。ライブ更新も継続。これは単体の短い計測で、実機や全処理のFPS保証ではない。

実カメラ・個人写真は使用せず、Canvasの合成映像だけを使用。外部通信は遮断し、本番の認証・投稿・ストレージに書き込んでいない。ブラウザー用の一時プロファイル内で現行のローカル保存経路を検証した。

## 残る確認

WebKitは既存環境に実行ファイルがないためSKIP。Safari、iPhone/Androidの実機、実カメラの画質・長時間動作・発熱・消費電力は未検証。減色の少ない配色ほどぼかしの差が見えやすく、少色・粗いドットでは差が弱くなる場合がある。撮影済み原動画の保持、帯位置の操作、深度推定、ハードウェアのフォーカス制御はこの変更に含めない。
