# PiXiEED 作品をつなぐツール計画

各ツールと旧投稿の詳細設計・検証条件は [制作ツール群の設計入口](creation-suite/README.md) を参照。この文書は全体像を示し、現行サイトの変更や旧データ移行を実施した証拠ではない。

## 目指す体験

一枚のドット絵を描く、写真をドット絵カメラで撮る、音をつける、遊べる形にする、地図に置く。この流れを、ファイルの書き出しと再読み込みなしで行えるようにする。各ツールは同じ作品を参照するが、元の作品を書き換えず、派生作品として保存する。

公開するツールは、実際に作成・保存・再開できるものだけにする。現在の公開ツール一覧はドット絵カメラと望遠鏡のみで、描画・音楽・ゲーム・パズルの公開アプリはない。

## 既存資産の棚卸し（2026-09-27 の main）

| 対象 | 確認できたこと | 新しい実装での扱い |
| --- | --- | --- |

| 描画・音楽・ゲーム | 現行公開ツール一覧には存在しない。過去の Studio/iDRAW/iAUDIO/iGAME は本格制作向けに実装されたが、現行 main にそのソース一式はない。 | 本格版は別の役割として保ち、公開サイト向けの簡易ツールを別に作る。旧エディタを縮小・改造しない。 |

### 旧 PiXFiND から引き継ぐ原理

- 間違い探し：同じ寸法の2枚の画素差を検出し、近い差を一つの領域にまとめる。拡大時も正しい元画素をクリック判定に用いる。
- もの探し：絵とは別の対象レイヤーから連結領域を検出し、各対象に名前とヒット領域を持たせる。対象が近すぎる場合は作成時に知らせる。
- 制作者のプレビュー、難易度、正解表示は残す。ただし旧 `pixfind/app.js` は約5千行の画面・通信・判定の一体実装であり、そのまま移植しない。
- 旧 SQL は匿名クライアント ID による直接書き込み方式。現在の投稿審査・権限モデルへそのまま接続せず、新しい公開 API で権限と公開状態を扱う。

## 共通の作品データ

どのツールでも、元作品の ID と固定された版を渡す。派生物は自分の ID を持ち、元作品の版を参照する。画面で見せるサムネイルと編集可能な元データを別に保持する。

| 情報 | 用途 |
| --- | --- |
| `assetId`, `revisionId`, `contentHash` | 何を編集・再生・公開したかを固定する。元画像があとで更新されても、公開済みゲームやパズルが勝手に変わらない。 |
| `kind` | ドット絵、ドット写真、音色、曲、キャラクター、ゲーム、パズルを区別する。 |
| `source` | 手描き、カメラ、外部からの持ち込みと、派生元の作品・版を記録する。 |
| `owner`, `reusePermission`, `visibility` | 他人の公開作品をパズル等に使えるか、制作者が決める。公開作品でも無条件に改変可能とはしない。 |
| `pixelData`, `palette`, `layers` / `audioNotes`, `instrument` / `puzzleRules` | 各ツールの編集データ。画像だけを保存して編集内容を失わない。 |

地図の座標は公開セルのみを派生先へ渡す。元の精密な位置は引き継がない。

## 各ツールの最初の完成形

1. **かんたんドット絵**：ペン、消しゴム、塗りつぶし、対称描画、色パレット、最小限のレイヤー、取り消し、端末内保存と再開。16〜512px。PNGと編集データを保存し、描いた絵を地図・音・ゲーム・パズルへ渡す。タッチ操作を先に成立させる。
2. **絵から音楽**：色を直接、無制限に音符へ変換しない。面積の大きい色を4〜8個の音色スロットへ割り当て、横方向を時間、縦方向を音域の初期案にする。音階・テンポで整え、再生しながら音色と音符を編集できる。カメラ写真も入力できるが、撮影画像と編集した曲は別作品にする。初期生成は端末内の決定的な処理で行い、AIは品質を測って必要性が確認できた場合に検討する。
3. **キャラクターからゲーム**：描いたキャラクターを選び、背景と音を選び、まずは「歩いて集める」一つのテンプレートで遊べる状態にする。移動・当たり判定・ゴールを簡単な操作で調整し、端末内保存と再開を可能にする。汎用ゲームエンジンの全機能は初版に入れない。
4. **ジグソー**：公開中の通常投稿のドット絵・ドット写真、自分の保存絵、端末で選んだ画像から遊べる。投稿画像はプレイ中だけ切り分け、保存するのは投稿参照・画像指紋・配置で、元画像を複製・変更・再公開しない。元画素の縦横比とドットを保ち、ピース数を選べる。
5. **間違い探し**：作品を複製して変更箇所を描くか、2枚の同寸画像を指定する。検出された差分領域を制作者が確認・修正し、問題として保存する。
6. **もの探し**：作品の上に探し物の領域を指定し、名前をつける。描画ツールのレイヤーから取り込む場合も、公開前に対象領域を確認する。写真からの自動物体検出は任意の補助にとどめる。

## 実装順と完成判定

1. 共通作品データと「描く → 保存 → 再開 → 地図に投稿」を一本つなぐ。既存のカメラ投稿と手描き投稿の区分を維持する。
2. 同じ作品を音楽ツールで開き、色から短いループを作って編集・保存・再開する。音の変更で元画像は変わらない。
3. ジグソー、間違い探し、もの探しを同じ作品入力から作る。旧 PiXFiND の判定を独立テストで再現した後、新 UI へ接続する。
4. 描いたキャラクターと作った音を簡単ゲームへ渡し、公開版が参照する画像・音の版を固定する。

各段階で、スマホとデスクトップの操作、保存後の再開、元作品の非破壊性、作者の再利用許可、公開と非公開の境界を確認する。サイト全体のツール一覧には、その段階を通過したものから載せる。
