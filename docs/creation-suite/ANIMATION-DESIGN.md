# かんたんドットのアニメーションと音楽ページ

2026-10-01。描画のコマ・レイヤー・GIF、音楽のコマ再生、タイル共有と先読みを実装しました。同日、共通アプリ・共通PXD案は撤回しています。現在は [ツール別プロジェクト](INDEPENDENT-TOOL-PROJECTS.md) が優先仕様です。以下の共通作品・明示同期・画面内モード切り替えの記述は旧設計です。実機検証と公開はしていません。

かんたんドットの現在の表示方針は、パレットと描画道具を常時表示し、レイヤー・フレームを必要時だけ開く方式です。操作欄の44pxボタンに現在の選択を小さく示し、タップするとキャンバス上に非モーダルのパネルを開きます。パネルを開いてもキャンバスの寸法は変わりません。セル・レイヤー番号・フレーム番号はすべて44px、描画済みは点、選択中は黄色で区別します。明示的な閉じる操作・Escape・外側の操作で閉じ、作品読み込み時は閉じた状態から始めます。音楽画面の表示方式はこの変更の対象外です。

## 調査と採用方針

現行の公式資料を確認した。特定バージョンの高速化実装を移植したという意味ではない。

- [Asepriteのアニメーション](https://www.aseprite.org/docs/animation/): レイヤー・フレーム・セルのタイムライン、コマ複製、空コマ、移動、時間設定、再生を参考にする。
- [Asepriteのセル](https://www.aseprite.org/docs/cel/): レイヤーとフレームの交点がセル。PiXiEEDでは画素の「1セル」と混同しないよう、通常の操作では「コマ」と「レイヤー」を使う。
- [Asepriteのリンクセル](https://www.aseprite.org/docs/linked-cels/): 画像と座標を共有し、編集が他のリンク先にも伝わる仕組み。PiXiEEDの初期実装では、その編集連動は導入しない。内部の画素だけ共有し、編集時にそのコマを独立させる。
- [Asepriteのファイル仕様](https://github.com/aseprite/aseprite/blob/main/docs/ase-file-specs.md): インデックス画像は1画素1バイト、セルに座標・寸法を持たせる構造を参考にする。Asepriteのコードや依存は追加しない。
- [Pixilart](https://www.pixilart.com/features): コマの複製・並べ替え・個別時間・前コマ表示を参考にする。[Piskel](https://www.piskelapp.com/)の再生プレビューとGIF出力も確認した。

取り入れるのは、普段は1枚の絵として使えて、必要になったらコマを増やせる操作。グループ、特殊合成、リンク編集、タグ、タイルマップは初期対象外。

旧iDRAWのタイル共有・コピーオンライト・差分Undoも[棚卸し](IDRAW-ANIMATION-PERFORMANCE-AUDIT.md)した。現行のImageData再利用と変更範囲描画は既にあるため、そのまま活用する。旧アプリ全体を戻さず、全画素コピー・全面Undo比較・直線プレビューの削減を優先する。

## 現状で問題となる境界

| 現在の実装 | そのまま増やした場合の問題 | 対応 |
| --- | --- | --- |
| `draw-core.mjs` の単一画像・透明値 -1 | Uint8Arrayへの単純変換で透明値が255になる | 境界で明示変換し、0=透明・1以降=色にする |
| `pxd-project.mjs` の `main` 静止画像 | 再生コマで書き換えると他ツールの画像参照が変わる | アニメーション本体と表紙を分離 |
| `audio-core.mjs` の最大16小節 | コマをつなぐ長い曲を保存できない | 時間列を別契約で追加、旧曲の解釈を維持 |
| 再生開始時に全音を準備し、音ごとに全音との重なりを検査 | 長い曲で開始時の音源数・計算が増える | 時刻順イベントと短い先読みで再生 |
| `audio-export.mjs` の曲全体のOfflineAudioContext | 長い曲ではPCM・WAVの同時確保が大きい | 書き出し前の容量検査、分割描画を別の必須工程にする |
| `pxd-codec.mjs` の64 MiB・512項目上限 | セルごとにファイル追加すると項目数超過 | 画素プールを部品ごとの1バイナリ項目にまとめる |

## データの正本

- 絵の重なりはレイヤー、時間の順番はフレーム、その交点に画像と座標を置く。
- 全コマで同じ寸法・同じパレットを使う。新規制作は現在の共通キャンバス上限（通常128px・16色、特典256px・32色）を維持する。
- 色IDはパレットの並び順から独立させる。色変更は全コマに反映するため、その範囲を表示する。音色割当は色IDで保存する。
- 画素は `Uint8Array`。0は透明、1〜32はパレット参照。変換前に整数・範囲を検査する。初期の合成は不透明色と完全透明の通常合成だけ。
- 初期案は旧iDRAWにならった32pxの疎なタイル。同じ画素ブロックは共有し、透明タイルは保持しない。端のタイルは実寸だけ確保する。ハッシュ一致だけで共有せず、画素も比較する。
- コマ複製はタイル参照の複製。編集したコマの変更タイルだけを分離する。セルの位置・参照はコマごとに独立する。空のセルは画素を確保しない。
- レイヤー・フレーム・画像は安定IDで管理。画面の選択位置と、作品一覧に表示する表紙フレームは別にする。
- Undoは画素差分と構造操作。毎操作で作品全体を複製しない。現在の4 MiB予算を基準に、古いUndoだけを除く。

PXD内の提案配置:

```text
animations/main/state.json   # schemaVersion:1、寸法、色ID、レイヤー、コマ、セル参照
animations/main/cels.bin     # 共有インデックスタイルの連続プール
animations/audio/state.json # 明示取り込みした曲側の独立したコマ列
animations/audio/cels.bin
audio/animation-link.json    # コマの演奏順・120 Tick/セル・元作品/revision
images/main/...             # 選んだ表紙の静止画像。旧ツール向け
images/audio/...            # 曲側の表紙。旧ツール向け
```

画素ブロック記録にはID・幅・高さ・プールのoffset/length、セル記録にはlayerId/frameId/x/yとタイル位置・ブロック参照を持たせる。範囲・重複ID・参照切れ・宣言容量を、画素確保前に検証する。編集時の参照カウントは実行中だけの情報とし、読み込み時に参照から再構築する。

既存PXDはそのまま読み書きできる。既存画像をアニメーションへ移すときだけ1レイヤー・1コマへ変換する。古い512px、多色、半透明画像は勝手に縮小・減色しない。変換が必要なら原本を保ち、確認付きの制作コピーにする。

未知の部品・未知のメタデータ・非編集データは保持する。未知のアニメーション版は編集せず保存可能な状態にする。既存の部品単位の競合判定は維持し、初期のアニメーション競合は上書きせず別コピーで残す。異なるセル編集の自動マージは、画素プールの競合を検証するまで行わない。

## 軽量化の予算

初期の提案上限は8レイヤー・128コマ、作品内の描画・曲側を合わせた独立画素の合計32 MiB・アニメーションメタデータ1 MiB。これは上限まで無条件に作れるという意味ではない。書き込み前に容量を検査し、超える操作を元の内容を変えずに止める。PXD全体の64 MiB上限も別に守る。

静止背景の256×256pxは64 KiB。100コマでも共有できる。全部違う8レイヤー×128コマは64 MiBになるため、32 MiB予算で先に止まる。履歴・JSON・合成画像・PXDエンコード中の複製も別途測定し、32 MiBを端末全体の使用量として案内しない。

合成キャッシュは最大3コマ。256pxのRGBAなら合計約768 KiB。サムネイルは見える範囲だけ生成する。再生中はコマが切り替わる時だけ再合成し、セル編集は1操作の中でまとめて確定する。試作の1画素編集APIを毎ドラッグ点で呼ぶ実装にはしない。

矩形共有と32pxタイル共有を独立試作で比較した。256pxの異なる模様を持つ背景から100コマ（元＋99複製）を作り、各複製で1画素を変えると、矩形方式の画素は6,553,600バイト、タイル方式は166,912バイト。元コマはどちらも不変。タイル方式は1回の編集でプールへ追加する画素が1,024バイト以下だった。

これは画素payloadだけの測定で、参照メタデータ・一時バッファ・JSヒープ・実行速度・ディスク容量は含まない。小さな1画素だけの絵は矩形方式の方が小さいため、初期は構造を統一する32pxタイルを採用し、保存時の透明余白圧縮は別に検証する。アプリ接続後にメタデータや編集時間が不利なら、保存形式の版確定前に見直す。

## 音楽との接続

**コマを曲のページとして左から演奏し、次のコマへ進む。** 1画素=1音の既存操作、色=音色を維持する。レイヤーは楽器にはしない。曲へ取り込んだ可視レイヤーの合成画像だけを読む。

- PPQ=480、1セル=120 Tickを維持。`pageTicks = width × 120`、セル時刻は `pageIndex × pageTicks + x × 120`。
- BPMは1拍の速さ。幅やコマ数を増やしても1セルの時間を変えない。
- 120 BPM・横16セルは1コマ2秒。32コマで64秒。横64セルなら1コマ8秒、8コマで64秒。
- 空のコマも同じ時間を使う。非表示レイヤー、オニオンスキン、グリッド、選択枠は音にならない。
- 同じ行・色・音色の連続画素はコマ境界でもロングトーンにする。空白・無音色・色変更で切る。最後のコマと最初のコマは自動でつなげない。
- 絵の再生速度（durationMs）と音楽ページの長さ（Tick）は別。絵が12fpsだから曲も12ページ/秒にするとBPMが崩れるため、この変換は行わない。
- 楽器が未設定の色も普通のパレットとして残す。初期4音色・追加音色の特典表示を維持する。

絵から曲への更新は、現在の「絵の更新を曲に反映」で全コマを確認して取り込む。曲側は独立コピー。テンポと既存色の音色対応を保持し、新しい色の音色は未設定にする。既に公開したパズルや画像参照は更新しない。

再生はAudioContextの時刻を正本とし、コマと再生位置も同じ時刻から求める。0.15〜0.25秒程度の先読みを出発点として端末測定で調整する。音を曲全体分生成しない。イベント数・同時発音に上限を持たせ、密度超過は警告する。長さとメモリの事前検査なしに長いWAV/動画を開始しない。

## 画面案

1. 通常は全画面キャンバスとパレット・描画ツール。レイヤー×フレーム表は必要な時だけ開く。中央ナビの保存操作を維持する。
2. 番号・交点セルは同じ44px角。描画済みの印と現在選択を示す。フレームの最後とレイヤーの次番号に＋を置く。
3. 番号をタップして選択、350ms長押しで持ち上げて並べ替え。長押しして動かさず離す、右クリック、ダブルクリック、Shift+F10でその番号の操作メニューを開く。
4. 複製・空白・表示時間・削除・オニオンスキン、レイヤー名・表示・ロックは文脈メニューにまとめる。格子内はスクロールでき、ページ全体とキャンバス寸法は変えない。
5. 前後1コマの薄いガイドを切り替え可能にする。書き出しには混ぜない。コマ切替でもズームとパンを保持する。
6. ドットで音楽は個別プロジェクトと既存コマ帯を維持する。描画・音楽ともペンの再タップで消しゴムへ切り替え、色選択でペンに戻る。GIF保存は通常の保存メニューにまとめる。

## 実装順と完了条件

1. インデックス画素、コマ/レイヤー、PXD往復、旧形式、未知情報、競合を先に完成。
2. 描画への接続、コマ帯、レイヤー、Undo、オニオンスキン、再生を完成。
3. 表紙PNG・GIF・PXD書き出し。グリッド、パレット、ガイド、選択枠が入らないことを画素検証。
4. 音楽ページの保存・音符生成、短い先読み再生、コマ境界ロングトーンを完成。
5. 長い曲のWAV/動画の容量検査・分割処理を完成。旧1枚の曲は以前の出力を維持。
6. スマートフォンの短い画面、縦横、PCホイール、ピンチ、作品切替、特典期限切れ、保存失敗を確認。
