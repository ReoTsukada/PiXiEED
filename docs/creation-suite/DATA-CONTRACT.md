# 画素・保存・受け渡しの共通契約

2026-09-28。全制作ツール（カメラ、かんたんドット、音楽、ジグソー、間違い探し、もの探し、ゲーム、PXD）が守る共通ルール。実装は `js/creation/pixel-contract.mjs`、検証は `tests/creation-suite/pixel-contract.test.mjs`。

保存形式は変えない。作品は従来どおりJSON配列で保存し、編集用の型とは境界で変換する。旧作品はそのまま読める。

## 型は用途ごとに揃える

| 用途 | 扱い | 変換 |
|---|---|---|
| 画像のRGBA・PXDのファイル内容 | `Uint8Array`。原本のバイト列を保持 | `toBytes`（0〜255の整数だけ受け付ける） |
| Canvasへの描画 | `Uint8ClampedArray` | `canvasRgba`（同じバッファのビュー、表示する境界でのみ作る） |
| 編集中のパレット番号 | `Int16Array`。透明の −1 を維持 | `toPaletteIndices` / `paletteIndicesToJson` |
| 対象マスク | `Uint8Array`（0/1） | `toMask` |
| 画素位置 | `Uint32Array` | `toPixelIndices` / `pixelIndicesToJson`（範囲外・重複を拒否） |
| 音符・テンポ・楽器設定 | 現行のJSONと整数Tickを維持 | 変更なし |
| 音声の波形 | `Float32Array` | `toSamples`（−1〜1） |
| 地球儀・望遠鏡の座標 | 計算は数値のまま。GPUへ渡す部分だけ型へ変換 | 変更なし |

型付き配列は範囲外の値を黙って変換する（`Uint8Array.from([-1])` は 255、300 は 44）。だから**型へ入れる前に必ず検査する**。この変換を通さずに型付き配列を作らない。

Draw文書は、検証（`validateDrawDocument`）と内容ハッシュ（`hashCanonical`）が保存形式（通常の配列）を前提にしている。編集形式（`toEditingDocument`）のまま保存・検証・ハッシュに渡さず、必ず `toSavedDocument` で戻す。往復後の検証とハッシュが旧データと一致することをテストで固定している。

## 7つの共通ルール

1. **原本と作業コピー** — 原本の寸法・色・透明度は変えない。音楽用の縮小、簡易エディター用の減色、パズル用の加工は別コピーにし、`describeWorkingCopy` で用途・変換条件・元画像への座標対応を残す（`toSourceDot` で元のドットへ戻せる）。
2. **ドット数・表示倍率・出力サイズは別物** — `createPixelFrame` で分けて持つ。64×64の絵を画面へ拡大表示し 2048×2048 で保存しても、作品は64×64ドット。タップ判定やパズル分割は `dotAtPoint` で作品の座標に直してから行う。
3. **色・透明度・音色の対応** — 色IDは `rgba-rrggbbaa`（PXD画像メタデータと同じ、`colorIdOf` / `colorIdOfHex`）。音色は色IDに結び付け、パレットの位置には結び付けない（`instrumentForColor`）。並べ替えても音は変わらず、未割当の色は絵に残って無音。ツールが勝手に再減色しない。
4. **保存版・履歴・未知情報** — 保存は「編集を始めた版」を `expectedRevisionId` として渡し、別の画面が先に保存していたら何も書かずに `LocalDraftConflictError` を返す。容量不足は `LocalDraftQuotaError`。どちらも編集内容は画面に残る。PXDの未知の項目は、同じPXDへの保存だけでなく、別名保存・別ツールへの移動でも `preservedPayload` として持ち運ぶ。
5. **バッファと非同期処理** — 編集原本のバッファを Worker へ transfer しない（transfer すると元が使えなくなる）。現在 transfer しているのはカメラ処理の使い終わったフレームだけで、意図してコメント済み。読み込みは `createLatestGate` で最新の1件だけが画面を置き換える。
6. **読み込み上限・権限・プレミアム** — 検査の仕組み（`checkReadLimits`）は共通、数値は用途別（`READ_LIMITS`: 投稿・編集・ゲーム・ジグソー・PXD）。撮影・編集・投稿に同じ上限を強制しない。パスが終わっても既存の作品を縮小・削除しない。
7. **描画と資源の解放** — 既存の共通Canvas描画を使い、変更部分だけ更新する。一時URL・Worker・画像・音声は `createResourceBag` に入れて不要になった時にまとめて解放する。全ツールの機能を起動時にまとめて読み込まない。

## 実施状況

| 段階 | 内容 | 状況 |
|---|---|---|
| 1. 共通仕様と検証 | 型・透明値・寸法・色ID・上限・保存版の契約、旧作品での往復テスト | 実装済み（`pixel-contract.mjs`） |
| 2. データ消失の修正 | 下書き保存の競合（4件同時保存で履歴が1件しか残らなかった）、PXDの未知情報の欠落（新しいPXDへ移すと消えた）、古い読み込みによる上書き | 実装済み。`local-drafts.mjs` は IndexedDB の1トランザクションで先頭版を確かめてから追記、先頭版が変わっていれば自動で積み直す（`expectedRevisionId` 指定時は止める）。`pxd-puzzles.mjs` は読み取った payload を保持して書き戻す。かんたんドットは開いた版を基準に保存し、読み込みは最新の1件だけが反映される |
| 3. 入口・出口を揃える | カメラ→描画→音楽→各パズルの受け渡し、PXD保存、画像出力を契約へ接続 | 未着手。各ツールの保存を `expectedRevisionId` 付きにし、上限を `READ_LIMITS` へ寄せる |
| 4. 測定してから軽量化 | TypedArray化、差分描画、再利用バッファ、音楽の重なり計算 | 未着手。実端末で時間とメモリを測ってから効果のある所だけ |

## 合格条件

往復後の画素・音符・色対応が一致する。旧作品と未知情報が残る。同時保存でも履歴を失わない。透明画像・長方形・拡大PNG・別タブ・容量不足・パス終了を試し、実端末で処理時間とメモリ使用量を測る。
