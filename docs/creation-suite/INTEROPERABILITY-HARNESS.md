# 共通保存・ツール間の往復検証仕様

2026-09-28。[見直し案](INTEROPERABILITY-REVIEW.md) の広い受入基準。ユーザー承認後の実装と実際の検証範囲は [PXD.md](PXD.md) を参照。以下の将来項目をすべて実装済みとは扱わず、テスト名や手順があるだけでPASSにしない。既存単体試験は部品の回帰基準として再利用する。

## 必須fixture

| ID | 入力 | 期待結果 |
| --- | --- | --- |
| image-identity | 16×16、32×16、64×64、512×512。透明・半透明・4色超・1px境界・非対称な左右目印 | 同寸法でCamera→Draw→Audio→Drawを往復してRGBA、論理寸法、色IDを保持。表示の整数倍出力と原寸を混同しない |
| oversized-import | 通常枠超、拡張枠内、拡張枠超、横長・縦長 | 原本を先に保持。中止/広告不成立で編集中の曲を変更しない。縮小する場合は別コピー・縦横比・座標対応・変換版を保存 |
| entitlement | 無効、有効、作業中失効、読込前失効、別タブ、別端末 | 既存の大きい曲・楽器は編集/再生/保存/出力可。新規拡張だけを判定。作品ファイルからパスを付与しない |
| camera-return | 正常、要求UUID不一致、15分超、取消、書込失敗 | 成功時のみ同じ曲へ撮影画像を適用。元曲のテンポ/音色を保持。失敗時は元曲へ戻って新しい撮影要求を作れる |
| pxd-history | 履歴reader/writer由来のDraw2 v1、v2 DRAW/AUDIO/GAME、Legacy ZIP v2 | 拡張子ではなく実ヘッダーで識別。幅/高さ、画素、ノート、asset bytes、ゲームJSONを照合。原本bytes/hashを保全 |
| pxd-unknown | 未知部品・既知部品内未知フィールド・将来版・未参照entry | 既知画像だけ編集して保存し、他のpayload bytes/ID/hashが一致。未対応の実行は不可。未対応と破損は別診断 |
| pxd-corrupt | hash不一致、重複entry、切れたpayload、不正長、上限超、危険なpath | 書込や実行前に拒否。元ファイル・既存下書き・前版を変えない。未知保持を検査の迂回路にしない |
| atomic-save | 画像/曲/問題を更新中に例外・容量不足・保存途中終了 | 全部品が同じ作品版で保存されるか、前の完全版が開ける。半更新を完了扱いしない |
| color-sound | 色の順序変更・同色統合・新色・色値変更・音色変更 | colorIdと音色対応を保持。非音楽ツールで保存してもノート時刻/長さ/強さ・音色ID/モデル版/seedを変えない |
| linked-cell-edit | 音楽付き画像をAudio/Drawで塗る、消す、同じ色へ変える | 対応画像セルと1セル1音のノートを同じ作品版で更新。セル変更と無関係なノート/楽器設定は保持。途中失敗では双方を前版へ戻す |
| old-audio | 持続音・セル間の開始時刻・複数clip・画面外音程・音声asset付き曲 | 簡易セルに投影しても原曲を正規化して上書きしない。表現できない部品はそのまま保持し、互換出力の損失を明示 |
| spot-roundtrip | 固定元絵+変更絵、1px差、離れた差、透明差、作者の統合/除外 | Drawで変更絵を編集→戻る→確認→保存→再読込で正解画素が一致。再編集後は再確定まで公開不可 |
| hidden-roundtrip | 1px対象、離れた複数対象、透明部分、空/重複マスク | 名前・画素マスク・固定画像版一致。画像resizeを新しい問題版として扱い、旧問題の座標を黙って変更しない |
| source-revision | 正常固定版、後続版あり、元版消失、改変hash | 最新へ勝手に差し替えず固定版を使う。欠損/改変は説明して中断。古い絵と新しい正解の混在を拒否 |
| public-permission | 自分の原本、他人の公開絵、非公開/消失絵、端末画像 | 自分の制作連携と公開画像のプレイを分離。他人の公開絵はJigsaw一時プレイ可でも編集・派生公開へ渡さない |
| derived-exports | 同じ作品のPXD/PNG/WAV/MIDI/問題画像/OGP | それぞれの対応範囲と元の固定版を照合。PNG再読込で楽器や問題の正解が復元すると扱わない |

乱数を含む音は、同じseed・音源版でイベントと基準レンダーを比較する。現行のMath.randomによる波形は端末間で完全一致する合格基準にしない。ノートイベント一致と波形bytes一致を別の検査項目にする。

## 実画面と処理量

- Chrome/WebKit、320×568・568×320・390×844・768×1024で、原本取込→作曲→描画→問題編集→保存→再開を実際に行う。ラベルとボタンの重なり、44pxの押しやすさ、ピンチ/ドラッグ後の座標を確認する。
- DPR 1/2/3、ズームと画面回転後のCSS座標→論理画素→音符→正解マスクを照合する。
- 同じ作品を別タブで編集したときは、古い版が新しい版を黙って上書きしない。保存失敗・再読込・要求期限切れ・戻る操作を含める。
- 16×16、128×16、32×32、64×64、128×128で疎な曲と全セル曲、短い音と長いrelease、重い追加音色を測定する。再生開始時間、入力から描画までの遅延、音切れ、同時ノード数、メモリー、10分以上の反復後の増加を記録する。
- 低性能の物理端末で検証する。暫定目標は編集応答のp95が100ms以内、再生開始が300ms以内、開始後の処理量が曲全体のノート数とともに常駐増加しないこと。実測前の設計目標であり達成値ではない。
- 負荷不足を理由に原本の画素や音符を黙って間引かない。合格しないサイズは新規拡張の上限に出さず、既存作品の保全と明示的な軽い作業コピーを提供する。
- 一時handoffの期限と共通ファイルの保存期限を混同しない。ファイルを外へ保存→ブラウザー内下書きがない環境で開く試験を必須にする。

## 実装単位と報告

旧形式fixture/reader→共通codec→下書き適合層→Camera/Draw/Audio→音楽上限→Spot/Hidden/Jigsawの順に実装・検証する。codecのunit合格後に実ツールの往復を行う。外部公開・新規DB変更をこの試験に含めない。

報告には現行Git SHAとdirty差分範囲、形式とfixture版、実行したファイル・件数、原本/RGBA/音符/未知payloadの照合結果を記録する。unit/browser/device/旧実ファイル/productionを別々にPASS/FAIL/UNTESTEDで表示し、未実装suite・0件・skipだけは成功終了にしない。
