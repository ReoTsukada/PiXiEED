# Luna 実装の分割案

個々の作業と完了条件は [実装ステップ](STEPS.md) を参照。この表は Luna に渡す単位を示す。

このページは次の実装契約のひな型。各着手時に SOL が現行 HEAD と dirty worktree を再確認し、Luna に読むファイル・書けるファイル・合格コマンドを具体的に渡す。本格版 iDRAW/iAUDIO/iGAME は改造対象にせず、Git 履歴から旧 Studio/PiXFiND を一括復元しない。独立して検証できる単位だけ進める。

| 順 | Luna の仕事 | 書込範囲の候補 | SOL の受入条件 |
| --- | --- | --- | --- |
| 0 | 現行画面・投稿の回帰 fixture とハーネス実行器 | 新規 `scripts/creation-suite-harness.mjs`、`tests/creation-suite/` のみ | 欠損/0件で失敗、既存地図/カメラ/望遠鏡テストが維持される。ブラウザー未確認を明示 |
| 1 | 旧SNS画像とPiXFiND問題の読取アダプター・入口。作品の公開先は地球儀に一本化し、販売は公開画面から外す | 新規読取モジュール、必要最小の `js/app.js`/旧 `/works/` 転送と問題入口、対応テスト | 位置のある作品のみ地球儀に表示し、位置のないSNS画像1件は元データを保持して推測配置しない。旧問題6件をID/slugで開く。Market参照4件を無料画像へ複製・販売表示しない。権利・旧URLを守り、実データ移行はしない |
| 2 | 共通の固定版参照と権限判定 | 新規 `js/creation/` と対応テスト | 元作品が不変、閲覧/再利用が分かれる、未知権限は拒否。既存投稿の hash 方式を保持 |
| 3 | かんたんドット絵の縦切り | 新規描画画面/ローカル文書/ラスター操作と対応テスト | 16px 作品の描く→保存→再開→PNG、320px 幅とタッチで成立 |
| 4 | 絵から短い音楽の縦切り | 新規音楽画面/PPQ Tick 小型コアと対応テスト | 固定版画像→決定的な初期案→編集→再生→保存→再開。元画像不変 |
| 5 | ジグソーと PiXFiND の独立判定 | 各純粋関数と対応テスト、後に別画面 | 元画素再組立て、作者が確定した正解領域、旧問題の閲覧互換、権限外作成拒否 |
| 6 | キャラクターからゲームの縦切り | 固定テンプレート/小型 runtime と対応テスト | キャラ/音の版固定、歩く→集める→ゴール、保存→再開、スマホ入力 |

各段階で UI を公開するのはその段階のブラウザー/端末ゲートが通ってから。0〜6 の完了は単体テストの PASS だけで決めない。Stage 1 の実データ照合は読取専用で別に実施し、旧投稿の位置付与・移行は件数、画像 URL、作者権限、旧共有 URL の確認後に扱う。依存追加、DB 書込、公開、コミット/プッシュはこの計画に含めない。

Luna への個別依頼は「Owner / Read scope / Write scope / Acceptance / Handoff」を必ず持つ。SOL は `IMPLEMENTED`、`UNIMPLEMENTED`、`UNTESTED` を分けてレビューし、実装が他の変更中ファイルに触れる場合はその段階を分割し直す。
