# 作品単位の描画・音楽

> 2026-10-01 方針変更: 以下の共通アプリ・共通PXD・モード切り替え案は撤回しました。現在の仕様は [ツール別プロジェクト](INDEPENDENT-TOOL-PROJECTS.md) です。各ツールが独立した作品を持ち、他ツールの作品はコピーとして取り込みます。以下は経緯の記録で、現在の操作仕様ではありません。

`/draw/` と `/audio/` は同じ制作アプリの二つの入口。端末内のPXDを正本とし、作品IDで分離する。「前回の曲」や旧画像棚による別の復元入口は音楽から除去。旧保存データ自体は削除しない。

## 操作

- 上部の作品名からサムネイル一覧を開く。新規・名前変更・複製・保存をまとめる。
- 上部の「描く」「音楽」は保存完了後、同じアプリ内で切り替える。ページ再読み込みとプロジェクト管理の作り直しは行わない。絵と曲の作業画像はそれぞれ保持し、「曲の絵を編集」で音楽画像を描画モードへ渡せる。
- 通常の入口は新規の空の作品。続きはプロジェクト一覧から選ぶ。URLで指定した作品がある場合はそちらを開き、他ツールの前回下書きで上書きしない。
- 描画の更新は曲に自動反映しない。「絵の更新を曲に反映」で最新保存版を確認し、同じ作品のテンポ・楽器設定を保持して音符を再生成する。パズルや公開済み作品を変えない。
- 絵、曲、色と音色の対応、選択・ズームを作品内に保持する。描画のUndo履歴はその画面での編集に限り、再読み込みをまたいでは保持しない。
- 編集後、約1秒の待機で自動保存する。同一内容は保存版を増やさない。保存失敗は表示し、編集内容を維持する。
- PXDのファイル読み込みは新しい作品IDのコピー。書き出しはその作品の絵・曲・未知の部品を一緒に保持する。

## 混同・競合対策

`project-session.mjs` は呼び出し時に編集スナップショットと作品IDを固定する。保存は直列化し、最後に保存できた版へ比較付きで追加する。遅い保存の完了で新しい作品のID・URL・復元先を変更しない。

別タブの更新を検出したら上書きを止める。複製して続けられる。一覧から作品を開く際に競合が起きた場合は、このタブの編集を独立した「別タブの編集」プロジェクトへ保存してから選択作品を開く。退避保存に失敗したら切り替えない。読み込み・描画失敗時は元の作品の内容とIDを復元する。

画像のみのPXDから曲を作る際は、新しい空の曲を基にする。直前の別作品のテンポ・楽器・音符を使わない。サイズ変換は確認を挟み、原本は保持する。

## 旧案の記録: 共通アプリとモードの寿命（不採用）

撤回前の試作では `creation-app.mjs` が入口、画面テンプレート、スタイル、URL履歴、単一workspaceを管理していた。現在の公開入口は `draw-entry.mjs` と `audio-entry.mjs` であり、共通アプリは読み込まない。旧案では各モードを `mountDrawMode` / `mountAudioMode` で開始し、`mode-scope.mjs` にイベント・タイマー・Observer・終了処理を登録していた。保存してから旧モードを終了し、音楽の再生や二重のイベントを残さない設計だった。

両モードのセル座標と連続線は `pixel-input.mjs`、キャンバス表示は既存の `pixel-canvas-surface.mjs` を使用する。ズーム配置のモード別制約と音楽の音符モデルは維持する。カメラ・パズルは今回の画面内統合の対象外で、保存後に従来のページへ移動する。
