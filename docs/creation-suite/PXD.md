# PXD：作品ファイルとツール連携

2026-09-28。ユーザーの承認により、旧Studio全体の復元ではなく、画像・音楽・パズルの保全と受け渡しを実装する。後続の「対応する色のみを読む」指示を優先し、音楽への自動減色は採用しない。この文書を現行の実装範囲とし、INTEROPERABILITY-REVIEW.mdの広い将来案とは分ける。

## 必要な仕組み

- PXD v3の読込・書出し、端末内の版付き保存。他の部品や未知のフィールド、payloadを保ったまま、担当部品だけ編集する。
- PNGへ再変換してドット寸法を推測せず、論理寸法とRGBAをそのまま格納する。透明画素の隠れたRGBも保持する。
- 同じ保存版を指定してDraw、Audio、Jigsaw、Spot、Hiddenへ移動する。カメラの撮影済み画像もPXDへ保存できる。
- 前後画像・対象マスク・ジグソーの配置を内包し、元端末の下書きがなくても、自分の画像を使った問題を別端末内の新しい下書きへ復元する。
- 旧PXDの理解できない部分を実行・正規化せず原本ごと残す。旧原本を変更せず取り出せる。

旧DAWや汎用ゲーム制作の画面、販売・課金・公開サーバーへの新しい保存方式は導入しない。ファイル内のパス期限・認証・公開権限は特典や投稿許可の根拠にしない。他人の公開作品で作ったジグソーは公開参照を保持し、画像を編集用素材として内包しない。

## 画素と音

画像の色にはRGBA由来の安定したcolorIdを付ける。Audioの音色スロットは既存のslotIdを使い、パレットを並べ替えても対応を変えない。

絵を音楽へ取り込むときは、対応する色だけを音符へ変換する。未割当の色も絵として表示・保存し、そのセルは無音にする。あとから色と音色を割り当てる。平均色や近似色で自動的に4色へ置き換えない。複数の色を同じ音色へ対応させられる。作曲専用のカメラは音楽面と同じ寸法で16色を撮影し、その撮影画像から音楽で使う色を決める。通常のPiXiEELENS撮影モードの初期配色は変更しない。

音楽の編集面は現在の16行・最大128列の範囲を使う。原本と作業面の寸法が違う場合だけ、縦横比を保つ最近傍の作業コピーと透明な余白をプレビューする。原本、変換条件、座標対応を別々に残す。初回は使用面積の多い実際の4色へ既存の音色を対応させ、その他を無音にする。あとから任意の色を同じ音色へ割り当てられる。作曲中の横幅変更はセルを伸ばさず、左側を基準に右側を追加・切り詰める。色の割り当てを再抽選しない。中止時は現在の作品を置き換えない。既存の拡張作品は、パスが切れても削除・縮小しない。

Drawは各辺16/32/64/128/256/512px・最大128色の範囲で、長方形も原寸のまま編集できる。非対応寸法や多色の原本は、明示して作業コピーを作り、原本を別画像として保持する。対応する音楽画像をDrawで編集すると、変更したセルの音だけを更新する。新しい未割当色は絵に残し、Audioで後から音色を決める。旧持続音やセル外音程の曲を、簡易セル形式へ無条件に正規化しない。

## 部品の保存場所

| 保存場所 | 内容 |
| --- | --- |
| `images/<role>/meta.json` / `pixels.rgba` | 論理寸法、安定した色ID、RGBA原本 |
| `draw/state.json` / `images/<role>/draw.json` | 描画用パレットと画素インデックス |
| `audio/state.json` / `audio/link.json` | 曲の正本、色と音色、セル座標とTickの対応 |
| `camera/state.json` | 撮影後のドット画像の設定・出自 |
| `puzzles/spot_difference.json` | 前後の固定画像、差分候補、確定状態 |
| `puzzles/hidden_object.json` | 元画像、対象名、マスク、確定状態 |
| `puzzles/jigsaw.json` | 凹凸の分割条件、配置、回転、結合、トレー |
| `legacy/original.pxd` | 読み込んだ旧形式の原本bytes |
| その他のentry / `opaquePayloads` | 未対応部品・未参照payloadを変更せず保全 |

`main`は原本、`draw`は明示して作った描画コピー、`audio`は音楽用画像。パズルの固定画像には`spot-before`、`spot-after`、`hidden`、`jigsaw-main`を使う。変更後画像を再編集するとSpotの差分を作り直し、正解を未確定に戻す。Hiddenも元画像が変わったら再確認する。画像を変更して既存の公開問題を黙って差し替えない。

## 保存・形式の境界

v3は`PXD\0`、32bit little-endianの版3、manifest長、JSON manifest、連結payload。entryはpath・offset・length・SHA-256で検査する。64MiB・512entryを上限とし、危険なpath、重複、切断、範囲重複、hash不一致を拒否する。旧Draw2 v1/v2の独自形式と、Legacy stored ZIP v2を識別し、原本と検証したentryを新形式へ保持する。未対応の圧縮ZIPや将来版を互換済みと扱わない。旧アプリがv3を読める保証はない。

端末内の保存先は`pixieed-pxd-v1`の`projects`。画像・曲・問題を一つのファイルbytesとして原子的に保存する。比較対象のrevisionが古い場合は、別タブの新しい版を上書きせず保存を止め、編集内容は画面に残す。過去の完全な版を保つ。既存の`pixieed-creation-drafts-v1`の下書きは一括移行・削除しない。ファイルの取り込みは新しい端末内コピーにする。

PNG/GIFは表示用、PXDは編集継続用。音楽のPNGも未割当の色を含む実際の作業画像を整数拡大して出力する。Canvas/PNGでは透明画素の隠れたRGBや半透明のRGBに正規化・丸めが生じ得るため、厳密なRGBA原本保持にはPXDを使う。PXDを開く・端末に保存する・書き出す操作だけでは外部投稿や広告視聴を実行しない。

## 検証

`node scripts/creation-suite-harness.mjs --suite pxd`でcodec、原本、未知部品、保存競合、カメラ要求、音楽セル、各パズルの復元を検査する。ブラウザーは`scripts/pxd-browser-harness.mjs`で実際の読込・保存・ツール移動・出力を確認し、`scripts/pxd-puzzle-camera-browser-harness.mjs`で元の下書きがない新しいブラウザーへのパズル/カメラ画像の復元を確認する。実行環境の指定は[HARNESSES.md](HARNESSES.md)を参照。

2026-09-28の最終検証:

- `node scripts/creation-suite-harness.mjs --all`: 297件成功、失敗・skipなし。うちPXD 37件、Audio 57件。
- `node scripts/pxd-browser-harness.mjs`: Chromium 11項目、WebKit 11項目成功。実IndexedDBの別タブ競合拒否、原寸RGBA・未知部品の保持、ファイル出力、Draw/Audio往復、未割当色の表示/無音/PNG保持、後割当、320×568/568×320pxでのパネル操作を確認した。
- `node scripts/pxd-puzzle-camera-browser-harness.mjs`: Chromium 7項目、WebKit 5項目成功。元の下書きがない隔離ブラウザーへSpot/Hidden/Jigsaw/カメラ画像を復元し、固定画素・対象名/マスク・配置/回転を検査した。Chromiumでは二本指ピンチで画素/音符/色対応を一緒に戻すことと、合成16色映像の撮影から同じPXD曲へ戻り原本を保持することも確認した。
- PXD関連18モジュールの構文検査と変更範囲の空白検査は成功。サイトへ依存を追加せず、既存のPlaywrightと既存ブラウザーエンジンを使用した。Safariでフィルター付き親要素の下へ保存パネルがずれる問題は、パネルを作業面の外へ置いて修正・再検証した。

物理端末、旧ユーザー実ファイル、本番投稿・広告は未検証。合成カメラの合格は実カメラの速度や画質の保証ではない。128×128の作曲面、旧DAW全機能の編集は今回実装していない。PNGの透明画素の隠れたRGB保持をCanvas mockの成功から保証しない。コミット・プッシュ・配備はこの作業では行っていない。
