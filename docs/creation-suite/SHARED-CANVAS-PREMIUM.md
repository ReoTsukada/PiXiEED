# 共通キャンバスとプレミアムの再設計案

2026-09-30更新。写真・描画・音楽に同じ寸法/色/RGBA8 Uint8Arrayを使う共通契約を実装した。新規共通作品には音楽16行への縮小を適用しない。旧音楽データの互換処理は保持する。実装範囲と検証結果は [SHARED-CANVAS-IMPLEMENTATION.md](SHARED-CANVAS-IMPLEMENTATION.md)、画像契約は [UNIFIED-PROJECT-TOOLS.md](UNIFIED-PROJECT-TOOLS.md) を参照。

## 推奨する形

初期キャンバスは1:1。長方形も全制作モードで共通対応する。選べる比率は1:1・3:4・9:16とその横向き。内部の正本は比率名ではなく整数のwidth/height。16/32/64/128/256pxの長辺から実寸法を一度決め、その作品では撮影・描画・音楽・問題制作に同じ実寸法を渡す。ユーザーの「簡単を目指す、MAX256px」の指定を反映し、新規制作には512pxを出さない。

例えば長辺128pxなら1:1は128×128、3:4は96×128、9:16は72×128。その作品を音楽で開いても同じセル数。新しい別比率で撮り直したい場合は、作品全体のサイズ変更としてプレビューして適用する。モード移動でリサイズしない。

画面の縦横比は作品の寸法に使わない。現在のカメラの「画面」比率を新規プロジェクトの固定寸法として保存するなら、開始時の実寸法に確定し、その後の画面回転/ウィンドウ変更では変えない。通常UIでは固定比率プリセットを優先する。

既存の長方形を正方形へ移行しない。任意の整数寸法はreaderで扱い、プリセットに丸めない。表示は縦横比を保って収め、描画と音楽ではピンチ/ドラッグで表示位置を変える。撮影では確定した寸法比で映像をクロップする。サイズ変更時に絵を横へ押し潰さない。

正方形だけにしてもRGBA8の保存契約は簡単にならない。長方形の保存量は同じ総画素数なら同じ4byte/px。音楽再生の負荷は幅の時間区間・割当色の音符・同時発音も関係するため、画像保存量とは別に測定する。

## 初回リリースの共通上限案

| 項目 | 通常 | パス有効中 |
| --- | --- | --- |
| キャンバス長辺 | 最大128px | 最大256px |
| 使用色 | 最大16色 | 最大32色 |
| 比率 | 1:1・縦長・横長を共通で利用 | 同じ。比率そのものは特典にしない |
| 描画・撮影・作曲・問題制作 | 上記の共通キャンバスをそのまま使用 | 上記の共通キャンバスをそのまま使用 |
| 楽器 | 基本音色を任意の色へ割当 | 既存の追加音色も利用 |
| 通常のPNG/PXD保存・大きい表示用PNG・投稿 | 基本機能 | 基本機能 |
| カメラGIF・タイムラプス・遊ぶ側の追加ヒント | 現在の通常機能 | 現在の拡張機能を維持 |

ユーザーの更新依頼に基づき128px/16色を通常枠、256px/32色を拡張枠として実装した。新規手描きの初期設定と共通上限は別であり、モードによって上限や現在寸法を変えない。パスは現行の広告1回で全体1時間追加する規則を維持する。

256px/32色でも、保存形式として扱えることとスマートフォンで音楽を快適に処理できることを分けて確認する。256×256のRGBAは262,144B（256KiB）で、512×512の1/4。画像本体と走査するセル数は減るが、最大サイズの音符生成・再生・編集が受入試験に通るまで「全ツール対応済み」として公開しない。音楽だけ縮小して対応済みにすることも避ける。

色数はプロジェクトの共通画像に使う異なるRGBAの総数を数える。透明色もこの予算に含め、色が違うのに近似で同じ色扱いにはしない。音楽で鳴る色の数、表示する選択パレット、楽器の種類数は画像の色数と別。色ごとの楽器割当は画像のRGBAを変えない。複数の色に同じ楽器を設定できる。

`Uint8Array`はRGBA8で使うためフルカラーを表現できる。16/32色は製品の共通ルールであり、配列の型の上限ではない。旧512px/フルカラーPXDは勝手に縮小・減色せず読み取り・保存・取り出しを維持し、新しい共通上限へ変換して編集する場合だけプレビューで確認する。

## 同じ色をどう作るか

カメラ/外部ファイルから新規作品を作る際に、選んだ共通サイズ・共通色数で画像を確定する。この時だけサイズと色を合わせる。確定した共通画像は、描画・音楽・問題制作が再減色せず同じRGBAで読む。

カメラのライブ配色固定・タップ更新の既存の操作感は維持し、作品から撮る場合は共有パレットと共通寸法を使う。新しい色を採用するときは画像と色の設定を同じ保存版に更新し、曲の既存の楽器対応を別の色へ推測で移さない。新色は未割当または明示的な割当ルールで扱う。

描画の新色追加で上限を超える場合は、その一操作を適用する前に拡張を案内する。既存色の利用/置換や明示的な作品全体の減色を選べるようにし、無断の減色で枠へ収めない。別モードへ移動してもこの判定を回避できない。

投稿の現行受付上限128色/各辺512px/512KiBは、新規制作の256px/32色上限とは別。この変更で既存の公開画像やサーバー受付上限を縮めない。容量条件は別なので、32色以下でも投稿できると保証しない。公開用PNGを実バイトで検証し、加工が必要なら確認する。公開コピーは端末内の正本を変えない。

## 判定を一つにする

`project.canvas-expanded` を共通特典として実装した。ツール別 `audio.canvas-wide` は互換の参照として残す。画像のwidth/height・実使用RGBA色数を共通ポリシーへ渡し、各ツールは判定結果と案内理由を使う。

パス自体の保存/広告/延長は `js/pixieed-pass.mjs` に維持する。作品にパス期限や広告視聴履歴を埋め込まない。これらのクライアント判定を、サーバー投稿権限や有料課金認証の証明として使わない。

## 期限切れの挙動

- 通常上限内の作品はそのまま制作できる。色に割り当てた追加楽器は、音楽の追加機能を開始するときに判定する。
- 通常の128px/16色を超え、新規制作上限256px/32色以内の作品は、表示・端末保存・PXD/画像の取り出しを維持する。新しい描画編集・共通寸法での撮影・曲再生/生成・問題制作操作を始める際は、パス追加を案内する。別モードに逃げて同じ拡張内容を編集できる状態にしない。
- 表示文の例：「この作品は256px・32色です。続けるには利用時間を追加してください。」作品を自動縮小・減色しない。通常サイズへ変える場合は本人が選び、履歴を保つ。旧512px/128色など新規制作上限外の作品は、パス追加だけで編集可能になると案内せず、共通上限へ変更する確認か原本取り出しを案内する。
- 有効な間に始めた一回の撮影・描画ストローク・生成・出力は完了まで続ける。終了時に保存する。次の操作は新たに判定する。無期限の再生を開始時の判定だけで永続許可せず、音楽の一回分の再生/生成範囲を固定する。
- 受取済みの画像を縮小しなければ開けない、保存しなければ出られないという画面にしない。通常の保存や書き出しは広告を必須にしない。

## 実装前に追加する受入条件

1. 通常128px/16色、拡張256px/32色の境界と1px/1色超過を、カメラ・Draw・Audio・各問題ツールで同じ判定結果にする。257px以上/33色以上ではパス追加だけで対応するように誤表示しない。
2. 96×128の写真を全ツールで往復し、寸法・全RGBA・色数・画像ID/hashが一致する。音楽を16行へ変換しない。
3. 9:16の作品をPC/スマートフォンで回転・画面変更しても、72×128の正本が変化しない。サイズ変更時はクロップ/余白の確認があり、単純な縦横独立伸縮をしない。
4. 旧フルカラー・現在の64px/16色Draw・16行Audio・512pxの撮影画像をそれぞれ読める。統一でどの画像を正本にするか曖昧な旧PXDは確認し、旧部品を捨てない。
5. 期限切れ・途中失効・別タブの時間追加・保存失敗を注入。編集中の内容を失わず、次の拡張操作は停止し、許可済みの一回の処理は完了する。
6. 画像の色数と楽器割当数を混同しない。32色画像に基本4音色を割り当てても画像は32色を保持する。追加楽器を選んでもRGBAや寸法を変更しない。
7. 256×256と144×256の32色画像で、入力・全色読み出し・音符化・先読み予約・同時発音・保存を実端末で測定する。256pxの画像が256KiBで収まる事実だけで音声の快適さを証明しない。

上限・共通寸法・プレミアム操作開始判定は実装済み。以下の受入条件をすべて確認済みとは扱わない。特に最大サイズでの実端末音声性能、物理カメラ、Safari、本番投稿は未検証。詳細は実装記録を参照。
