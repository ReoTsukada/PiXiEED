## 1. 確定条件と提案の位置付け

**ユーザーの確定条件は「入口は一つ」。** 最初に「投稿／販売／依頼」の用途を選ばせる入口は採用しない。一つの作成画面（以下composer）で、必要な情報を追加する。

常設の新規投稿入口を共通ヘッダーの `[投稿する]` 一つにする構成を第一候補とする。地球儀の中央投稿、セルの投稿ボタン、制作ツールの専用投稿を同時に表示しない。作品管理の「編集」は既存対象を同じcomposerへ戻す操作として残す。この配置、下記の寸法・文言・状態設計はAI間レビューを統合した推奨であり、ユーザーが細部まで承認済みとは扱わない。

中央ボタンを全ページ共通投稿へ変える対案は、撮影・再生・保存の移設を伴い、現行の制作主操作を弱めるため第一案に採用しない。UI側の相互レビューはヘッダー一入口案で合意しているが、これはユーザーによる細部承認とは区別する。

制作ツールごとの独立したプロジェクトは維持する。[ツール別プロジェクト](INDEPENDENT-TOOL-PROJECTS.md) に記載されたユーザー指示を優先し、投稿のために巨大な共通編集形式や全ツールの自動同期を復活させない。共通化するのは作成画面、公開用下書き、確認手順である。閲覧画面まで一画面にする要件はない。

本書保存時の作業は文書のみ。コード・DB・既存の作業中ファイルの変更、インストール、ビルド、投稿、commit、push、公開は含まない。

## 3. 一つの常設入口と元画面の候補

共通ヘッダーに同じ名称・意味の `[投稿する]` を置く。クリックすると同じcomposerを直接開く。未ログインでも先に作成画面を見せ、公開に必要な認証は下書きを保存してから行う構成を推奨する。

下部ナビの保存・再生・シャッターは制作の主操作として残す。地球儀中央の新規投稿操作は除去・変更対象だが、代わりの中央操作や4枠化は本書で確定しない。投稿を減らすために別の用途選択ボタンを置かない。

旧中央＋へ別動作を割り当てる場合、投稿に見える＋のままにせず、動作に合うアイコンとラベルへ変える。全画面・集中表示でヘッダーを隠す場合は、表示解除などヘッダーへ戻れる操作を確保し、第二の投稿入口を複製しない。composer表示中は開始用のヘッダー投稿操作を隠す等で再入を防ぎ、作成画面の公開操作と競合させない。

| 呼出元 | 候補として受け取るもの | 自動では行わないこと |
| --- | --- | --- |
| 制作ツール | 現在の作品から固定した出力、名前、出力形式、元画面の復帰情報 | 編集プロジェクト全文の公開、出品、展示ON |
| 選択した自分の公開作品 | 安定した作品／公開アセット参照 | 元作品の変更、既存商品の再販売 |
| 地球儀 | 選択セルの候補と復帰用の地球儀表示状態 | 精密位置の公開、展示ON、即投稿 |
| ホーム等 | 空の共通下書き、または明示選択した保存下書き | 本文から価格や場所を推定して設定ON |
| 作品管理の編集 | 指定された投稿等の既存参照と編集対象 | 新規投稿の重複作成、商品・サービスの同時書換え |

候補は出所を表示し、採用／選び直し／外すを可能にする。空キャンバスや出力未準備でもcomposerを開けるようにし、添付候補の生成失敗を文字投稿や相談受付の開始失敗にしない。形式選択が必要な出力は添付設定内で行い、入口を用途選択に変えない。

既存下書きがある場合、ヘッダーを押すとその下書きを復帰する。現在ツールの出力や選択セルで内容を上書きせず、「今回の候補を追加」等を本人が選べるようにする。新しい下書きを作る操作も復帰した画面内で明示し、開始時の用途選択にはしない。

「マイ作品」は端末保存／オンラインの所在を明示し、販売中・停止・受付状態等はバッジやフィルタで示す。同じ作品が販売状態になっただけで別の場所へ消える排他的な分類は作らない。所在と対象の性質を区別し、同じ作品から商品・サービスへの参照をたどれるようにする。

### 現行構造上の注意

共通ヘッダーに一本化すること自体は可能だが、ボタンを移すだけでは完了しない。

- `app.js` はヘッダー内部を書き換えるため、`site-header.mjs` と一緒に生成順・イベント登録を整える。再描画で入口が消えたり二重生成されたりしない。
- 地球儀はiframe内に選択状態を持つ。親ヘッダーが子の準備完了を待って候補を読み、元の地球儀状態を保つ接続が必要。スタンドアロン版にも入口は一つだけ置く。
- 描画の現イベントは `draw-to-globe` の存在を前提にする箇所がある。HTMLだけ削除して初期化を壊さず、出力処理をヘッダー用adapterへ移す。
- 現行 `js/globe/post-handoff.mjs` はcomposerへの受け渡しでhandoffを消費する。新経路では下書きへの永続化を確認してから受け渡しデータを消費し、中断時の再開情報と元プロジェクトは保持する。
- 上部への移動は下部投稿より親指で届きにくい。常に見えるヘッダー、44px以上の操作域、短い表示名、元画面への確実な復帰で補う。狭幅で既存のカメラ・音楽操作が押し出される場合はヘッダー配置を再検討し、第二の投稿入口を追加して解決しない。

## 4. composerの文章ワイヤー

一列の編集面を基本とし、用途を選ぶ開始画面は設けない。

1. **上部:** 「投稿を作成」または既存対象の編集名、下書き状態、閉じる／元画面に戻る。
2. **ひとこと:** 任意の共通本文。商品・サービス説明をここへ再入力させない。
3. **公開添付:** 「新規ファイル」「自分の作品」から追加。候補があれば出所とプレビュー、公開する内容、外す操作を表示。
4. **追加する情報:** 同じ画面内の短い設定行。販売、制作の相談受付、地球儀展示は初期OFF。三つの大きな入口カード、モード切替、別の作成画面への遷移にしない。
5. **対象カード:** 有効にした商品・サービス・展示だけ、要約と「変更」「外す」を表示。編集途中は「設定途中」と示す。
6. **公開要約:** 必要な行だけ「公開内容」「購入／相談できること」「展示セル」を表示。非公開購入データはファイル名等の本人向け確認だけを出し、一般公開の要約へ添付しない。
7. **下部:** 下書き保存状態と一つの固定主要操作 `[公開する]`。上下に公開ボタンを二重表示しない。処理中・確認待ち等は状態を表示し、公開完了と混同しない。

本文だけ、公開作品だけ、完成した商品／サービスカードだけでも成立可能とする。本文・添付・有効な対象が全て空の投稿は公開しない。添付を付けることを相談受付の前提にしない。

### 販売の発見性と入力

添付前も「販売するデータを追加」の行を見せる。作品選択後はカードに「この作品を販売する」を置き、同じ設定へ接続する。画像なしでも販売ファイルから商品を作れるようにする。

設定では商品名・説明・価格・販売状態・購入データ・必要な利用条件をまとめる。公開プレビューと「購入者に渡すデータ（一般公開されません）」は別領域とする。購入データから画像や内容を勝手に公開プレビューへ転用しない。商品説明は対象カードが表示に使い、共通本文との二重入力を求めない。決済方法、通貨、販売ファイル形式・容量等は実装契約で確定する。

既存商品は「参照して紹介する」と「商品自体を編集する」を区別する。後者は全掲載先への影響を示してから確定。売切れ・停止商品を参照しても再開しない。閲覧側の購入CTAは実際の販売状態と購入可能性を確認して表示する。

過去に公開したファイルを購入データへ選ぶ場合、確認できた公開履歴を警告し、別データを選べるようにする。履歴不明のファイルも未公開とは保証しない。「一般公開されません」は今回の購入データの配信範囲を表し、既存の公開URLや取得済みコピーを秘密に戻す保証ではない。

### 制作の相談受付

初期は作者が相談を受けるサービス。依頼者による募集や受注契約の自動成立とは分ける。範囲、料金目安、納期目安、受付状態を入力し、画像は任意。完成したサービスカードだけでも公開可能とする。本文に同じ説明を再入力させない。

閲覧側CTAは「制作を相談する」。相談開始・送信・契約・決済の成立を混同せず、初期提供範囲を表示する。既存サービスの参照追加と内容編集を区別し、受付停止を勝手に解除しない。商品購入CTAと同時表示する場合も、それぞれの対象名と状態を表示する。

### 任意の地球儀展示

「地球儀にも展示する」を本人が有効にした場合だけ設定する。候補セルを確認し、地球儀で仮選択→適用／取消を可能にする。取消は元セルに戻し、OFFではセルを公開しない。画像なし投稿／サービスを地球儀にどう表示するかは未確定なので、対応未実装の組合せは設定時に明示し、架空画像で成立させない。

「今回の投稿で展示しない」と「既存作品の展示を取り下げる」は別操作。既存展示の削除は対象と影響を確認し、商品停止・投稿削除と連動させない。

## 5. スタイル・補助シート・復帰

現行の明るい公開面、暗い制作面／地球儀、赤い主要操作、黄色い制作設定・選択状態を基準にする。色は `site.css`、`pixieed-design-system.css`、画面別CSSの読込順で変わるため、トークンを参照して実表示を確認する。

推奨は、共通composer内のテーマを一つに固定し、開いた元ページでフォーム配色を変えないこと。既存の暗い投稿・作品管理シートを基準に、公開操作を赤、設定・選択を黄に寄せる案とする。現地球儀の公開ボタンは黄なので、赤への変更は未承認のデザイン提案。販売・相談・展示を色だけで区別しない。

- スマホは既存の下部シート慣習、デスクトップは右側シートを基準とする。多項目composerには高さ拡張と内部スクロールを用意し、必要幅は実表示で決める。
- ロゴ・アイコンは既存資産を再利用。アイコン24pxと操作域44px以上を分ける。入力は48px程度・文字16px、複数行は88px以上を基準にする。
- カードは公開添付や設定済み対象の確認に使用する。追加機能の入口を三つの主役カードにしない。
- シートの開閉で本文、添付、参照、設定、スクロールを維持する。補助シートを一枚ずつ開き、閉じる／戻るは親composerへ戻す。フォーカスは開いた操作へ返す。
- モバイルのキーボード、safe-area、下部ナビと固定公開ボタンが入力欄やエラーを隠さない。狭い画面では本文を優先し、詳細は必要時だけ展開する。
- Escape／ブラウザー戻るは補助シート→composer→元画面の順序を定義する。下書き破棄は別の明示操作。元ツールの編集データは消さない。
- 地球儀の回転・ズーム、ツールのプロジェクト・表示位置を復帰情報として保つ。認証画面を閉じても作成の取消と扱わない。

`INTERACTION_PRINCIPLES.md` の直接操作、連続値のスライダー、詳細の折り畳み、キーボード代替、reduced motionを引き継ぐ。

## 6. ID・寿命・確定アセット

| 対象 | 独立して扱う理由 |
| --- | --- |
| ツールproject ID | 編集・保存・取り込みの所有境界。投稿の所有権証明にはしない |
| draft ID | composerの本文、添付、各対象の新規／既存参照、状態、復帰情報を束ねる |
| post ID | 告知と表示内容。削除しても商品・サービス・注文・購入権利を削除しない |
| 公開asset参照 | 出力内容を固定し、公開中に元プロジェクトの編集へ追従させない |
| product／service ID | 他の投稿から再利用でき、公開告知とは別に販売・受付状態を持つ |
| 購入データの版 | 公開プレビュー更新で購入済みの納品内容を無断差替えしない |
| order／購入権利 | 告知削除・展示撤去・販売停止後も必要な購入履歴と権利を保持 |
| placement IDまたは既存対応参照 | 展示セルと取り下げを投稿・商品と独立管理 |

固定asset参照には保存済みファイルの参照、出力形式、内容hash、元revision等の必要な情報を持たせる。元プロジェクトを後で再出力して審査対象を変えない。hash一致だけで異なる作品を強制統合しない。

**汎用release基盤を全ツールへ全面導入することは前提にしない。** 最初の対応形式で確定アセットと公開状態の境界を定め、既存の固定版契約を利用できる箇所は利用する。購入データは公開assetと別の配信・認可境界を持つ。具体的なテーブル名、移行DDL、既存注文との対応は未確定。

## 7. 下書きと多対象公開の状態

下書きには本文・公開添付本体、確定asset候補、商品／サービスの新規または既存参照、展示ON/OFFと仮セル、owner、復帰情報、requestKeyと内容fingerprintを保存する。ファイル入力の選択状態やメモリー上の関数だけに依存しない。保存失敗は表示し、保存成功と偽らない。保存容量・期限・端末内の購入データの扱いは実装時に確定する。

追加設定OFFの値は下書きに保持するだけとし、公開payloadへ含めない。非表示欄はフォーカス、読み上げ、`required` 検証から除外する。有効な対象だけで公開時のpayloadを組み立て、CSSで隠すだけの実装にしない。

| 状態 | 表示と可能な操作 |
| --- | --- |
| 下書き | 編集・保存・復元可能。一般閲覧、検索、購入、展示へ露出しない |
| 設定途中 | 該当行へ不足を表示。設定を続けるか、本人が「今回は公開しない・下書きに残す」を選ぶ |
| 公開準備中 | 同意した対象集合と内容を固定。重複送信を防ぐ。外部処理も非公開状態で照合 |
| 結果確認中 | 通信断等で結果不明。同じrequestKeyの結果確認・再送。別投稿として増やさない |
| 確認待ち | 受付済みでも審査等で未公開。購入・展示可能や公開完了と表示しない |
| 公開済み | 指定対象の確定結果・ID・状態を確認して表示 |
| 失敗 | 修正・再試行可能。元下書きと既存公開版を保つ |

未完の商品を黙って落として本文だけを公開しない。本人が除外した設定は下書きに残し、公開する対象集合と区別する。今回OFFの追加機能があっても、完成した本文等があれば投稿は可能。

一括確定できないStorage・決済等を含む場合は、準備対象を非公開で作り、照合・補償・再試行を定義する。新規商品だけ先に検索や購入へ露出させない。既存公開版は切替完了まで維持する。既存商品内容を変更する場合も、告知だけ更新／商品自体更新の意図と全掲載先への影響を明示する。複数対象の公開を安全に確定できない実装段階では、その組合せを未対応として説明し、成功表示で覆い隠さない。

認証前にdraftを保存し、認証復帰先へdraft IDを結び付ける。復帰時に同じ内容・表示位置へ戻し、ユーザー変更時はownerと既存参照の権限を再検証する。購入データや私有参照を別アカウントへ引き継がない。

## 8. 受入条件

1. 常設の新規投稿操作は画面ごとに一つ。ヘッダーから直接同じcomposerへ入れ、用途3択がない。地球儀親／子や初期化後に二重入口が出ず、composerの固定公開操作も一つ。
2. 投稿入口追加後も保存・再生・撮影が従来どおり使え、狭幅でもヘッダーの操作が重ならない。集中表示からヘッダーへ戻れ、別動作の中央操作が＋投稿に見えない。地球儀中央の最終配置は別途レビューする。
3. 文字だけ、作品だけ、画像なし相談カード、公開画像なし商品設定を扱える。空の投稿は公開不可。本文と対象説明の二重入力を求めない。
4. 添付前から販売・相談行が見つかり、追加設定OFFでは詳細・必須判定・フォーカス・読み上げ・公開payloadへ露出しない。値は下書きだけに保持し、価格・位置・出品を本文から自動ONにしない。
5. 設定シート、セル選択、認証、戻る、再読み込みの後に下書きと復帰情報が保持される。認証取消で下書きや元プロジェクトを消さない。ヘッダー再入で現在出力やセル候補が既存下書きを無断上書きしない。
6. 同じ制作物を非同期出力中に編集しても、選択した固定出力が公開対象になる。公開用選択に作業履歴や別の未選択作品を含めない。
7. 購入データが公開プレビュー／公開添付へ漏れず、公開歴を確認した原本には警告と別データ選択がある。未確認の公開歴を安全と保証しない。
8. 売切れ商品の紹介、受付停止サービスの参照で勝手に再開しない。購入／相談CTAの対象と実状態が一致する。
9. 商品・サービス編集の掲載先への影響を確認できる。告知削除や展示撤去で商品・注文・購入権利を削除しない。
10. 未完対象は本人が明示除外するまで公開を進めない。準備途中の新規対象は検索・購入・地球儀で見えず、旧公開版が維持される。
11. 通信断・二重クリック・再送で重複作成せず、結果不明／確認待ち／公開完了を区別する。成功結果のIDと状態を照合する。
12. 位置なし公開を仮座標で、画像なし公開をダミーPNGで成立扱いしない。地球儀展示OFF、仮セル取消、既存展示撤去をそれぞれ検証する。
13. 390px／1280pxの構造に加え、320px・横画面・実機キーボードで固定UIが本文／設定／エラーを覆わない。キーボード操作、focus復帰、reduced motionを確認する。
14. マイ作品の所在が端末／オンラインとして分かり、販売状態を変えても作品が排他的な別分類へ消えない。同じ作品の投稿・商品・サービス参照を確認できる。

## 9. 発見した現行不具合の修正候補

通常の地球儀composerに「パズル」の確認欄が表示された。`post-ui.mjs` は `.field.puzzle-handoff` に `hidden` を付けるが、`globe-prototype.css` の `.field { display: grid; }` が非表示指定を上書きする。今回の通常投稿観察で再現した。

該当欄の `hidden` を確実に非表示にし、パズルhandoffがある時だけ表示する修正を候補に記録する。広い全体CSS変更にせず、同種の追加設定にも対象なし／OFF／取消後の非表示とfocus除外を検証する。本書作成ではコードを修正していない。

修正後は見た目に加え、読み上げ・フォーカス・必須検証・公開payloadからの除外を確認する。OFFの内容を下書きに残すことと公開することを分離する。

## 10. 対応ファイルと段階実装

| 段階 | 利用者向けの結果 | 主な対応箇所・境界 |
| --- | --- | --- |
| 1 | 一つのヘッダー入口から同じ下書きを開き、閉じて元画面へ戻れる | `js/site-header.mjs`、`js/app.js`、`css/site-header.css`、共通composer／draftの限定module。既存中央主操作を保持し、投稿入口を重複させない |
| 2 | 制作出力・既存作品・セル候補を引き継げる | `js/creation/draw-page.mjs`、`draw-handoff.mjs`、`puzzle-handoff.mjs`、`js/globe/prototype.mjs`、`post-ui.mjs`、`post-handoff.mjs`。対応形式ごとにadapterを追加。HTMLの専用投稿操作とイベント登録を一緒に整理 |
| 3 | 場所なし／画像なしを含む一般投稿を正しい契約で受付・復元できる | `supabase/functions/create-post/index.ts` の契約拡張または新経路、必要な限定migration、公開reader・審査。新規APIと旧位置付き投稿の互換性を定義 |
| 4 | 作者の相談受付を作成・再利用できる | 共通composer設定、serviceデータと権限、閲覧CTA。初期は相談受付、契約・決済は別の対応範囲 |
| 5 | 商品の作成／参照と私有購入データを扱える | 商品schema／注文／購入権利の読取確認を先行。商品設定、私有Storage、決済・配信、既存商品の状態確認。未接続の決済を完成扱いしない |
| 6 | 複数対象の確認と安全な公開・撤去が通る | 非公開準備、結果照合、再送、審査、公開reader、購入CTA、placement。受入条件を端から端まで確認 |

段階1の画面試作では未接続機能を未対応と表示し、ダミー成功を作らない。PNGから始める場合も画像なし・場所なしの設計をAPIで塞がず、将来のGIF・音声・動画・パズル対応を形式ごとの独立した契約として追加する。段階は推奨であり、対象形式やAPI方式は実装着手前に合意する。

実装前に変更可能ファイルと合格条件を限定する。コード変更後は該当状態遷移の限定テストと代表的な表示確認を行い、統合時に関連回帰を一巡する。文書保存のためにインストール・ビルド・全体テストは行わない。

## 11. 最終レビュー結論と阻害要因

ヘッダー一入口は実現可能。現在のiframe、ページ別ヘッダー生成、出力handoffへの接続作業が必要で、専用ボタンを単純に削除する変更では不十分。主な操作上の懸念は上部への到達性と狭幅ヘッダーの密度であり、実機確認を配置確定の条件とする。

一般投稿・画像なし相談・場所なし公開は現行APIでは成立しない。商品／注文／購入権利の完全なschema、決済・私有配信、相談の送信先と運用は未確認。これらは設計保存の阻害要因ではないが、機能公開の前提条件となる。

本書は棚卸し、AIレビュー、文章ワイヤー、実装境界、受入条件を保存した。新UI、DB移行、決済、公開処理、hidden不具合修正は未実装。観察範囲外の動作を検証済みと扱わない。
