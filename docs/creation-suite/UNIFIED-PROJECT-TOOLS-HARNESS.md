2026-09-30更新。 [UNIFIED-PROJECT-TOOLS.md](UNIFIED-PROJECT-TOOLS.md) の受入仕様。共通画像fixture、版競合、矩形音楽、カメラ引渡しのテストを追加し、ローカルブラウザーで96×128の往復を確認した。ただし下記の全fixture・全端末ゲートを完了した扱いにはしない。実施済みの結果は [SHARED-CANVAS-IMPLEMENTATION.md](SHARED-CANVAS-IMPLEMENTATION.md) を参照。

## 画素と互換

1. U01/U03/U04のPXD encode→decode→各ツール保存→decodeで、編集していない画像の寸法・全RGBA・透明度・hashが完全一致する。上限外の旧U05は未変更の互換保存/取り出しで一致し、黙って新規編集へ移さない。
2. U05の画像メタデータは4KiB以下を目標とし、26万色のJSON一覧を作らない。画素本体は1,048,576B。プロジェクト全体のhashなどを含むサイズと画像メタデータのサイズを分けて記録する。
3. U08を新readerで開いて描画だけ変更し、曲・未知entry・未知フィールド・旧原本bytesを比較する。新writerを有効化する前に全対象readerの接続を確認する。
4. 壊れたlength/hash、重複ID、未対応schema、上限超過を拒否。開いていた別作品・未保存編集・原本を変えない。
5. U04の一セルだけ共通パレット内の色で塗り、そのセル以外のRGBAと前版を比較する。幅144が128や256へ変化せず、モード切替で16色へ減色されない。Undo/Redoは対象セルだけ復元する。
6. U01は通常の新規制作パレットと初期サイズを維持する。写真の全色をパレットのボタンに展開せず、どのモードでも使用色と共通画素が一致する。
7. U06の共通寸法への読込を中止した場合、元ファイルと現在の作業は保持。適用した場合、その画像をすべてのモードで同じ寸法・色で使う。
8. 出力PNGの整数倍セルを比較し、色の混合・UIパレットの混入がない。再読込時は記録された論理寸法を使い、拡大寸法を作業セル数にしない。
9. U03/U04のモード切替前後で現在画像ID・幅・高さ・全bytesが一致。新規プロジェクトに `draw`/`audio`/`hidden` 用の重複画素payloadを追加しない。変更しない往復で画像hashを変えない。
10. 共通画素はUint8Arrayでセルあたり4byte。1px=1byte/256色のインデックス配列と混同しない。Canvasの型viewを編集用の第二正本にしない。

## プロジェクト隔離と撮影

1. 作品AにU04、作品BにU01を保存。Aのカメラ→描画→もの探し→音楽→描画の往復、Bの別タブ編集、Aの再開で、作品ID・画像ID・版・曲・問題が混ざらない。
2. Aの現在画像・曲・問題を保存して撮影。共通寸法で撮り、採用前はAを変えない。採用後は共通画像の新版として全モードに反映し、以前の版と公開済み問題を維持する。
3. 単独カメラ入口はライブ表示、作品入口は共通画像更新の撮影。撮り直し/キャンセルは保留画像だけを破棄し、作品の保存済み画像を破棄しない。
4. 遅い保存、撮影中の別タブ更新、移動直前の連続編集、保存失敗、戻り先期限切れを注入。CAS競合では上書きを止め、撮影結果や編集を別作品へ退避できる。退避失敗なら切り替えない。
5. ファイル読込と複製は新作品ID。元の作品・旧下書き・他モードの状態を維持する。
6. GIFを静止画としてPXD保存完了扱いにしない。静止画連携の対応範囲を確認する。

## 問題と公開

1. U03/U04からもの探しを作り、背景にない減色を行わず、元画素座標でマスクを保存。DPR 1/2/3、ズーム、ピンチ、画面回転でも同じ対象を指す。
2. U07で間違い探しの前後を確定。前・後のいずれかの画像編集で未確認へ戻り、公開済みの問題版は維持。画像差し替え・寸法変更でも古い正解を自動承認しない。
3. ジグソーの同寸法別画像に旧ピース進捗を付けない。固定画像版から再開した盤面は同じ画像を表示する。
4. 128色以上の画像は投稿用コピーだけ減色。前後画像に同じパレットを使い、差分の消失・余分な差分を検出したら共有を止める。もの探しは対象の視認性を再確認する。
5. 投稿用PNGが現在の8〜512px/128色/512KiB制限を満たすことを実バイトから検証する。共有後も端末内のフルカラー原本と作業画像が一致する。
6. U09の遊ぶ画面にPXD/画像保存・素材複製・Draw編集がないことを確認。URLパラメーター、PXD読込、共通作品シート経由でも許可しない。参照を持つだけで所有者扱いにしない。

## 音楽とパス

1. U02/U03/U04を音楽で開き、64×64/96×160/144×256の同じ共通画像を表示する。16行化・減色・別作業画像を作らない。割り当てた色だけ音符になり、未割当色は表示される。
2. 描画と音楽で同じセルを塗り、双方の同じRGBA値・1セル1音・色/楽器対応・テンポ・行音程を照合。画像とノートの計算を同じ保存版に結び付ける。
3. 音楽からの撮影は共通画像寸法で撮影し、正しい作品・版へ戻る。途中でBを開いた場合はBを上書きしない。
4. U10で期限後の新しい拡張操作は追加を案内する。期限直前に開始した生成・再生は完了まで続行。原本・曲の保存やPXD出力は妨げず、パスを作品に埋め込まない。
5. 高さ256行でも画像の行を捨てず、保存した音程対応を再現する。幅256列の予約は近い時間区間だけを対象にし、同時発音規則を変えて画素/対応ノートを黙って削除しない。
6. 異なる旧main/audio画像のPXDを開き、統一前に基準画像を確認。元の旧部品を保存し、未確認でどちらかを縮小/上書きしない。

## ブラウザーと性能

- 320×568、390×844、844×390、1440×900で撮影・描画・音楽・問題制作・結果を確認。作業画面は縦横にはみ出さず、44px以上の押せる範囲が隣と重ならない。作品シートのみ必要に応じて内部スクロール。
- 作品名/モード/画像選択/保存状態が全ツールで同じ操作。中央ナビの主操作は各モードで明確。シートを開閉しても現在の編集を失わない。
- 256px/32色の連続線入力・Undo・autosave・同寸法音楽再生を測定。指の移動ごとの全画像/全プロジェクト複製を避け、変更範囲を描画する。大きい音楽の処理不足を画像の縮小で回避しない。実端末で入力を妨げる停止があればwriterを有効化しない。
- 新規256px作品20件と旧512pxの作品を混在させ、複数保存版で一覧を開く。サムネイル表示のために履歴全RGBAを展開しないことを測定・記録する。保存失敗/容量不足を注入し、成功表示の誤りがない。
- ローカルChrome系、実機Safari、物理カメラ、本番投稿を別ゲートとする。今回取得できなかった結果はUNTESTEDと記録する。
