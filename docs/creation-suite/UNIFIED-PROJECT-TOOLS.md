# カメラ・描画・音楽・パズルの共通プロジェクト

2026-09-30更新。既存PXD v3を拡張し、共通RGBA8画像・寸法・色数判定と全制作モードのプロジェクト接続を実装した。実装範囲と未検証事項は [SHARED-CANVAS-IMPLEMENTATION.md](SHARED-CANVAS-IMPLEMENTATION.md) を参照。別の保存形式やクラウド同期は追加していない。

## まず決める画像の扱い

ユーザー訂正を反映：写真・ドット絵・音楽で、**同じ幅・高さ・画素座標・色・画素データ**を使う。一つの作品の現在画像を `Uint8Array` のRGBA8として保存し、各ツールは同じ画像IDと保存版を参照する。モード切替で縮小・減色・音楽用コピーを作らない。

`pixels.length === width * height * 4`。一セルはR/G/B/A各1byteで4byte。`Uint8Array` は256色制限を意味しない。各成分を0〜255で持ち、画像はフルカラーと透明度を表現できる。Canvas用の `Uint8ClampedArray` は同じbufferの表示用viewとし、別の画像正本にしない。ページ移動・別タブ・書き出しではbytesの再読込は必要だが、保存する画像の正本は一つ。

比率とプレミアムの共通ルールは [SHARED-CANVAS-PREMIUM.md](SHARED-CANVAS-PREMIUM.md) を参照。ユーザーの更新依頼に基づき、初期1:1・長方形も共通対応、通常128px/16色・拡張256px/32色を実装した。旧512px/全色の互換読込・保存対応は新規編集上限と区別する。

| 用途 | 共通契約の規則 |
| --- | --- |
| 通常のカメラ | 新規撮影は共通上限最大256pxと共通色数から画像を作る。既存作品から撮る場合はその作品の共通寸法・色数を使い、採用時に現在画像を更新する |
| 新規のかんたんドット | 今の16・32・64pxと16色を初期設定にする。作った作品の寸法と使用色を全モードで共有する |
| 撮影画像の描画編集 | 撮影画像の同じUint8Arrayを編集。64px・固定16色への自動変換をやめ、選択パレットと画像の使用色を区別する |
| 大きい画像の読み込み | 今回の新規共通編集は各辺256px以内・共通色数内。上限外ファイルは共通寸法/色数への変更を一度だけ確認し、その結果を全ツールで使う。元ファイルは履歴/バックアップとして保持し、ツール別の作業画像にしない |
| ドットで音楽 | 16行固定を外し、画像と同じ幅・高さを使う。Xは時間、Yは保存された行音程対応、色は楽器。対応する色の一セルが一音となり、未割当色はそのまま表示して鳴らさない |
| もの探し・間違い探し | 新規作品の共通画像を元の画素座標・同じ色数で扱う。正解をCSS上の表示寸法から保存しない。旧問題と新規制作の上限を混同しない |
| ジグソー | 既存の長方形・フルカラー対応と最大2,097,152画素の処理範囲を維持。制作と公開作品を遊ぶ画面の権限を分ける |
| PNGなどの出力 | 編集用の論理寸法と整数倍拡大した表示用寸法を分ける。現在の長辺最大2048pxを目安とする拡大を維持し、ぼかし・補間で色を増やさない |
| 地球儀への投稿・共有 | 現在の受付上限は各辺8〜512px・128色以下・512KiB以下。必要な場合だけ投稿用コピーを作り、見た目を確認する。端末内の原本・編集データは変えない |

フルカラーの編集は、撮影画像を写真風に再処理する機能ではない。今のカメラが生成した画素をそのまま受け取り、塗る・消す・スポイトなどを適用する。透過もRGBA8で保持する。

新規制作の16色は初期の選択パレット。作品の使用色は全モード共通で、モードごとの16色/4色への変換はしない。操作パレットには選択色だけを表示し、画像中の全色をボタンにしない。スポイトで選んだ色は画素のRGBA値から取得する。サイズ・減色を明示的に適用した場合は共通画像全体の変更として扱う。

## 現在の問題と根拠

- カメラは `js/pixel-lens/app.mjs` の旧 `mountPxdTools` を使用。既存プロジェクトを開いて保存すると `main` に撮影結果を書く。Draw/Audioの新しい作品一覧・競合保護とは別経路。
- `js/creation/draw-core.mjs` の簡易化は最大64px・16色。`draw-page.mjs` の `replaceDocument` は常にこれを適用する。512px・128色以内でPXD読込に成功した画像も簡易化され、同じroleに保存され得る。変換を要した場合だけ別コピーを作る現行経路では、すべての原本保持を保証できない。
- 正確なPXD→Draw変換は各辺16/32/64/128/256/512px・128色以下のみ。カメラの96px、160px、288×512pxやフルカラーは対象外。もの探し・間違い探しもDraw互換を必要とする。
- `js/creation/pxd-project.mjs` の画像schema 1は、RGBAに加えて全色のJSON一覧を保存・再検証する。フルカラーでは一覧の方が大きくなる。
- 間違い探しの変更後・もの探しの画像編集は確定を解除するが、変更前の画像編集は同じ解除処理の対象外。ジグソーの同寸法画像変更も固定画像版の扱いを確認する必要がある。
- 作品一覧の `listProjects` は保存履歴を含むレコードを全件読み出す。画像が大きい作品を増やす前に、一覧と履歴本体の読み出しを分ける必要がある。

### 色一覧の試験計測

## 保存の設計

### 一つの現在画像と履歴

- 一つの作品ID・現在画像IDを全ツールで維持。画素・寸法・出自・内容hashは共通画像へ集約し、モードは同じ正本を編集する。
- 撮影プレビューは採用前の一時データ。採用すると共通画像の新しい保存版にする。以前の絵は保存履歴へ残し、常時使う描画コピーは作らない。別作品にしたい場合は明示的に新規/複製を選ぶ。
- 原本保護は撮影時の保存版と変更履歴で行う。モード切替のために `draw`・`audio`・`hidden` などの同内容画像を増やさない。
- 音楽は共通画素と楽器/行音程/テンポの対応から音符を生成する。音符の計算キャッシュは再作成可能なデータであり、第二の画像正本にしない。色を塗れば同じセルの表示と音が更新される。
- 過去の曲・旧PXDで画像と音符が一対一でない情報は保持し、勝手に削除しない。旧形式から共通画像へ移すときの競合は確認してから適用する。
- もの探しは同じ画像の座標に対象を記録。間違い探しの比較前/後や公開問題は必要な固定版を参照し、通常の制作モード用コピーとは区別する。
- PXD全体は現行の64MiB・512エントリー上限内。超過時は保存できたと表示せず、未保存の内容を保持して別プロジェクトへの分離などを案内する。原本を勝手に間引かない。

### 画素と色の保存

PXD v3コンテナを維持し、画像メタデータschema 2を追加する。画素は `Uint8Array` のRGBA8を正本にし、フルカラーの全色一覧は保存しない。既存schema 1・旧Draw文書を読み取り、画素・色・透明度を完全一致で変換する。未知のPXD部品はそのまま保持する。

旧Drawのインデックス文書は互換読込として残す。共通描画面には直接RGBAの更新経路を追加し、型・寸法・透明度の変換を共通適合層に集約する。撮影・描画・音楽の共通画像書込を同じ経路にし、旧のツール別画素配列への二重書込をしない。音楽の色IDはRGBA値由来の安定IDを必要な色にだけ作る。

音楽の大きい画像は画像自体を縮めず、必要な時間区間だけ音符化して予約する。高さと音程数を同一視せず、各行の音程を保存し、音程範囲を超える行を黙って切り捨てない。同時発音の上限・重複音の集約は音声処理上の規則として示し、画素や作曲内容を削って軽量化しない。旧16行の行音程はそのまま読めるようにする。

旧PXDに異なる `main` と `audio` の絵がある場合は、自動でどちらかへ寄せない。統一時に基準となる画像を確認し、元のPXD部品を未編集の互換データとして保持する。新規プロジェクトではこの分裂を作らない。

画像schemaを理解できない旧クライアントで編集できると説明しない。未対応部品は編集を断り、元bytesを保つ。新しいreaderを全対象ツールへ先に接続してからwriterを有効化する。

作品一覧は小さなサムネイル・作品名・寸法・更新日時だけを読み、作品を開いた時に必要な本体を読む。Undoは変更した画素範囲を保持し、フルカラー画像全体を指の移動ごとに複製しない。既存の保存履歴は無断で削除・再構成しない。

## 共通UIと利用の流れ

画面全体を作品・カメラ・盤面に使う現在の構成を維持する。HTMLは意味と操作要素、CSSは配置・演出、JavaScriptは作品状態とツール固有処理を担当する。

- 上部は「作品名／保存状態」と「現在のモード」。モード選択は小さなシートにまとめ、全ツールのボタンを常時横並びにしない。
- 作品名から同じサムネイル一覧を開き、新規・複製・名前変更・PXD保存を扱う。通常制作では現在画像は一つ。履歴や比較画像は専用の確認操作で見る。
- モードは撮る・描く・音楽・もの探し・間違い探し・ジグソー。ページ入口は現在のまま。切り替え前に保存し、同じ作品ID・現在画像ID・固定版を渡す。
- アイコン、押せる範囲、パレット、Undo、シート、結果画面の部品は共通にする。中央ナビボタンと必要な操作は撮影・再生・問題の確認など、そのモードの主操作を維持する。
- 一般のカメラ入口は毎回ライブ撮影を開始する。作品から来た撮影は共通画像と同寸法で撮り、採用時に現在画像を更新する。独立撮影は撮影結果から新規作品にする。前回の撮影画像をライブ画面と誤認させない。
- カメラのプレビューから「描く」「もの探し」などへ渡し、その場で同じ作品を保存して移動できる。既存の撮り直しと通常PNG保存も維持する。
- 音楽からの撮影も作品の共通寸法で撮影し、元の作品へ戻る。音楽モードへ移るための縮小・減色・16行化はしない。対応色と楽器は画像を変えずに設定する。
- UI選択・ズーム・スクロール位置は作品とモードごとに保持。読み込みが失敗したら前の作品と表示を維持する。

操作の押せる領域は最低44pxを基準に、320×568px・横向き・PCで重なりを確認する。作業中はキャンバス上に広告を追加しない。既存の結果・プレビュー広告は結果画面内で収める。

## 原本・問題・権限の保護

撮影開始時に作品ID・版・戻り先・操作IDを固定する。撮影中に別タブで作品が更新された場合は上書きを止め、結果を別作品へ退避できる。保存完了が遅れても別作品の復元先を変更しない。

問題は画像IDだけでなく内容hash・固定版に結び付ける。間違い探しは前後どちらの画素変更でも確定を解除。もの探しは画像変更時に対象位置・見え方を再確認。ジグソーは同寸法でも画像が違えば旧プレイ状態を新画像へ無条件に結び付けない。作業中の変更で公開済みの問題を差し替えない。

共有時に128色へ減色するなら、間違い探しの前後画像は共通パレットを使い、共有用画像から差分を再検証する。答えが消えたり余分な差分が出た場合は公開を止める。もの探しも対象が識別できることを作者に再確認してもらう。サーバーの現行寸法・色数・容量検証は緩めない。

他人の投稿作品は遊ぶ用途の参照だけ。共通作品一覧に自分の編集素材として追加せず、PXD・画像保存・複製・描画編集を有効にしない。公開ジグソーの遊ぶ画面には編集用ワークスペースを直接取り付けない。端末内のIDやファイルの所有者申告だけで公開作品の所有権を付与しない。

パス失効時は既存の広い曲・追加音色を削除・縮小しないが、新しく開始する拡張操作は止めて追加を案内する。再生・編集・生成などの開始ボタンで有効なら、その操作は完了まで続行する。作業保存・原本の取り出しは可能にする。画像部品にパス期限や広告状態は保存しない。

GIFの連続フレームを描画・曲・問題へ渡す機能は今回の対象外。静止画を共通化した後に別途扱う。GIFを一枚絵へ置き換えて保存済みと表示しない。

## 実装順と担当境界

横断的な編集形式の変更のため、提示されたAGENTS.mdの事前確認後に着手する。依存追加・公開DB変更・ゲーム制作復活・コミット・プッシュは本案に含めない。

| 順序 | 実装する範囲 | 主なファイル | 完了条件 |
| --- | --- | --- | --- |
| 1 | 画像schema 2・一つの現在画像の参照・全色一覧の解消 | `pxd-project.mjs`、共通画像適合層、PXD fixture | 旧データ・未知部品の往復とRGBA一致、フルカラーのメタデータが色数に比例しない |
| 2 | 共通色/長方形描画と同寸法音楽の適合 | `draw-core.mjs`、`draw-page.mjs`、`pixel-canvas-surface.mjs`、`audio-core.mjs`、`audio-viewport.mjs`、`pxd-draw-audio.mjs` | 144×256px・32色の写真を描画/音楽で同じ画素のまま編集し、16行化も別画像保存もない |
| 3 | 共通寸法での撮影と全ツールの作品シート | `project-workspace.mjs`、`project-session.mjs`、`pxd-ui.mjs`、`pixel-lens/app.mjs`、各ページHTML/CSS | 同一作品の撮影→編集、A/B隔離、採用前キャンセル・別タブ競合・保存失敗回復 |
| 4 | 写真から問題制作と固定版の保護 | `pxd-puzzles.mjs`、各puzzle core/page | もの探し・間違い探しが長方形/全色を扱い、画像変更時の確定解除と旧問題保護 |
| 5 | 大きい音楽の処理・公開用出力・一覧性能 | `audio-page.mjs`、音符生成/再生、`pxd-store.mjs`、`project-catalog.mjs`、共有準備 | 共通画像を変えず対応色だけ再生・失効時案内・減色後の答え確認・大きい作品一覧の測定 |

各段階は前段のreader/contractを受け取ってから実装する。同じ保存契約を複数エージェントが同時に変更しない。受入仕様は [UNIFIED-PROJECT-TOOLS-HARNESS.md](UNIFIED-PROJECT-TOOLS-HARNESS.md) を参照。
