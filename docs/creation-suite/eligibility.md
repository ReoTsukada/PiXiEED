# 投稿・再利用・正解判定を分ける

「ドット絵かどうか」を単一の曖昧な点数で決めると、細かい手描き絵やカメラ写真を誤って排除する。まず機械が客観的に確認できる入力条件、投稿者が申告する出自、公開・再利用の権限、ゲームの正解を別の判定として扱う。判定結果は画面に理由を具体的に表示し、制作者が直せる項目だけ修正導線を出す。

## 4つの判定

1. **ファイル受付:** 地球儀の現行投稿画面はPNG/WebPを受け取り、画素を数えてPNGへ正規化する。受付FunctionはPNGの実画素を復号し、寸法・色数の申告と照合する。新規投稿の規則は8〜512px、1〜128色、512KB以内。DB側の新規画像用制約は移行案まで作成したが未適用であり、公開投稿を通した確認はまだない。旧 `js/post-composer.js` の8〜128px/512色は現行地球儀から呼ばれない旧画面の規則で、全サイト共通とは称しない。既存の受理済み画像や状態更新を遡及的に不適格にしない。
2. **作品の出自:** `pixel_art` は手描き/持込、`pixel_camera` はPiXiEEDカメラ由来として、保存した方法と利用者への説明を一致させる。少色・低解像度だけで「手描き」と断定しない。旧 `post_kind` の欠落は表示互換の既定として扱い、著作者性の証明にはしない。
3. **公開と再利用:** `status=published` と画像の公開可否で閲覧を決める。編集・派生公開や他ツールへの制作入力は本人の端末内画像だけとする。ただしジグソーの端末内プレイだけは公開中の投稿画像を一時的に切り分けられ、画像そのものは保存しない。旧 PiXFiND の `client_id`、サンプル画像、URL が分かるだけでは編集権限を与えない。`pending/rejected/hidden` や審査前画像を公開 API へ流さない。
4. **遊びの正解:** 間違い探しは作者が確定した差分領域、もの探しは作者の対象マスク、ジグソーはピース ID と置き先を正本にする。色の近さ、画像認識、見た目だけを唯一の正解にしない。曖昧な候補は制作時に作者へ提示し、公開時には固定した正解版を使う。

## 判定ハーネス

`ELI-01` 同じファイル fixture がクライアントと受付 Function で同じ受理/拒否と理由になる。`ELI-02` 申告寸法・色数を偽ってもデコード実体に反する値を受理しない。`ELI-03` 手描き・カメラ・旧列欠落を分類表示し、出自を勝手に塗り替えない。`ELI-04` 公開閲覧可・再利用不可の作品で編集入口と API 書込を両方拒否。`ELI-05` 旧 PiXFiND の `client_id` を知るだけでは編集できない。`ELI-06` 問題の拡大率・DPR・レイアウトが変わっても同じ元画素が正解。`ELI-07` 未知の列、壊れた権限値、欠損画像は失敗側に倒し、既存の他の投稿表示は続ける。

初版で作るのは説明可能な決定的判定と作者確認。AI による物体認識・品質スコアは正解や権利の代わりにせず、導入するなら別の評価データと誤判定率を測ってから補助として扱う。
