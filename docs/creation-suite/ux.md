# 既存サイトとつながる画面設計

## 守る基準

現行の各 HTML に古いナビのマークアップが残っていても、実行時は `js/app.js` の `renderPublicShell()` が5項目のアプリナビへ置き換える。実画面の基準は「ホーム・地図・ページ固有の中央操作・ツール・マイページ」。`tools/index.html` のカードはドット絵カメラと望遠鏡の2件で、ツール一覧の中央操作はカメラ。ここは新サービスを開発中に並べ替えたり、未完成の入口を出したりしない。新ツールは同じ言葉、余白、色、アイコンの使い方を引き継ぎ、固有の編集画面だけ必要な面積を取る。中心の操作は画面ごとに「描く」「再生」「遊ぶ」「完成を確認」など一つに絞る。

## 行き来を短くする

素材を選ぶ → ひとつ作る → 下書き保存/再開 → 作者が確認 → 公開先を選ぶ、という順を共通にする。元画像は自分の端末に保存した絵・カメラ写真から選び、他人の投稿作品カードから作成ツールへは進まない。手描きとドット絵カメラは出自を表示するが、画面上で編集方法を制限する理由にはしない。公開作品のカードには閲覧・遊ぶ操作だけを出し、作成メニューは出さない。閉じる・戻るで未保存の変更を黙って消さない。

詳細設定は必要な場面だけ開く。保存、音の再生、ゲームの Play、パズルの正解確認といった主操作を同時に大きく並べない。画面幅 320/390/768/1280px と短い縦画面で、キャンバス、タイトル、ナビ、確認ボタンが重ならないことを基準とする。タッチ、キーボード、支援技術に同じ状態と結果が伝わるようにする。

## 公開する順番

まず旧公開作品を壊さず表示できることと、新しい下書きが端末内で保存/再開できることを確認する。次に描画の完成フローを公開し、音・ゲーム・パズルは各自の保存と実機操作が通ってから追加する。既存作品の再公開は権限・画像到達・旧 URL の確認が完了してから行う。画面デザインだけの完成を公開基準としない。

## UI ハーネス設計

`UX-01` 実行時の5項目ナビとページ固有の中央操作、既存カードの URL/見出しが変わらない。HTML の静的ナビだけを比べて PASS にしない。`UX-02` 未完成ツールは公開一覧に出ない。`UX-03` 320/390/768/1280px と短い縦画面で主操作、編集対象、下部ナビが重ならず、スクロール後も操作できる。`UX-04` タッチとキーボードで作成→保存→再開を完了できる。`UX-05` 他人の投稿作品カードに二次制作を提示しない。`UX-06` 画面を戻る/更新しても確認前の公開や未保存データの消失が起きない。ブラウザーの DOM/スクリーンショットと実機操作は純粋関数テストと別に記録する。
