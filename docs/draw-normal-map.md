# PiXiEEDraw ノーマルマップ

2026-11-16。Drawでは、絵からノーマルマップを推定してプレビューする方法と、専用レイヤーに方向色を直接描く方法を使えます。ノーマルマップは絵の色とは別に保存され、通常の画像表示・PNG出力には混ざりません。

## 方向色で描く

1. レイヤー・フレームパネル上部の「ノーマルマップを作成・編集」から開き、「専用レイヤーで描く」で法線レイヤーを作成します。
2. 初回は「透明から描き始める」が既定です。「元の絵の範囲を平面色で埋める」も選べます。既存の法線レイヤーを開き直しても消去や塗り直しは行いません。元絵のアルファや色は変更しません。
3. 法線レイヤーを選ぶと、通常の絵を下敷きにして法線を最前面に重ねて表示します。透明部分や消した部分からは下の絵が見えます。透明色と、正面および8方向それぞれの30°・60°に対応する17色を使い、通常のペン・塗りつぶし・図形ツールで描けます。
4. 「凹凸」パネルの描画レイヤーモードでは、法線を照明したプレビューを確認し、OpenGL（Y+）またはDirectX（Y−）向きのノーマルマップPNGを保存できます。

パレットは「ゆるい傾き 30°」と「強い傾き 60°」の2組で、各組の中央を「正面」、周囲を8方向の矢印にした一定の配置です。正面色は同じ色を両方の中央に表示し、透明色は先頭の独立したボタンです。ボタンの枠・角丸・影・選択表示は通常のDrawパレットと共通です。PCでは2組を並べて表示します。スマートフォンでは既存の左右操作列と中央の150px高のパレット領域を維持し、中央だけを法線色へ切り替えます。各方向のボタンに30°・60°を添え、入りきらない組は通常パレットと同じ横スクロールで選べます。操作領域やキャンバスを法線編集中だけ縮める変更は行いません。設定はレイヤー・フレームパネル上部から開きます。

法線色は方向を表す固定色です。通常の色パレットとは独立しており、法線レイヤーで色の追加・削除・調色はできません。選択レイヤーを切り替えても、通常の絵で選んでいた色は保たれます。法線レイヤーは1枚、通常レイヤーは法線を含めて8枚までです。通常の絵のレイヤーは最低1枚必要です。保存する法線レイヤーの不透明度は固定です。「編集画面の重ね表示の濃度」は0〜100%で変更でき、通常の絵を見ながら描けます。表示濃度は法線の画素・レイヤー不透明度・画像出力に反映しません。透明画素に法線を描くと、その画素は不透明になりますが、元絵の画素やアルファは変化しません。

## 絵から推定する

「凹凸」を開くと現在のコマを読み込みます。設定を変えると、推定したノーマルマップとライティング表示を更新します。パネルを開いた後に絵を変更した場合は「現在の絵を読み直す」で取り込みます。

| 設定 | 内容 |
| --- | --- |
| 高さの作り方 | 「輪郭から丸みをつける」は透明部分との境界から高さを推定。「明るさを高さとして使う」は色の明るさを高さとして扱う。 |
| 凹凸の強さ | 法線の傾きを調整。0〜8。 |
| 丸みの半径 | 境界から内側へ丸みをつける幅を調整。1〜32px。「輪郭」方式で使用。 |
| 高さを反転 | 高さの山と谷を入れ替える。 |
| 光の向き（左右・上下） | ライティング表示と照明済みPNGに反映。保存するノーマルマップPNGの画素には反映しない。 |
| 光のプリセット | 左上・右上・正面・左・右から選択し、角度を微調整できる。 |
| 艶・粗さ・環境光・光の色・強さ | 「艶と光を調整」で設定。照明表示と照明済みPNGに反映。 |
| 法線を描いていない部分にも光を当てる | 手描きモード用。既定OFFでは法線alpha=0の背景色をそのまま保持。ONでは正面の法線として照明する。 |
| Y方向 | OpenGL（Y+）またはDirectX（Y−）。緑チャンネルの向きを反転する。 |

この方法は現在のコマだけを対象にし、形状を絵のアルファや明るさから推定します。正確な立体形状を復元するものではありません。描いた方向色の法線も「凹凸」パネルで照明表示できます。

## 保存・データ

法線データは通常の色パレットから独立した専用レイヤーに保存します。通常の合成画像や通常のPNG書き出しには法線レイヤーを含めません。法線レイヤー選択中は、レイヤー一覧の順番にかかわらず通常の絵の上へ法線を重ねて表示します。アニメーション再生中も各コマの法線が最前面になります。法線を非表示にすると下の絵が見え、通常レイヤーの選択に戻すと通常の絵だけを表示します。この重ね表示は編集画面用で、保存する法線PNGには下敷きの絵を混ぜません。法線レイヤーは各コマに独立したセルを持ち、通常のUndo/Redo、コマ複製、リサイズの対象になります。

生成モードのPNGは入力と同じ幅・高さのRGBA8です。パレット画像にはせず、元絵のアルファを保持します。描画レイヤーモードでは法線レイヤーをPNGとして保存し、OpenGL／DirectXのY方向を選べます。いずれも画像サイズの拡大縮小はしません。

保存形式はPXD schema 5です。schema 5に未対応の旧アプリはこのデータを開けず、対応した新しいDrawが必要です。

## 照明設定とPNG保存

照明の向き・艶・粗さ・環境光・光色・強さ、背景の照明対象、マップ方式、作成方法、編集時の表示濃度を作品単位で保持します。保存先はPXDの `manifest.creationProject.normalMap`（schemaVersion 1）で、パレットや法線タイルとは別です。画面の再読み込み、出力画面からの戻り、別作品への切り替えで復元します。設定のない既存作品には既定値を使い、既存の法線レイヤーがあるときは手描きモードを選びます。

「元の絵・法線・照明」を並べて比較できます。「ノーマルマップPNGを保存」は方向色の画像、「照明済みPNGを保存」は現在の照明を反映した色画像です。どちらも元と同じサイズと透明度を使います。Drawの共通出力画面に渡した後、「PNGを保存」で端末へ保存します。出力画面で形式やサイズを変更しなければ、作成済みPNGをそのまま保存します。

保存不具合の原因は、直接ダウンロードリンクが共通出力処理に捕捉され、Blob URLの再取得へ回っていたことです。ローカル検証ではこの取得が失敗しました。修正後は作成済みBlobを直接渡し、設定を含む作品を保存してから出力へ進みます。「出力画面へ移りました」「ダウンロードを開始しました」を保存完了と混同しません。

## 推定の限界

「輪郭」方式は、完全透明な画素からの距離を8近傍のchamfer距離で近似します。正確なユーザー指定の高さや立体形状を復元するものではありません。画像全体が不透明で輪郭を検出できない場合は平面になります。画像端そのものを背景とはみなしません。

「明るさ」方式も、輝度を高さとして仮定する簡易推定です。色の明暗と実際の奥行きが一致しない絵では、意図した凹凸にならないことがあります。照明は法線を使った簡易的な拡散反射・鏡面反射の表示です。実際の物理的な材質を復元するものではありません。

OpenGL／DirectXの選択は緑チャンネルの符号を切り替えます。各ゲームエンジンのインポート設定、座標系、シェーダーでの見え方との適合は未検証です。たとえばGodotへ取り込んだ際の最終的な解釈も確認していません。

## 実装・検証の境界

**実装済み:** 現在のコマからの2方式の生成、強さ・半径・反転・照明・Y方向の設定、同寸法の法線PNGと照明済みPNG保存。専用法線レイヤー、17方向色と透明色、最前面への重ね表示と濃度調整、作品単位の設定保持。通常の合成画像・PNGには法線を混ぜません。

選択範囲の切り取り・貼り付け・移動では、法線を通常の色パレットの上限判定から分離しました。確定に失敗した場合は選択内容を保持します。25色の通常レイヤーがある64×64の検証作品で、法線1,024画素の切り取り・貼り付け・上へ4px移動・保存を確認し、保存後の全4,096セル、元の絵、通常パレットの一致を検証しました。

既存の道具・レイヤー・色調・選択操作・下部操作バーの配置を維持し、法線編集中は中央のパレット内容だけを切り替えます。文字アイコンは隠しラベルの影響を受けず中央に配置し、レイヤー追加・コマ追加・コマ複製は本体を中央、共通の＋を右上に統一しています。

**未実装:** 部位ごとの材質設定、照明後の元パレットへの再マッピング、全コマ一括の法線PNG保存、手描きの高さマップ、生成結果の17方向色への変換・専用レイヤーへの取り込み、MCPからの操作、回転・反転・対称描画に合わせた法線方向色の自動補正。通常／法線それぞれの色選択の記憶は同じ編集セッション内のみです。

**確認済み:** `node scripts/test-site.mjs` は3,600件PASS。最終のパネル位置修正後、関連25件もPASS（320px幅の上部バー回帰ケースを追加）。Chromeで専用レイヤー作成、描画、陰影表示、通常の絵への切り替え、Undo/Redo、保存・再読み込みによる照明設定の保持を確認。ダウンロードされた法線PNGと照明済みPNGの寸法・RGBA・透明度を検査しています。PCと390×844・320×568のブラウザー表示を確認し、320px幅でもキャンバス190px角、パレット150px高を維持します。

**未確認:** Safari・実機でのタッチ操作、各ゲームエンジンでの最終表示。ブラウザーの画面サイズ検証は実機検証の代わりにはなりません。
