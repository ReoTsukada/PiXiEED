# ホーム掲載の運用

この機能は未公開です。以下は配備・検証後の運用手順です。現在の本番設定、投稿、管理権限は変更していません。

## 投稿者から掲載まで

1. 投稿者がマイページの「ホームへの作品掲載」で、自分のアカウントまたは端末ゲストのチェックをONにして保存します。対象は所有者ごとに分かれ、初期値はOFFです。
2. 公開中の対応画像が、管理室の「ホーム掲載の確認」に入ります。許可のない作品、削除済み作品、対象外の形式は入りません。
3. 運営が画像・作品名・公開作者名を確認し、静止画像・掲載権利・内容の確認を選んで、その作品を掲載候補にします。一括自動承認はありません。
4. 同意・公開・画像と表示名の一致が保たれている作品から、ホームがランダムに選びます。承認後も、毎回すべての作品が表示されるわけではありません。

## 管理室

既存の `/admin/` から入ります。Google管理室へのログイン後、投稿審査で使用しているSupabase管理者セッションを共有します。画面上のメールアドレス比較だけでは審査権限を与えません。サーバーが毎回Auth.getUserで確認した非ゲスト管理者だけが操作できます。既存のserver app_metadata.roleまたは環境の管理者ID指定を用い、新しい管理者を自動追加しません。

「未確認」「承認済み」「見送り」で対象を整理し、必要に応じて次のページを開きます。画像は拡大表示しても切り抜かず、表示前にバイト数とSHA-256を照合します。読めない画像や差し替えられた画像は承認できません。承認時はサーバーでもサイズ・ハッシュ・PNG構造・非アニメーションを検査し、その後に最新の同意と投稿状態を再照合します。

「見送り」はホームの候補から外す操作です。元の投稿を削除したり、地図や作品一覧から非公開にするものではありません。本人の許可がOFF、投稿が非公開・削除済みなど対象外になっていても、過去の運営確認は取消用に表示します。対象外の画像は取得せず、承認はできません。一度見送った作品は、本人がONに戻しても自動では復活しません。公開投稿自体への対応が必要な場合は、別の投稿管理操作として判断します。

## 変更と失敗

- 投稿者がOFFにして保存すると、次回のホーム取得から対象外になります。すでに開かれている第三者の画面から画像を即時回収する機能ではありません。
- 画像、作品名、作者名などが変わった場合は、以前の確認を流用せず再確認します。
- ゲスト投稿の取り込み後は、新しい所有者が改めて同意します。以前のゲスト設定を自動コピーしません。
- 確認中に作品や同意が変わった場合は保存を拒否します。最新の一覧を読み直し、画像から再確認します。
- 通信切断などで保存結果が分からない場合は、同じ操作をすぐ繰り返さず一覧を読み直します。
- 管理者のログアウトやセッション変更では、確認画像と古い応答を残しません。

## 配備前の確認

既存ステージングと実認証を使った結合試験は、環境を確認したうえで行います。現時点では既存の独立ステージングは確認できず、手元のmigration履歴には初期baselineが欠けています。ミニschemaのSQL試験を、本番と同じDB構成の検証と読み替えないでください。

本番への配備、DB変更、環境の作成や課金、管理者権限の付与、実投稿の掲載承認は別途の承認が必要です。ログイン用パスワードやsecret/service keyを公開ファイルやブラウザーに置かないでください。
