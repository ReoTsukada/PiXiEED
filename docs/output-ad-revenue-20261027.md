# 既存 /output/ の広告売上 月3,000円を検証する改修

## 状態

この変更は検証用。新規広告枠は `enabled: false` で停止している。本番への反映・配信確認・月3,000円達成は未完了。既存の広告設定からユニットのIDと通常ディスプレイ広告としての設定は確認できたが、AdSense管理画面のサイト配信状態、Auto Ads、CMP、ページ別PV/RPM/収益は未確認。

## 対象と変更

- 対象は `https://pixieed.jp/output/` の公開案内。新サイトや機能の複製は作らない。
- `/output/work/` と変換エンジン、出力上限、無料保存、Offerwallや全体の広告設定は変更しない。
- タイトルと見出しを画像・音声の無料変換に統一。画像/音声/動画の目的別アンカー、再訪時の入口、公開URLコピーを追加する。
- 対応表の後に通常ディスプレイ広告1枠を準備。開始・保存操作と分離し、固定表示や自動更新をしない。
- `data/ordinary-ad-config.mjs` の既存responsive Display unitを参照する。独立した切替は `data/output-guide-ad-config.mjs`。
- HTTPS本番の公開案内のみが対象。workspace/start/iframe/ローカル/プレビュー/クエリ付きURLは拒否する。UTM付き流入も初期版では広告対象外になる点に注意。
- 最初の広告要求は表示領域の近くで一度だけ。未配信・広告ブロックでも変換リンクは利用可能。
- コピーは固定の公開URLだけ。素材・ファイル名・作品IDを扱わない。
- 既存のanalytics境界を利用し、開始リンクはselect_content、コピーはlink_copy。既存同意設定とイベント許可リストを変更しない。
- 月3,000円は広告売上の目標であり、利益保証・最低売上保証ではない。有料機能は追加せず、既存無料機能を維持する。

## 実行したテストと限界

- Node v22で `node --test tests/ads/output-guide-ad.test.mjs`：22件成功、0件失敗。
- ChromiumのオフラインDOM検査：36項目成功。320/390/1440pxのテスト用レイアウト、遅延開始、二重実行防止、再読込なし、コピー、workspace/iframe/クエリの除外、未配信とブロックを確認。
- オフライン検査の再実行：Python PlaywrightとChromiumがある環境で `python scripts/test-output-guide-isolated.py`。実広告へのリクエストやクリックは行わない。
- オフライン検査はモジュールの自動起動部分を除き、location/広告プロバイダー/クリップボードを注入した単体DOM試験。共通CSSは簡略化し、共通ヘッダー・全体解析・変換機能は試験していない。
- 実行環境で外部ブラウザ遷移が `ERR_BLOCKED_BY_ADMINISTRATOR`、コンテナの外部DNSも不可のため、全リポジトリ取得・全体npm test/build・本番ページのモジュール読込・実広告・実機は未検証。制限を解除/迂回していない。

## 公開と広告有効化の条件

1. 既存の開発環境で全体 `npm test`、`npm run build` と広告関連ブラウザ検査を実行する。
2. この変更の広告は現状OFFなので、既存の `/output/` 広告禁止テストは維持する。有効化する時は `scripts/adsense-browser-harness.mjs` 等の公開案内に関する期待値も更新する。workspace/startの既存制限は維持する。
3. AdSense管理画面でサイトの配信状態とポリシーセンターを確認し、既存ユニットが通常Displayであることを確認する。新しいページごとの審査が必須という意味ではない。
4. Auto Adsの対象・除外・プレビューを確認。SDK読込により、管理画面設定によっては自動広告も表示され得る。コードだけで広告が1枠になると断言しない。
5. 対象地域に適合したCMP/同意設定を確認する。新しいスクリプト自体はCMPではなく、今回管理画面の同意設定を検証できていない。
6. モバイル実機で操作を妨げず誤クリックを誘わないことを確認し、上記を満たした後だけ新規設定をtrueにする。
7. 実広告の自己クリック、テスト目的の連続アクセス、広告の自動再読込はしない。

## 月3,000円の計測

変更前30日と公開後30日について、AdSenseの同一期間・同一対象のページビュー、推定収益、ページRPMを比較する。Search Consoleでは公開案内のクリック、表示、検索語、登録状況を確認する。現時点ではどちらも未取得であり、目標到達の予測値を出さない。

`/output/` のURLチャネルが子ディレクトリを含む場合、`/output/work/` や `/output/start/` の収益をこの案内1ページの収益と混同しない。同一ユニットを使う別ページの売上も混ぜない。GA4の閲覧数をAdSenseのページRPMの分母に混ぜない。

必要PV = 3,000 / 実測ページRPM × 1,000。
仮にRPMが100/200/300/500円なら、月間30,000/15,000/10,000/6,000PV。これは実測値でも予測値でもない。月途中の換算値は見込みと表示し、収益調整後も複数期間で確認する。

## 追加改善の判断

- 検索表示が少ない：登録状況と実際の検索語を先に確認。タイトルだけ変えた薄いページを増やさない。
- 表示はあるがクリックされない：実際に対応する形式に限ってタイトル・説明を改善。
- 案内を経由しない利用者が多い：この1ページの広告売上は増えにくい。強制リダイレクト・待機・余計な画面遷移でPVを作らない。
- 広告表示が少ない：配信制限・端末・到達率を調べる。滞在時間を広告表示回数とみなさない。
- RPMが低い：広告枠を先に増やさず、配信状況と流入構成を確認。
