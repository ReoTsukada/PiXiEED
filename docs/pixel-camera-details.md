# 細部保護・孤立ノイズ・残像の改善

2026-09-24。ローカルのカメラに実装。公開・独自モデルの追加学習は行っていない。

後続の細線整形・線色による細さの表現は [pixel-camera-lines.md](pixel-camera-lines.md) に記録。

## 適用範囲

風景、動物、物、人物に同じ境界・色整理・時間安定化を適用する。人物だけに依存する変換方式にはしていない。既存のSlimSAMによる物体領域を維持し、人物の顔が検出されたときだけ目・眉・唇の保護を追加する。

- 同じ物体・同じ局所色領域の中で、周囲6セル以上に囲まれた弱い孤立点を既存パレットの色に揃える。異なる物体や局所領域を跨いで平均しない。8近傍につながる線、斜線、線の端、強いコントラストの点、顔パーツ保護セルは除去しない。
- 保護セルを含む小領域は近くの大領域へ統合しない。保護セルの明暗信号は平滑化せず、周囲の平滑化にも混ぜない。顔パーツを含む領域は色予算の配分で優先する。色の分位点は本来の画素数から求める。
- 隣接フレームの実画素RGBまたは物体IDが変わった場所と、その1セル周囲では過去の色・階調の保持を解除する。新しい階調が連続2回要求された場合にも古い階調を解除し、弱い変化が永久に保持されるのを避ける。
- 既存物体マスクの再利用では、縮小した平均値だけでなく元画像のRGB変化も確認する。平均では見落としていた細線移動でも古いマスクを破棄する。
- 局所色領域あたり最大3階調、全体48色、単色セル、出力alpha=255を維持する。RGBを平均した境界色や描画時のアンチエイリアスは追加しない。

## 顔パーツの検出

承認済みの顔パーツ検出には、Apache 2.0のMediaPipe FaceMesh系TFJSモデルを用いる。`@tensorflow-models/face-landmarks-detection` 1.0.6、`face-detection` 1.0.3、既存のローカルTensorFlow.js 4.22.0を使用。478点のAttention Mesh v1とBlazeFace Short Range v1を同梱した。新規資産は約3.75MB（既存TFJSを除く、ライセンスを含む）。出典・固定バージョン・サイズ・SHA-256は [PROVENANCE](../vendor/face-camera/PROVENANCE.md) に記録。

顔モデルは人の顔1つの位置を検出する補助処理で、人物の本人識別や、猫・建物・物の意味分類を行うものではない。風景や物の細線は共通の接続・コントラスト・領域処理で残す。これらを新しく学習した汎用物体パーツ認識AIとは呼ばない。

顔推論は描画とは別のWorkerで行い、最短400ms間隔、同時実行1件、古い要求を溜めない。初回準備中も通常プレビューは継続する。顔周辺が動いた場合、撮影から1.2秒を超えた場合、寸法・セッションが変わった場合には過去のランドマークを使わない。カメラ切替・撮り直しでは検出器内の前回位置もリセットする。画面端から少しはみ出す点は許可し、完全に画面外の顔は除外する。

モデルと実行コードは同一サイトのローカルファイルから読み込む。写真の外部推論サービスへの送信は追加していない。モデルの読み込み・推論が失敗しても共通変換を継続し、一時的な推論失敗は次のカメラセッションで再試行する。

## 検証

`node --test --test-reporter=spec tests/pixel-studio/*.test.mjs tests/globe/tool-shell.test.mjs` は125件成功。領域境界、細線、弱い孤立点、保護セル、静止RGB±2ノイズ、弱い境界の移動、2フレームでの階調解放、顔キャッシュ、古いセッションの遅着、失敗後の描画継続を含む。

実ブラウザーのModule Workerで公開サンプル4枚を変換。入力長辺512px、出力256px、物体AIマスクを与えない条件で共通変換と実際の顔モデルを確認した。人物で478点を検出し、猫・カップ・ロケットの写真では人物顔を検出しなかった。読み込み先は `http://127.0.0.1:4173` のみ。以下は1回の測定であり画質評価スコアではない。

| 写真 | 共通描画の初回 | 顔推論（準備後） | 保護セル | 整理した孤立点 | RGB±2で変わる出力セル率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| astronaut.png | 65.2ms | 104.4ms | 375 | 12 | 0.0763% |
| chelsea.png | 28.4ms | 83.1ms | 0 | 31 | 0.0827% |
| coffee.png | 16.2ms | 29.9ms | 0 | 31 | 0.0982% |
| rocket.jpg | 18.4ms | 34.6ms | 0 | 2 | 0.0046% |

4枚とも同一フレームの再入力は出力変化0。ノイズは決定的な-2〜2をRGB各チャンネルに加える検証で、実撮影動画の品質保証ではない。初回のモデル読み込み・GPU準備を含む人物推論は別測定で20.1秒かかった。環境・キャッシュ・GPUに依存する。

カメラ本体と同じ `preview-worker` → `face-worker` → 顔キャッシュ → 描画の実経路でも、静止人物サンプルで12フレーム・約2.05秒後に顔保護375セルが適用された。観測した推論は142ms、状態はready、エラーなし、リソース取得先はlocalhostのみ。初回の古い結果をそのまま使わず、新しい結果が届いた段階で適用されることを確認した。

実カメラ経路は顔が写っていない単色に近い入力で確認。通常プレビューは約9.6fps（61.4秒に592フレーム）。人物動画の推論込み速度とは区別する。505×962と390×844の画面で、画像の横・縦の拡大率が一致し、ページのはみ出しなし。狭い画面でも操作の重なりなし、通常画面の説明文追加なし、コンソールエラーなし。検証用の画面サイズ指定は解除し、一時比較ページは削除した。

13モジュールの構文チェックも成功。既存の物体AIは観測時processingであり、このターンでその認識精度や速度が改善したという判定はしていない。

## 限界

小さすぎる顔、顔の大きな動き、強い遮蔽、検出の遅延では顔の保護が使えない場合がある。その間は共通変換を表示する。強い1pxの点は目や星などの正当な細部かもしれないため残し、すべての1pxを消す処理にはしていない。全シーンのちらつき・残像の完全除去は保証しない。

今回の静止画試験はSlimSAMの境界検出精度を証明しない。物体の意味的な区切りは既存の認識マスクの精度に依存する。スマートフォン実機、長時間の発熱、複数人、あらゆる被写体での品質は未検証。

## 主な変更

- `motion-gate.mjs` / `mask-cache.mjs`: 動いた画素で過去の状態を解除。
- `pixel-clusters.mjs`: 同じ面の孤立点を整理。
- `material-groups.mjs` / `material-regions.mjs` / `three-tone-palette.mjs` / `object-renderer.mjs`: 細部保護と3階調の連携。
- `face-landmarker.mjs` / `face-features.mjs` / `face-cache.mjs` / `face-worker.mjs`: 端末内顔検出と有効な細部マスク。
- `preview-worker.mjs` / `app.mjs`: 非同期連携と検証用属性。操作ボタンや通常画面の説明文は増やしていない。
