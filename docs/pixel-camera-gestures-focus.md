# ドット絵カメラ：ダブルタップ色統合と長押しピント調整

2026-10-03。直前の通知ラベルによるプレビュー移動修正を保持したまま、プレビューの操作割り当てを変更した。

## 実装済み

- 同じ位置への300ms以内・48px以内のダブルタップで、2回目の位置からライブ色統合を開始する。従来の等倍リセットはカメラのダブルタップから外した。1×はズーム項目から選べる。
- 550msの長押しで、その位置のピント調整をカメラへ要求する。ライブ画面のみ。長押しで色統合や単タップの色再抽出を発火させない。
- ピンチ、10pxを超える移動、pointercancel、wheel操作は長押しとダブルタップ待ちを取り消す。単タップ・スワイプ・ピンチ・キーボードのMによる中央色統合を維持。
- ピント座標は表示画像から元映像の中央切り抜き・デジタルズームを逆算する。インカメラでは左右反転を考慮。
- カメラがfocusModeと位置指定を公開している場合だけ、既存制約を保持してfocusMode/pointsOfInterestを送る。single-shot優先、continuousが可能な場合はそれを使用する。非対応・失敗を通知する。
- 白いマーカーは要求を受け付けた位置を900ms表示する。実際にレンズが合焦したことを保証する表示ではない。カメラ停止・置き換え時の古い結果を破棄する。
- ピント要求中のズームとズーム制約適用中のピント要求は一時的に抑止し、制約の上書きを避ける。
- 操作案内・読み上げ文言を更新。CSS/preload/runtime/zoom/focusのキャッシュ版を `20261003-camera-focus-1` へ統一。

担当: 親エージェントが要件・差分レビューと受入、実装担当がapp/zoom/focus/UIと限定テスト、ブラウザー担当が隔離した合成カメラで検証。追加依存・コミット・プッシュ・本番公開なし。

## フル画面サイズの現状と今回の境界

比率メニューはappの `sharedFrameRatios()` から作り、`js/pixel-studio/framing.mjs` で画面比率に依存する `screen` を除外している。「画面に合わせる」は現メニューにない。固定比率のみになった共通キャンバス対応の状態を確認した。今回のラベル修正が削除したものではない。

「画面比率に合わせて撮影する選択肢の復活」か「固定比率の画像の表示のみ拡大」かを利用者へ確認した。このスライスでは比率を変更していない。撮影後の新しい色統合編集も追加していない。色統合は従来どおり撮影前のライブ画面が対象。

画像処理・撮影関数・5項目ナビゲーション・領域判定/追跡は維持。撮影関数、ナビHTML、領域判定と追跡モジュールのSHA-256は作業開始時と一致。
