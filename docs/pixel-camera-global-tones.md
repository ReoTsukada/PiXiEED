# 共通明度・局所色面・高彩度の配色

2026-09-24。ローカル実装。公開・コミット・依存追加なし。

後続の等価軽量化・同一入力のAI再利用・切替時の安定化は [24色カメラの安定化と軽量化](pixel-camera-stability-performance.md) を参照。

## 実装した状態

写真・動画の表示を見ながらのユーザー評価に基づき、**8段階＋選択ディザ**をカメラの既定にした。比較ページは4段階／8段階それぞれのディザ有無と、同じ原画・結果の白黒表示を持つ。カメラ本体の操作や設定項目は増やしていない。

- 原画を渡す物体AI、顔ランドマーク、細線抽出のモデル／処理は変更していない。色処理はその後段。
- 明度の段はグレー値 `24,56,88,128,168,192,216,240`。4段階は `24,88,168,240`。色付き画素を線形sRGBへ戻し、`Y=.2126R+.7152G+.0722B` から同じsRGBグレーへ戻す方法で評価する。任意の別のグレースケール変換との一致は保証しない。
- 素材の色は彩度を上げた**認識用**の色相24区分×彩度2区分で分類する。連結した局所領域を使い、強い明度境界で同系色の領域も分ける。元の物体IDを跨いで連結しない。
- 初回／タップで、実際の原画サンプルを元に最大12個の代表色を取得。大きな服だけで髪の暗色を失わないよう暗色・無彩色を確保しつつ、微小な高彩度アクセントだけで枠を使い切らない面積重みを使う。
- 固有色の出力彩度は線形RGBの無彩色軸からの色差を1.45倍にする。目標Yは動かさず、色域から出る場合のみ色差を縮める。無彩色候補は強調しない。深い暗部の共通青灰色は別扱いで、彩度を増やさない。
- 現行の全体パレット上限は**24色**（4段階／8段階共通）。最暗部・最明部は各1色を共有する。ユーザーの実画面評価「以前の色味が良い」を受け、全体の同系色3色・各明度3色の制限は解除した。近い色でも主色の差を優先して確保し、同じ明度に異なる色を置ける。各局所色面の出力は最大3色のまま。8段階は選択可能な明度段であり、すべての段を必ず埋める意味ではない。
- 全色のRGBは初回／タップ後に固定。サイズ変更・物体認識の更新・再描画で新しい色を生成しない。
- ディザは同じ素材の滑らかな明暗遷移だけに使う。平坦な面、顔パーツ、細線、物体境界、強い色境界では使わない。25/50/75%の2×2規則配置をキャンバス座標に固定し、明暗の混合比は線形Yで計算する。
- 静止した色面に後着AIが新しいIDを与えても、画素が95%以上変化せず既存の色の組が60%以上を占める場合は配色を引き継ぐ。動いた領域や色が変化した領域は再割当てする。

主な実装: `global-tones.mjs`, `global-palette.mjs`, `object-renderer.mjs`, `material-regions.mjs`, `material-groups.mjs`, `selective-dither.mjs`, `preview-worker.mjs`。比較操作は `media-test.mjs` と `camera-media-test.html`。

## 色数削減・ちらつき対策の追補

色一覧のRGBを固定しても、領域からどの色を選ぶかは別の処理。増えたちらつきについて、以下の切替点をコードと合成入力で確認した。増加分をすべて実動画から定量分離したものではない。

1. 各画素の明度とディザ被覆率が閾値を跨ぐと即時に色が変わる。固定のキャンバス座標は模様の位置だけを固定し、被覆率・使用範囲までは固定しない。
2. 局所領域の分割・統合や代表色の変化で、代表色候補と3色の組が再選択される。AIの領域IDの変化も影響していた。
3. 動き判定はノイズ画素の周囲も解除するため、疎な圧縮ノイズまで広範囲の色保持を解除していた。

対応は、代表色を切り替える改善幅、局所3色の明度誤差の改善幅、累積RGB変化に対するアンカーを設けること。明度は4以内の小さな揺れを保持し、アンカーを毎フレーム移動させないため累積変化で更新する。ディザ範囲の変更は安全な同素材の5×5領域に限り2フレーム確認し、新しい境界・細部・動きは待たずに保護する。連続した動きは隣接セルまで即時に解除するが、孤立ノイズは周囲全部を解除しない。AIのID変化だけではシーン切替とせず、元の画素変化から判断する。RGBを時間平均して残像を作る方法は使っていない。

色の共有は近い色相を優先し、別の色相のメインカラーを先に確保する。色相群は隣接する15度の認識区分を2つずつまとめた近似で、知覚的な同色を完全に判定するものではない。現行では同じ細かい色分類の候補を先に使い、その候補がない場合だけ近い色相群を参照する。24色上限により元写真のすべての色味を完全には維持できない。

色の進出・後退感は、色相だけでなく背景・明るさ・観察条件に依存する。赤／青から実際の前後関係を推定する処理には使わない。参考: [Thompson, May, Stone (1993), Chromostereopsis: a multicomponent depth effect?](https://www-users.york.ac.uk/~pt2/ThompsonMayStone1993.pdf)。この論文は青い影の一律適用や特定の混合率を最適と証明するものではない。主色の保持・明度段・境界・時間安定性を優先する。追加の青寄せは試作後に不採用とし、現行は元の色から明度を合わせる。無彩色と判定した候補は1.45倍の彩度強調から除く。

### 24色版（現行）の判断と実装

20色上限・色相群ごと最大3色の試作は、実写真では13〜14色まで減り、主色の表現が弱くなった。画面を見たユーザーの評価を優先し、24色へ変更した。まず原画の各細かい色分類の主色を確保し、その後に影・ハイライトの候補へ残りの枠を配る。同じ明度段への主色の衝突で、別の明度へ押し出す処理は外した。微妙に違う肌色・衣服色を残すため、候補を単に似た大分類へ統合しない。

追加した中間色の6%の青い色かぶりは**不採用として削除**した。中間色は元のRGBから同じ目標Yに調整する。最暗部の共有青灰色は以前からの仕様として保持。主色の彩度1.45倍はこの変更前から採用済みの設定で、無彩色候補は1倍。

色を増やしても時間安定性と動く輪郭の解放は維持する。大きな代表色変化では、旧3色の組を優先する判定も解除するよう修正した。比較ページのFPSは素材ロードや再生待ちを含めず、最初に処理結果を表示した時点から計測する。

人物写真128pxで24色、パレット自動変更0回、面ごとの最大3色を実画面で確認。

全体回帰: `node --test --test-reporter=spec tests/pixel-studio/*.test.mjs tests/globe/tool-shell.test.mjs` **212件成功**。24色上限、同明度の異なる暖色の保持、無彩色の色かぶり防止、局所3色、強い露出変化の追従、動く境界の残像解放を含む。

同じ24色で局所3色の組を保持する誤差幅を4・2・0で比較した。64×48・6色面・24フレームの合成ノイズ試験では、誤差幅2が4に対して±3ノイズの平均出力変化2.596%→2.237%、露出を徐々に20%上げた終点の新規描画との差8.561%→3.516%となったため**2を採用**。誤差幅0は±3ノイズ2.417%・終点差3.613%で、この例では2より良くなかった。全シーンに対する最適値の証明ではない。

この24色・誤差幅2と変更前の85色候補方式を比較すると、±3の平均出力変化7.693%→2.237%、±4は4.384%→2.041%。小さな±1/2はともに0%。動く矩形の2px外側の予期しない変化は0%。色数の変更も含む総合比較であり、動画全体のちらつき率や時間保持だけの効果とは呼ばない。

## 未実装・未検証の範囲

- 「髪」「衣服」を意味として識別する専用モデルは追加していない。色・連結・既存物体境界からの分離なので、同色で接触する髪と服を必ず分けられるわけではない。
- 4/8段階化そのものは形を復元しない。重要な細部が同じ明度に写る場合は残る。すべての照明・肌・髪色・被写体で最適という評価はしていない。
- パレットRGBが固定でも、物体や明度段の割当てによる動画の変化は残る。ちらつきゼロを保証しない。
- 物体AIの推論は数秒かかり、動きの速い動画ではキャッシュが不採用になる。先に軽い変換結果を表示し、妥当なAI結果だけを後続フレームへ反映する構造を保持した。
- 512pxは256pxより遅い。複数の画像領域、細線、色面を毎フレーム評価するコストがある。モバイル実機での速度・電池・熱は未検証。
