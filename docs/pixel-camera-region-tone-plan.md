# 後ろ姿・髪と服の混色・共通明度の修正案

2026-09-24。**後段の色処理を実装済み。** 実画像での確認後、ユーザーの「8段階はいい感じ」に合わせて既定を **8段階＋選択ディザ＋高彩度の固有色** に変更した。4段階も比較画面に残す。以下は当初案と判断経緯。実装の範囲と検証結果は [pixel-camera-global-tones.md](pixel-camera-global-tones.md) を参照。新しい部位識別モデルの追加は行っていない。

## 確認した症状と原因候補

比較ページの「街と歩行者」11秒を256×144・2倍表示で確認。配色取り直し前は物体AI未反映・顔0・ディザ0%でも、人物の背中と背景に細かい色面の分裂が見えた。画面から配色を取り直した後は48色・物体AI8領域・顔0・ディザ約0.51%。見た目は改善したが、服の面の細分化は残る。したがってディザだけを減らして解決する症状ではない。ユーザーが見た髪の特定画素が服の何色へ写されたかまでは、この確認では確定していない。

コード上の根拠:

- `fixed-palette.mjs:70–101`: 彩度を上げたRGBを色相7区分×彩度3区分で分類。低彩度はneutralに集める。髪/服という意味は識別しない。
- `fixed-palette.mjs:119–179`: 物体IDをパレットの集計キーに使わず、同じ色系統を画面全体で集計。その15/50/85%の明るさの実サンプルを3色として採用。面積が大きい服が分位点を支配すると、小さい髪の暗色が候補から落ち得る。
- `object-renderer.mjs:331–367`: 色系統だけで固定ランプを共有。同系統の髪と服に別々の基本色を割り当てる仕組みがない。
- `segmenter.mjs:27–37,323–403` / `segmentation-worker.mjs`: 現在は格子状の点から物体領域候補を得る。人物・髪・服という部位ラベルの契約はない。顔モデルも髪の領域を返さないため、顔が映らない後頭部に顔パーツの保護は期待できない。
- 現在の明るさは主に符号化済みRGBに係数を掛けたluma。色相の異なる影を厳密に同じグレースケールへ揃えるには、描画系全体で変換基準を定義する必要がある。

## 推奨する構成

原画 → 既存の物体/顔/細線認識 → 物体内の局所色面 → 全体の明度段階 → 固有色と共通影の割当 → 選択ディザ。

### 1. 認識の出力を保持し、その後ろに局所色面を作る

既存AIには原画を渡し続ける。顔座標・物体ID・前後関係・細線位置を、減色後の画像から再推定しない。顔モデルや物体モデルをまとめて交換する案にしない。

物体の内部を、連続した色・明度・境界から保守的に分ける。面積の大きさだけで離れた領域を統合せず、頭側の暗い面と胴体側の服の面が同じ色系統でも独立した基本色を持てるようにする。これは部位名がなくても使えるので、動物・植物・家具にも適用可能。

色や境界から分けられない場合に「画面の上だから髪」などと断定しない。境界が弱い場合は既存の物体領域と色を保つ。後頭部・帽子・毛皮などを意味的に分類する追加モデルは、この一般的な色面分離で不足することが実測された場合の別検討とする。依存追加はこの提案に含めない。

### 2. パレットの集計を局所領域で偏らせない

全体48色の枠と、領域あたり影・基本・明部の最大3色を保つ。画面の大きな面だけで3色を決めず、小さくても境界や形を表す暗色/明色を確保する。使用できる色の組は「局所領域の色の特徴と履歴」に結び付け、色相の粗い区分だけで髪と服に同じランプを強制しない。

共通の影色は意図的に共有してよい。一方、髪の基本色を服の基本色へ置き換えることは別の事象として検出する。初回/タップ時にこの配色を確定し、後からAI領域が増えた際には固定色の中で割り当てを行う。AI反映のたびに新しいRGBを生成しない。

### 3. 明度の基準を全体で4段階/8段階に揃える

ユーザーの「面をはっきり見せ、中間階調は必要な部分だけディザで補う」という優先順位を踏まえ、主候補を**全体4段階＋選択ディザ**に改める。8段階は細部・暗部の比較対象として残す。4段階だけで物体境界が正しくなるわけではないので、局所色面の分離と境界保護を前提とする。段数を動画の途中で自動切替しない。採用する段階の位置も初回/タップ時に固定する。

明度4段階は、画面全体を4色に限定するという意味ではない。同じ明度段に、肌・服・背景など異なる色相を置ける。各素材の最大3色は共通の4段階から選ぶ。

| 役割 | 色の扱い |
| --- | --- |
| 最も深い暗部 | 共通の暗色候補。境界が潰れる箇所は別段の確保を優先 |
| 影 | 青寄り/赤紫寄りなどの共通影候補を1〜2段に割当てる |
| 基本色 | 領域ごとの固有色を保持し、選んだ共通明度段へ合わせる |
| 明部 | 形を示す明るい面。領域ごとの色相と全体の明度基準を両立 |

黒い髪・黒い服は、暗いというだけで「影」と判定しない。領域内の相対的な陰影と素材の基本色を分ける。単一写真だけで照明と素材を完全分離できるとはせず、曖昧な領域は基本色を優先する。

### 4. 青・ピンクの影を同じ白黒の明るさへ合わせる

グレースケールの定義を一つに固定する。

1. sRGBの逆伝達関数で線形RGBへ戻す。
2. `Y = 0.2126 R + 0.7152 G + 0.0722 B` を計算し、全色共通の目標Yへ合わせる。
3. 色相は維持し、出力可能なsRGB範囲を超える場合は彩度を下げる。RGBを単純にクリップして明度をずらさない。
4. 8bit化した後も同じ変換で検査し、同じ段に属する色のグレースケール差を原則1/255以内にする。これは実装時の受入目標であり、現状の達成値ではない。

段階間隔は見やすいニュートラルグレーの階段として設計し、そのグレーから目標Yを求める。線形Yを等間隔に並べるだけでは見た目の等間隔にはならない。色合わせにはOklab/OKLCHを補助として利用できるが、OklabのLとYを同じ量として扱わない。どのグレースケール変換でも完全一致する、という約束にはしない。

### 5. 面の粒と動画の変化を抑える

色面の内部だけで低コントラストの細分化・1pxノイズを整理する。顔パーツ・髪の外形・服の襟/縫い目・細線・オブジェクト境界は保護し、細部を丸ごと平滑化しない。ディザは現在の遷移帯のみの方式を維持する。

明度段の境で微小ノイズによる往復を抑え、動きがあるセルは現在フレームへ戻す。AI結果の採用時も、変わらない領域の基本色/明度履歴まで一括解除しない。新しい境界の周辺だけ更新できるかを、動体跡を残さない条件と合わせて検証する。

## 検証と適用の順序

1. **診断:** 同じ後ろ姿フレームに原画/物体境界/色面/色の候補/最終結果を重ね、髪と服が混ざる段階を特定。テスト画面だけで扱い、カメラの設定を増やさない。
2. **局所の配色修正:** 髪と服を粗い色相だけでまとめない処理を先に独立評価。
3. **共通明度:** 4段階＋選択ディザを主候補に、4段階のみ・8段階のみ・8段階＋選択ディザも同じ写真で比較。入力・解像度・既存識別結果・ディザ許可領域・座標位相を揃え、カラーと指定のグレースケールをセットで判定。
4. **共通影色:** 明度段が安定してから青/赤紫の影を比較し、輪郭と固有色が崩れない候補を採用。
5. **動画:** 固定パレット、段階往復、AI採用時の切替、横切る物体の残像を確認。

受入条件:

- 同じ原画に対する既存の物体マスク・顔座標・細線検出の結果を変えない。追加処理は後段に隔離。
- 黒髪/茶髪/明るい髪、同系色の服、帽子、後ろ姿/横顔/正面、逆光/暗部で比較。髪へ服の基本色を借用しない。
- 猫のひげ、葉の枝、カップの取っ手、ロケットと背景の線が消えない。
- 共通影の色相を変えても規定のグレースケール段がずれない。重要な境界は4段階で潰れる場合があるので、8段階案との比較を必須とする。
- 3色/領域、48色/画面、RGBA不透明、整数ピクセル、固定ディザ位相、タップ以外のパレット不変を維持。
- 同一静止入力で、遅着AIの不採用だけを理由に全体の色割当が変わらない。AI採用で実際に境界が変わる場合の出力差は別に記録。

## 根拠資料

- [W3C — Relative luminanceの定義](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum): 線形化したsRGBからのY。ここでは文字コントラストの適合判定ではなく、色計算の定義だけを参照。
- [Björn Ottosson — Oklab原文](https://bottosson.github.io/posts/oklab/): 色相・彩度と知覚明度を扱うための色空間。Lとlinear-Yの区別、色域制約を踏まえた色合わせに使用を検討。
- [Cure — Pixel Art Tutorial](https://pixeljoint.com/forum/forum_posts.asp?TID=11299): 色面・クラスタ・色のランプ・hue shiftingの技法。画素ノイズを増やさず形を伝えるための参考。

資料から設計した実装案であり、同じ処理の品質が研究で保証されたという意味ではない。

## 4段階＋ディザ案の補足（追加回答）

4つの明度を土台に、隣り合う明度の25/50/75%配置を加えると、設計上は4＋3組×3＝13種類の局所平均輝度を表現できる。これは実色が13色になるという意味ではない。平均は線形輝度Yで計算する。13段階が知覚的に等間隔・滑らかに見える保証もない。実際の画素は4段階を保ち、小さな領域や拡大時にはパターンとして見える。

面の中央は単色、なだらかな陰影の接続だけをパターン化し、輪郭・目・髪の外形・細線には使わない。4段階化で失われた細部をディザだけで復元しようとしない。現在の実装は25/50/75%の固定パターンと適用領域の制限までで、全体共通4段階との統合・4条件の実画像比較はまだ実施していない。

調査済みの根拠はCureの色面/過剰ディザ/4色パレット解説、Mark Ferrariの波面・泡・雨雪での使い分け、Pangらの構造と階調を両方評価するハーフトーン研究。手描きの使い分けや構造保護の原則を参照したもので、構造保持型論文の最適化手法を実装済みとするものではない。
