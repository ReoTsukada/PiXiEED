# 固定配色と、面・陰影・細部を分けるディザ

2026-09-24。対象はローカルのピクセルカメラと `camera-media-test.html`。公開・依存追加・追加学習は行っていない。

## 参考資料から採用した判断

- [Cure / The Pixel Art Tutorial](https://pixeljoint.com/forum/forum_posts.asp?TID=11299): 色面の大部分をディザで埋めると不要な質感になる。色面の端の移行に絞り、色間のコントラストとピクセルのまとまりを重視する。50%以外のパターンは目立ちやすい。この実装では広い単色面を優先し、遷移帯以外をディザ化しない。
- [Pedro Medeiros / Pixel Art Fundamentals 1](https://www.patreon.com/saint11/posts/pixel-art-1-6971422): 大きなフラット色面と、細部を抑えた内部・読みやすいシルエットを使う。作者自身のスタイルであり普遍的な正解とはしていない。今回も作品を模写・学習データ化せず、描画判断を参考にした。
- [Mark Ferrari本人のQ&A](https://www.effectgames.com/effect/article-Q_A_with_Mark_J_Ferrari.html): 滑らかな波面には規則的パターン、泡には局所的な拡散、雨や雪の帯にはディザなしという使い分け。カメラの動画ではキャンバス固定という要件を優先し、ランダムな拡散は採用していない。
- [Pangほか / Structure-Aware Halftoning, SIGGRAPH 2008](https://ttwong12.github.io/papers/structurehalftone/structurehalftone.html): 明るさだけでなく構造の類似も評価する研究。構造保護という設計判断を参考にした。論文の最適化器・blue-noise方式を実装したものでも、同論文の評価結果を再現したものでもない。

これらは手描きの作例・技法解説・ハーフトーン研究であり、このカメラに対する閾値の最適性を保証しない。以下の数値は今回の実装上の選択。参照記事の本文を確認したが、外部配信の一部作例画像は取得できなかったため全作品を視覚評価したとはしない。

## 動作

### 配色

初回の使用色を最大48色で固定。色分類の分析だけ彩度を1.25倍にし、出力には実際に採ったRGBを使用する。同一色系統は影・基本色・明部の最大3色。物体の境界は分離しつつ、同じ色系統のランプは複数物体で共有する。肌・髪・服が意味的に必ず1系統に収まる保証はない。

場面変化、後から到着したAIマスク、出力サイズ、比率変更でパレットを取り直さない。カメラの再開・切り替え、画面タップで新しい画面の配色に更新する。タップは配色再認識であり、レンズの光学フォーカス制御ではない。比較ページでは素材の変更でも更新する。

映像準備中のRGBがすべて0の初期フレームは保留し、黒一色のパレットを固定しない。固定後の真っ黒な入力は普通に描画して前画像を残さない。RGBが少しでも非ゼロなら暗い画像でも処理する。完全黒から始まる入力では、最初の非ゼロフレームが配色取得の起点になる。

### 面・遷移・細部

- **面:** 通常は3段階の色面で表示。フラットな中間色に粒を足さない。
- **陰影の移り変わり:** 同じ物体・色系統内で、5×5の近傍が滑らかな明度勾配になっているところだけ候補にする。傾きと平面からの誤差を使い、細かいテクスチャをグラデーションと誤認しにくくする。孤立した候補も除く。
- **細部・境界:** 既存の顔パーツ、細線、強い境界を保護。保護セルや別の色領域を含む5×5近傍はディザ対象外。小さいパーツを点で穴だらけにしない。
- **パターン:** 隣り合う2色間の中央32〜68%の範囲に限定。25/50/75%の規則的な2×2配置を使い、両端は単色にする。50%は縦横の隣が必ず逆色になる市松模様。1/16の点や15/16の穴で細かな階調を稼ぐ方式は通常カメラで使わない。
- **濃淡の強さ:** 明度差6未満または100超の組はディザにしない。差が大きい組の粗い市松を避ける。
- **動画:** 模様は出力キャンバスの整数座標に固定。時間・乱数による位相変更なし。微小な入力変動には明度の保持を使うが、実際の動きには現在フレームの値へ戻す。
- **単独ノイズ:** 単色面の孤立した低コントラスト点には従来の限定的なクラスター清掃を適用。意図したディザと顔パーツ・細線・境界は保護する。RGBAの色補間は行わずalpha255。

物体/色領域と局所勾配での使い分けであり、布・金属・皮膚などの材質を新しい学習モデルで識別する実装ではない。

## 検証

実測結果は追記欄に記載。以前の配色自動更新方式との比較元は [既存素材テスト](pixel-camera-media-tests.md)。以前の試験結果と今回の固定配色・選択ディザの試験を混同しない。

合成テストでは、フラット面にディザなし、滑らかな陰影の一部だけにディザあり、境界/細部の保護、25/50/75%の密度、50%の完全な交互配置、座標周期、同じ入力の決定性、固定パレット、動体跡の除去を確認する。

実ブラウザーはこのMacでの写真4枚と実写動画2本。動画の表示FPSと物体認識FPSは別。認識には数秒かかり、動く映像に古いマスクを使わない処理のため、再生中は物体認識の結果が反映できない場面がある。配色固定だけで、動く画像のちらつきや全パーツの認識が完全に解決したとはしない。スマートフォン実機、長時間の発熱、高速運動、全ての被写体は未検証。

人物は先の全体的なディザで51,726/65,536セル（約78.93%）が対象だったが、選択ディザでは1,240セル（1.89%）。顔の保護領域・境界・服の面がディザで埋まらなくなった。写真4枚の最終色数は順に48・29・32・48。全体48色以下、局所ランプ3色以下、alpha255を維持。

静止入力の最終出力差は人物0.00305%、猫・カップ・風景・街は0%。初期AI反映や顔保護の更新による出力差が残るため、使用色変更0回と出力ピクセル変化0%は区別する。動いている動画のちらつきを定量保証する値ではない。

街の停止画面で画面操作によりパレットepochとrevisionが5→6へ進み、実際のRGBパレットも変更された。その後に128px・9:16へ変更しても同じRGBとrevisionを保持し、出力は72×128。AI認識時間は写真約5.5〜6.4秒、街約6.2秒。街の再生中は共通変換が中心、停止後に物体認識反映を確認。

`node --test --test-reporter=spec tests/pixel-studio/*.test.mjs tests/globe/tool-shell.test.mjs` は175件成功。カメラ・比較画面・ワーカーの構文検査も成功。独立した静的レビューでも重大な不具合の指摘なし。ブラウザー検証を合成テストだけで代替していない。

葉の動画は39.18秒全編と停止後を613フレーム/69.22秒観測（表示8.86fps、描画平均23.82ms、最終ディザ0.04%、48色、自動配色変更0回、非不透明フレーム0）。停止後にAIが8領域を認識し、約5.31秒。最終同一入力差は0%だが、processing→processingの1回に12.226%の割当て変更を確認し、認識キャッシュ破棄時の描画履歴リセットを追加調査した。これは配色のRGB変更ではない。初回走行は31.3秒時点まで確認後に比較タブが空になったため、ページを復帰して全編を再走行した。タブが空になった原因は特定できていない。

葉の最終画面をタップ操作で再認識するとepoch/revisionが2→3、48色→46色へ更新。512px出力へ変更してもRGBパレットとrevisionを維持し、512×288を生成。描画平均76.21ms、ディザ範囲3.40%。390×844の表示でもページ幅390、選択欄の左右範囲20〜191/199〜370で重なりなし。検証後は通常の画面幅・256pxへ戻した。

実カメラでも自動起動し、`selective-canvas-2x2`、paletteLocked=trueを確認。画面クリック後はepoch/revisionが1→2へ更新してフレームの表示が継続。追加の可視ボタン/設定なし。カメラと再走行の比較ページのconsole error/warnは観測時0。以前撮影済みの別タブは再読み込みせず保持した。

### 遅延マスクを棄却した場合のリセット修正

最終版では、古いマスクが `changed-region` などとして却下されたという理由だけでrendererの全履歴を消す処理を削除。実際のサイズ・セッション・配色切替は引き続きリセットし、画像変化と物体境界変化はrendererが判定する。遅延マスクなしの連続描画と、遅延マスクを拒否した描画の出力一致を回帰テストで確認。最終176件成功。

修正後の葉動画を先頭から末尾まで再確認。443フレーム時点の静止入力差は最大0%。その後、実際にAI結果を採用したprocessing→readyのフレーム456で12.2938%の出力差があり、最終1220フレーム/135.48秒時点は0%。パレット自動変更は0回。この修正は不採用結果による余分なリセットを直したもので、AI採用時の割当て変化まで解決したものではない。後続の局所色面・明度の提案は [修正案](pixel-camera-region-tone-plan.md) に記録した。
