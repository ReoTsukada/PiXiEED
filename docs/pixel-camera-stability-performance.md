# 24色カメラの安定化と軽量化

2026-09-24。ローカル実装。コミット・公開・依存追加・AIモデル変更なし。

## 変更前に確認した現状と問題

比較画面の人物写真で128pxは平均27.28ms／9.82fps、512pxは平均274.81ms／3.40fps。物体AIの推論は約6.6〜7.3秒だった。表示は最大約10fpsを目指す既存の直列フレーム処理で、未処理の映像を蓄積する構造ではない。

- 固定24色であっても、局所の3色の組を評価するたびに同じ色の明度を再計算し、一時配列を作っていた。細線検出も全画素の方向探索や前フレーム比較で多くの小配列を作っていた。
- 同一静止画・動画停止中にも、物体認識は処理完了ごと、顔認識は400msごとに再実行されていた。物体なし／顔なしも再実行対象だった。
- セッション切替時、旧AI処理の中断完了前に新しい要求を送り、拒否と再送を繰り返す経路があった。拒否時に現在の描画履歴もリセットされていた。

実装前にこれらの問題と「描画の等価な計算削減→厳密同一入力の再認識抑止→切替時の再送制御」の順序をユーザーに共有した。画質の設定やAI精度を落として速度を得る方法は採用していない。

## 実装

- `global-tones.mjs`: 整数RGBの256通りを64bitの変換表で参照する。小数は従来の式を使い、全整数・小数・負のゼロの値を保持する。追加の表は約2KB。
- `object-renderer.mjs`: パレット内の明度と色の組の情報を同一処理内で使い回し、候補評価の一時配列を除去する。比較順・誤差の加算順・閾値を維持。
- `thin-lines.mjs`: 方向探索・時間比較の一時配列をスカラーへ変更。線の位置・太さ判定・色の計算を維持。
- `mask-cache.mjs` / `face-cache.mjs`: `reuseExactFrame` をプレビューでのみ有効化。保存した入力と現在の**全画素RGBが完全一致**する場合だけ期限を超えて結果を再利用する。元の `capturedAt` と表示する推論年齢は更新しない。差が1でもあれば、元の取得時刻からの期限と既存の変化検査へ戻る。無物体・顔なしも完全一致時だけ再利用する。顔は既存の顔領域外も比較し、新しい顔の出現を再処理対象にする。
- `preview-worker.mjs` / `segmentation-worker.mjs`: busy応答の「終了待ちジョブID」を保持し、同じジョブの終了通知と現在のセッションの両方が一致するまで再送しない。描画履歴は保ち、空いた後にその時点の最新画像を送る。待機フレームのキューは増やさない。
- 比較ページの既存診断JSONにAI開始回数・厳密再利用・終了待ち状態を追加した。ユーザー操作は増やしていない。

24色、8段階、局所最大3色、画素の境界、細線保護、選択ディザ、撮影画像のサイズ、表示ループの上限は維持した。

## 検証

`node --test --test-reporter=spec tests/pixel-studio/*.test.mjs tests/globe/tool-shell.test.mjs` は **221件成功**。変更したJavaScriptの構文チェックも成功。完全一致と小差分の区別、期限、空結果、顔領域外の変化、セッション／寸法変更、busy中の履歴保持、誤ったidle通知の無視、終了後の最新画像送信を含む。モデルの実推論はこれらのテストでは代替している。

変更前のソースを一時フォルダーに保存し、人物・カップ・猫・ロケットの既存写真を128／256／512pxで比較した。静止・±3ノイズ・後着の合成物体境界・露出変化を含む**108フレームでRGB、パレット、出力ラベル、インデックス、統計が厳密一致**。この等価性比較は描画器の比較であり、AIの再実行タイミングまで同じにするものではない。

同じ比較の512px・各9フレームの平均処理時間:

| 写真 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 人物 | 367.86ms | 263.41ms |
| カップ | 256.50ms | 189.55ms |
| 猫 | 226.32ms | 166.91ms |
| ロケット | 305.04ms | 202.28ms |

全12素材・サイズの平均では約11〜34%短縮。実行順は交互にし、同じ入力を双方に渡した。少数フレームの単一端末の結果であり、全端末・すべての個別フレームでの短縮を保証しない。

実ブラウザーでは人物512pxを232フレーム表示し、平均154.38ms／5.74fps、24色、配色自動変更0回を確認した。40秒間の認識開始は物体・顔各1回で、その後の同一画像の差は0%。撮影時期・AIの反映状態・パレット取得条件に差があるため、上の変更前ブラウザー値との厳密な速度比較とは区別する。128pxは約9.7fpsで、表示上限は引き続き約10fps。

街の動画は0〜15.467秒を全編再生。停止後に物体AI反映、24色・局所最大3色、配色変更0回、最終同一入力差0%。361フレーム観測、平均16.11ms／9.48fps（停止後を含む）。後着AI反映時の同一入力の最大差2.58247%は残った。推論年齢21秒を超えても停止入力の再認識は増えず、再生を再開すると再利用が解除され新しい推論が始まった。

葉の動画も0〜39.18秒を全編再生。867フレーム観測、平均15.21ms／9.26fps（停止後を含む）、24色・配色変更0回。後着AI反映時の最大同一入力差4.04731%、最終差0%。停止後は推論年齢45秒を超えても同一RGBの結果を再利用した。両動画の静止入力差は、再生中の動きを補正したちらつき率とは異なる。

カメラ本体は一時タブで自動起動を確認した。`mode=live`、中央撮影ボタン有効、256px／8段階、初回プレビュー871ms、約11.2秒で101フレーム、直近描画15ms。観測シーンのパレットは5色だったため、複雑な被写体の速度の証明にはしない。保存・投稿は実行せず、確認後にカメラを閉じた。カメラと比較ページのコンソール警告・エラー0件。最終比較画面は人物・128px・8段階＋ディザに戻した。

## 残る範囲

- 初回の物体AI推論や動いた画像の認識には引き続き秒単位の時間がかかる。モデルの量子化や入力削減はしていない。
- 完全一致の再利用は静止写真・停止動画に特に有効。センサーノイズがあるライブ映像では常に成立するわけではなく、その場合は従来の有効性検査を保つ。
- 再認識の結果が初めて反映される瞬間の画素変化は残る。動いている映像の全ちらつきを動き補正して定量分離した検証ではない。
- 512pxで10fpsを達成したという結果ではない。スマートフォン実機の発熱・電池・長時間メモリーは未検証。
