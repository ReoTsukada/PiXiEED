# カメラのタップ操作と長押し色変更

## 変更の範囲

2026年10月4日。ユーザーの「色合い」は従来のタップで表示色を選び直す動作を指すと確認した。自動露出や色温度の新しい処理は追加せず、既存配色処理を保つ。

UI担当はカメラ本体・共通ジェスチャー・HTML・関連単体テスト、ブラウザー担当は現行ジェスチャーハーネス、親はヘルプ・読み込み版番号・この記録と受入を所有する。新規ネイティブ提案書と他の制作ツールは変更しない。実装時点ではコミット・プッシュを行っていなかった。

## 実装した動作

| 操作 | 動作 |
| --- | --- |
| タップ | 指を離した時に既存の配色選び直しを実行し、対応カメラへ同じ位置のピント要求を独立して送る。 |
| 長押し | 約550msで押した位置のライブ色統合を開く。指を離してもタップ・ピント要求を発火させない。 |
| 素早い連続タップ | それぞれ通常のタップとして処理し、色統合や倍率リセットを行わない。 |
| シャッター長押し | 既存のGIF撮影を維持する。 |

配色処理をピント要求より先に実行するため、フォーカス非対応・要求拒否・処理中でも配色選び直しを止めない。フォーカス結果の通知はタップ時には静かに扱い、非対応の案内で色の完了表示を覆わない。対応時のマーカーは「要求済み」を表し、光学的な合焦を保証するものではない。

カメラではダブルタップ判定を無効にして300msの判定待ちを除去した。共通ジェスチャーの既定動作は保ち、カメラだけで即時タップを選ぶ。ドラッグ、スワイプ、ピンチ、キャンセル、長押し完了はタップと分離する。既存の設定パネルを閉じた直後の600ms保護と、固定配色では色を選び直さない仕様は維持した。

プレビューの切り取り、デジタルズーム、前面カメラの座標変換は既存のフォーカス処理を使う。ヒント・読み上げ説明・共通使い方パネルを新操作に合わせ、カメラ入口・ズームモジュール・ヘルプの読み込み版を `20261004-camera-tap-focus-1` に揃えた。

## 検証

- `node --test tests/pixel-lens/focus.test.mjs tests/pixel-lens/zoom-gestures.test.mjs tests/pixel-lens/camera-page.test.mjs` は21件合格。
- `node --test tests/site/tool-help-data.test.mjs tests/site/tool-help.test.mjs` は9件合格。
- `node scripts/camera-gesture-browser-harness.mjs` は390×844・844×390の隔離Chromiumで25項目合格、ページ実行エラー0。合成Canvas映像と模擬カメラトラックを使用し、利用中のユーザータブは操作していない。
- タップの配色epoch更新は1→2、操作から観測まで5ms・92ms。対応時の位置要求は期待座標との差0.002未満。非対応・要求拒否でもepochが増え、色統合は開かない。
- 連続タップはepochが2→4となり2倍ズームを維持。マウス・CDPタッチの長押しは開始セル(66,62)と一致し、指を離しても配色epoch・フォーカス要求を増やさない。ドラッグ・ピンチ・pointercancelも誤発火しない。
- 最終記録は `/tmp/pixieed-camera-gestures-20261004/gesture-results.json` と同じフォルダーの成功画面画像。検査対象6ファイルのハッシュは現在のソースと一致し、親は縦・横のタップ、長押し、非対応状態の画像を確認した。
- 構文確認と差分の空白検査は合格。

途中の検査失敗は、設定終了直後の保護時間中にタップしたこと、閉じて非表示の設定に表示待ちを要求したこと、ライブ追跡で更新された起点を開始座標と比較したことによる。ハーネスの待機条件と最初の起点記録を修正した。最終結果は上記JSONで、同じフォルダーに残る古いfailure記録とは分けて扱う。
