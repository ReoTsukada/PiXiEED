# Pixel Studio — 調査・実装・品質の境界
更新: 2026-09-23

## 目標
写真を粗く見せるだけでなく、色面がまとまったゲーム素材・イラスト寄りのドット絵にする。写真を外部へ送らない。端末内AIを試す。自動変換がすべての場面で手描き作品を超える、という主張はしない。

## 調査結果
| 方式・参考 | 実際に行うこと | 採用判断 |
|---|---|---|
| [SLK_img2pixel](https://github.com/Captain4LK/SoftLK-tools/tree/master/SLK_img2pixel) | サンプリング、パレット生成、色距離、ディザ、シャープなどを組み合わせる。CC0（外部依存を除く）。 | 色数・サイズ・輪郭を別に調整する設計を参考にする。写真の形を描き直すAIではない。 |
| [Pixel It](https://github.com/giventofly/pixelit) | ブラウザー内で縮小とRGBパレットへの色割当を行う。MIT。 | 小さく実装できるが、これだけでは今回の目標に不足。 |
| [pngquant / libimagequant](https://pngquant.org/) | パレットの選択と割当、ディザを改善する。 | 減色は重要な仕上げだが、意味のある形を生成する工程ではない。ライブラリーは追加せず独立実装。 |
| [Pixelated Image Abstraction, 2012](https://gfx.cs.princeton.edu/gfx/pubs/Gerstner_2012_PIA/Gerstner_2012_PIA_full.pdf) | 出力セルと限られた色を共同で最適化する。 | 形とパレットを同時に考える根拠。論文の再現実装とは呼ばない。 |
| [Content-Adaptive Image Downscaling, 2013](https://johanneskopf.de/publications/downscaling/) | 画像内容に応じて縮小時のサンプル配置を変える。 | 細部保持を参考にする。ライブ動画の安定性は別途必要。 |
| [PixelOE](https://github.com/KohakuBlueleaf/PixelOE) | 高コントラストの輪郭を先に広げ、細部を残して縮小する。Apache 2.0。 | 非AIの処理。輪郭を平均化しない設計の参考。ソースを移植したものではない。 |
| [Make Your Own Sprites, 2022](https://github.com/WuZongWei6/Pixelization) | 学習モデルでセル構造とエイリアスを扱う。 | 公式コード・重みは非商用の科学研究用途に制限。今回の製品には取り込まない。 |
| [SD-πXL, 2024](https://igl.ethz.ch/projects/sd-pixl/) | 拡散モデルを利用して低解像度・限定色の絵を最適化する。 | 再描画という目標に近いが、論文条件で1画像約1.5〜2.5時間。端末内カメラへの直接採用を見送る。 |
| [Magenta ブラウザー内画風転写](https://magenta.tensorflow.org/blog/2018/12/20/style-transfer-js/) | 写真と見本の絵柄を、学習済みの予測器・変換器で結び付ける。 | 端末内AIの試作として採用。任意画風転写であり、ドット絵専用モデルでも独自学習モデルでもない。 |
| [OKLab](https://bottosson.github.io/posts/oklab/) | 明度や色味の知覚差を扱いやすい色空間。 | RGB値の単純距離に代えて、色の選択・割当へ利用。 |

公式ツールの機能記述、公開コード、論文を区別して調べた。公開作品を無断で学習データに収集することは行っていない。全既存アプリとの優劣比較も行っていない。

## 新しい実装
- 撮影または写真取込 → 元画像を保持 → 任意の端末内AI → ドット格子への変換 → 減色 → PNG。
- AIは明示的に適用する。見本と強さを変えて試し、元の画像処理版へ戻せる。
- AIは撮影後の静止画向け。撮影前は通常のカメラ映像。現バージョンはライブAIカメラではない。
- 出力セルの近傍を4つの領域として比較し、色のばらつきと中心色への一致度で面を選ぶ。その面の実画素を代表にするため、髪と背景を混ぜた中間色を作らない。
- パレットはOKLab上でエッジを考慮してクラスタリングし、実際の代表色を使う。小さな色面の修正は色差が小さい場所だけに限定する。
- 輪郭は境界の暗い側だけに、同じパレットの色で付ける。全輪郭を黒線で囲う処理ではない。
- 高精細ディザは固定したBayer格子を使う。隣接色の距離順が変わっても模様の位相を反転させない。
- 固定パレットでも指定色数の上限を守る。写真内の頻度から使用色を選ぶ。
- 拡大表示と拡大PNGは補間しない。PNGはRGBA形式で、使うRGB色数を制限する。インデックスPNG形式という意味ではない。
- 写真用途として透明部分は白へ合成する。透過スプライトの保持・背景自動除去は未実装。

## AIと配布資産
既存の学習済みモデルと実行ライブラリーを自己ホストする。読込み後の推論に外部API・APIキーは使わない。配布元、固定版、ハッシュ、ライセンスは `assets/pixel-studio/models/` と `vendor/pixel-studio/` の資料を参照。

`assets/pixel-studio/style-reference.png` は本タスクで新規生成した画風見本。生成した絵の格子精度や色数を保証するものではない。写真からの変換成果物ではなく、AIへ渡す画風条件である。元画像に応じて形・色が変わり過ぎる場合があるため、初期状態ではAIを自動適用しない。

## 廃止したもの
`js/pixel-camera/`、`tests/pixel-camera/`、旧カメラ専用スクリプト5本、旧設計・採点文書を撤去。旧評価スコアを新方式の品質根拠にしない。公開写真4点と出典READMEは `assets/pixel-studio/samples/` へ移し、ハッシュ一致を確認した。

`/pixel-camera.html` と地球側の `PiXiEED:camera-handoff:v1` は維持する。「地球に置く」は端末内で投稿画面へ渡す操作で、投稿確定とは別。

## 検証の考え方
古い独自採点を廃止し、色数上限・境界色・決定性・入力保護などの小さい機能テストと、人物・動物・風景・静物の実画像目視を使う。ブラウザー・端末・AIありなしの結果を分けて記録する。デスクトップで動作しても、すべてのスマートフォンで同じ速度や品質を保証しない。

最終の確認結果は `docs/pixel-studio-validation.md` に記録する。
