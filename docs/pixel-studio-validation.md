- 同梱資産: 固定TFJS 4.22.0 とモデル資産の11エントリーについてサイズ・SHA-256・重み参照を照合済み。

## 実ブラウザーで確認したこと
Codex内ブラウザー、ローカル静的サーバー。写真は同梱の公開サンプルのみ。
- 人物、風景、動物、静物を読み込み、通常変換と端末内AIを実行。
- AI中間画像 → 128px / 24色の仕上げ。元写真、AI中間、仕上がりの切替とAI取消を確認。
- AI25%と55%を静物で比較。既定25%、AIは初期OFF。
- 高精細ディザは480×320 / 8色を生成。
- ブラウザーからPNGを実際に保存。保存ファイルを独立して検査し、480×320、使用8色を確認。
- 拡大PNGは3840×2560。原寸PNGの最近傍8倍と全画素一致。
- 保存したPNGをファイル選択で再取込し、128×85 / 8色へ再変換。
- 320×740と通常の1280×720表示を確認。320px時のdocument.scrollWidthは320、表示中のボタン・選択欄・スライダーの横はみ出しなし。128×85画像を256×170で表示。画面幅の一時指定は解除済み。
- AI進行中はPNG・地球配置を無効化。終了後に有効化。中止ボタンの押下試行時には推論が先に完了したため、ブラウザーでの中断成立は未確認（AbortSignal接続は静的確認）。

## AIの品質判定
**動作は確認できたが、ゲーム素材として描き直す品質目標は未達。**
汎用の任意画風転写は、構図を残しながら画風見本の色と質感を反映した。しかし55%では人物の顔・服、動物の毛、風景の空、静物の背景に細かな斑点や余計な質感が増えた。25%では静物の色と形の保持は改善したが、手描きのドット絵に見られる意図的な形の省略や整った色面を安定して作れてはいない。
そのためAIを自動適用する標準方式にはせず、比較可能な試作として残した。これは一つの見本画像と4枚のサンプルによる目視評価であり、全画風・全写真に対する優劣判定ではない。

最初の実行ではWebGLの圧縮テクスチャ経路で縦縞が出た。公式移植元の設定に合わせてWEBGL_PACKを無効にし、実画像が生成されることを再確認した。この互換性設定を外さない。

## 撮影専用・直列AIの更新記録

- 詳細設定・比較・AI取消・写真取込・作例パネルを撤去。起動→AI処理済みプレビュー→撮影→PNG保存/再撮影のUIへ更新した。
- `createFrameLoop` は前の処理が終わるまで次のフレームを取得せず、完成結果だけを表示。停止・再開・カメラ切替では世代とAbortSignalで古い結果を捨てる。更新は500ms周期を目安に、重い時は完了まで待つ。
- カメラ入力で起動→128×72 / 24色の処理済み表示→撮影固定→PNG保存をブラウザーで確認。前後切替ボタン後も処理済み表示へ戻ることを確認。ただし実際に別の物理レンズへ切り替わったかと、スマートフォン実機での動作は未検証。
- 320px幅で横スクロールなし。ライブ時の3ボタンの左右端は36〜284pxで画面内。元videoは常時display:none。画面サイズ指定は解除し、検証用カメラは閉じた。
- フレームループ4件、変換5件、素材記録4件、ナビ3件の計16テストがPASS。構文検査もPASS。合成テストとブラウザー確認は別の証拠である。
- 公開写真4枚の別検証では、WebGL / AI最大192px / 強度25% / 出力128pxで、初回7055ms、別縦横比初回6561ms、その後同じ縦横比171ms・121ms。初期化/shapeのコンパイルを含むため、この4値を一般的なFPS保証に使わない。
- 画風特徴cacheは初回miss、残り3回hit。各回のTFJS tensorは353、論理保持17,360,384 bytesで一定。dispose後tensor/論理bytes/active GPU bytesは0。GPU再利用プールの確保は272,912,520 bytesのままなので「総GPUメモリがゼロ」「常時20MBで動く」とは言わない。
- 画質は汎用画風転写のままで、物体識別・線の意味的な描き直し・時間的一貫性を新たに学習したわけではない。
