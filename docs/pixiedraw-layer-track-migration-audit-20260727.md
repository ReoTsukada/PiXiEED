# PiXiEEDraw レイヤー軌道移行監査（2026-07-27）

## 目的

フレームごとの描画セルを安全に対応付け、レイヤー追加・削除・並び替えで別のレイヤーへ絵が入る不整合を防ぐ。

この段階では `frames[].layers[]`、既存の PXD、履歴、V2 チェックポイント／ジャーナルを維持する。`Map` を使う疎セル化や保存形式の全面変更は、計測で必要性が確認できるまで実施しない。

## 現在の正本

```text
document
└─ canvases[]（複数キャンバス時）
   └─ frames[]
      └─ layers[]
         ├─ id                 // セル固有 ID
         ├─ name / visible / opacity / blendMode
         └─ indices または indicesTiles（32 x 32 の疎タイル）
```

- `layer.id` はフレーム固有であり、同じ表示行の別フレームでは通常異なる。
- 現在のタイムラインは `layers[index]` を同じレイヤー軌道として扱う。この暗黙の位置対応が不整合の原因になる。
- 空の通常レイヤーは長さ 0 の TypedArray を使い、描画時にだけ実体化する。描画済みのコンパクト raster は 32 x 32 の `indicesTiles` に保持され、空タイルは削除される。
- フレーム複製は Copy-on-Write の raster 共有を使う。`layer.id` は複製セルごとに固有であり続けなければならない。

## 導入する ID の役割

```text
layerTrack.id  = キャンバス内で不変の軌道 ID
layer.id       = 1 フレーム内のセル ID（現行互換のまま）
frame.id       = フレーム ID
canvas.id      = キャンバス ID
```

第1段階は各 `layer` に `trackId` を追加するだけで、`state.activeLayer`、履歴、ジャーナルの `layerId` は変更しない。これにより、描画・選択・Undo の既存経路を維持しつつ、構造操作とタイムラインの対応関係を検証できる。

## 不変条件

1. 1 キャンバス内で各軌道の `trackId` は一意である。
2. 各フレームは各 `trackId` に対して最大 1 個のセルを持つ。
3. フレーム複製は `trackId` を維持し、`layer.id` は新規発行する。
4. 新しいレイヤー軌道の追加は、1 個の新しい `trackId` を発行し、全フレームに同じ `trackId` の空セルを追加する。
5. レイヤー並び替えは `trackId` を変えない。
6. 新しいレイヤーとしての複製は、新しい `trackId` と新しいセル ID を発行する。
7. 旧プロジェクトの補完時だけ、現在の配列位置を対応付けの入力にしてよい。補完後の通常操作では位置を識別子として扱わない。
8. 既存の画像データ、`indicesTiles`、`direct`、`importSourceDirect`、可視性、不透明度、合成方法を補完処理で変更しない。

## 旧プロジェクトの互換補完

`trackId` がない PXD／自動保存を読込む時は、次の順番で一度だけ補完する。

1. 現在の `repairLayerTracksAcrossFrames()` と同じ安全方針で、最も多いレイヤー数まで不足フレームを空セルで埋める。
2. 配列位置ごとに新しい `trackId` を 1 個発行する。
3. 全フレームの同じ位置のセルへその `trackId` を設定する。
4. `layer.id`、ピクセル情報、既存の `activeLayer` は保持する。
5. 次回保存時に `trackId` を永続化する。

旧形式には位置以外の軌道対応情報がないため、これは後方互換で復元できる唯一の決定的な規約である。不足セルは空セルとして扱い、他セルの絵を移動・複製しない。

## 変更対象と順序

### 第0段階（完了前の監査）

- `document-model.js`: 作成・複製・疎タイル・Copy-on-Write
- `document-serialization-utils.js`: PXD／自動保存の直列化と復元
- `timeline-layers.js`: タイムライン表示、レイヤー構造操作、セル移動
- `canvas-core-workflow-utils.js`: 現行セル ID によるアクティブ選択
- `local-project-journal-utils.js`、履歴・リサイズ・インポート: `layerId` を使う既存操作

### 第1段階（次の実装）

- `createLayer()` に任意の `trackId` を渡せるようにする。
- 新規文書・フレーム複製・レイヤー追加で同一軌道の `trackId` を維持する。
- シリアライズ／デシリアライズで `trackId` を保存し、旧形式へ上記規約を適用する。
- 読込み後および構造操作後に、`trackId` の欠損・重複・不足セルを修復する。

### 第2段階以降

- `canvas.layerTracks[]` に表示順と共通メタデータを移す。
- ランタイム専用の `Map<trackId, layer>` 索引を、構造変更時だけ再構築する。
- 履歴／ジャーナルを `canvasId/frameId/trackId` で表せるようにし、旧 `layerId` 記録を読込み互換として残す。
- 実測で空セルのオブジェクト数が問題になる場合に限り、`frame.layers[]` を疎な `cells` へ変更する。

## 計測する規模と指標

| 規模 | フレーム x レイヤー |
| --- | --- |
| 小 | 10 x 5 |
| 中 | 100 x 20 |
| 大 | 500 x 50 |
| 極端 | 1000 x 100 |

各規模で、読込み、レイヤー追加・削除・並び替え、フレーム複製、保存・復元、タイムライン初期描画・スクロールを測定する。平均値だけでなく p95、最大停止時間、生成オブジェクト数、GC 後に残るヒープを比較し、疎セル化の判断材料にする。

## 明示的に行わないこと

- 共有の空 `Map` を凍結して使い回さない。`Object.freeze(new Map())` は `Map#set` を止めないため安全ではない。空セルは当面、既存の遅延 TypedArray を維持し、将来は `storage: null` を使う。
- この移行に合わせてタイムラプス、共有、Voxel、シミュレーションの仕様を変更しない。
- 既存 PXD の画像データを再配置・再圧縮しない。
