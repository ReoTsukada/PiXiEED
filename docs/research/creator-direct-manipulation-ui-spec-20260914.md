# PiXiEED Studio 直接操作・ショートカット中心 UI 設計案

作成日: 2026-09-14  
対象: PC 版 iDRAW / iAUDIO / iGAME  
状態: 仕様基準。P0（入力所有権・Space操作）とP1（モード別タイムライン記憶、iAUDIOのSpaceパン）は実装済み。P2以降は既存UIの棚卸しに基づく段階実装対象。

## 1. 結論

PiXiEED Studio の初心者向け画面は、ツールや設定を探す画面ではなく、**中央の制作対象を直接触る画面**にする。

操作の優先順位は次の通りとする。

1. Canvas / Piano Roll / Stage 上の直接操作
2. その面にフォーカスがある時だけ有効になるショートカット
3. 選択中にだけ現れる Context UI
4. それでも必要な精密値だけ Inspector

ボタンを減らすこと自体を目的にはしない。直接操作だけでは発見できない操作、取り消し・再生・保存など安全性に関わる操作は残す。

既存の iGAME 5 レールや iDRAW / iAUDIO の内部状態は削除せず、PC 初心者画面では少数の視覚面へ投影する。詳しい設定画面や互換用レールは、必要な時だけ開く。

## 2. PC の共通画面構成

```text
┌────────────────────────────────────────────────────────────────────┐
│ Project   Undo  Redo     iDRAW  iAUDIO  iGAME     Save   ● Play     │  上部レール
├──────────────┬──────────────────────────────────────┬──────────────┤
│              │                                      │              │
│ Context      │                                      │ Context      │
│ Drawer       │          Canvas / Piano Roll /        │ Card         │
│              │                 Stage                │ 選択時のみ   │
│              │                                      │              │
├──────────────┴──────────────────────────────────────┴──────────────┤
│ Timeline / Track strip / Scene strip（必要なモード・状態だけ）       │  下部レール
└────────────────────────────────────────────────────────────────────┘
```

### 常時表示

- 現在の Project と保存状態
- Undo / Redo
- iDRAW / iAUDIO / iGAME の現在位置
- 状態に応じて Play または Stop へ切り替わる 1 枠の再生ボタン
- 現在操作している中央面

### 状態に応じて表示

- 左 Drawer: 素材、レイヤー、トラック、ツールなど、そのモードで必要なものだけ
- 右 Context Card: 選択中のノート、オブジェクト、範囲、フレームだけ
- 下部レール: iDRAW のフレーム／レイヤー、iAUDIO のトラック／クリップ、iGAME の Scene
- 変形ハンドル、スナップガイド、衝突範囲、再生ヘッドなどの一時オーバーレイ

### 常設しないもの

- 空の Inspector
- 「選択中」「オブジェクトを選択」など、状態を説明するだけの大きな文言
- Canvas / Stage 上に重なる操作ボタン
- Timeline、Sound / Music Timeline、Playground などの大きな見出しだけを持つ帯
- 直接操作と同じことをする Add / Move / Focus ボタン

ボタンが必要な場合は、上部レール、Drawer のヘッダー、選択対象の Context Card に寄せる。Viewport の上には置かない。

## 3. モード別レイアウト

### 3.1 iDRAW

```text
┌ Project / Undo / Redo ───── iDRAW ───── Save ─ Play ┐
├─短いツールレーン─┬──────── Canvas────────────┬─選択時のContext─┤
│ P Pen            │                            │ Transform       │
│ E Eraser         │  描く / 選択 / 変形        │ Outline         │
│ M Select         │  直接ハンドル             │ Text            │
│ H Pan            │                            │ 精密値          │
├──────────────────┴────────────────────────────┴─────────────────┤
│ Frame × Layer timeline / Palette drawer（必要時のみ）            │
└──────────────────────────────────────────────────────────────────┘
```

- ペン、消しゴム、範囲選択など、Canvas の形だけでは判断できない基本ツールは小さな固定レーンに残す。
- 線幅、アウトライン、テキストのサイズなどは、描画開始後または選択中に対象の近くへ出す。
- 選択範囲の拡大・縮小・回転・反転は枠のハンドルと Context UI を主役にする。
- フレームとレイヤーは下部のセルを直接クリック／ドラッグして変更する。Inspector の選択値を主操作にしない。
- パレットはスウォッチを主役にし、色名や HEX は精密編集時だけ出す。

#### iDRAW の直接操作

| 操作 | 動作 |
| --- | --- |
| ペン上で押してドラッグ | ストロークを描く |
| 選択ツールで空白を押してドラッグ | 範囲選択 |
| 選択中の描画を押してドラッグ | 移動。元描画はプレビュー中に表示上だけ切り取る |
| 選択枠の角をドラッグ | 拡大縮小。Shift で比率維持、Alt で中心基準 |
| 選択枠の外側ハンドルをドラッグ | 任意角度の回転。Shift はスナップ補助 |
| 選択枠の辺・中央ハンドル | 横／縦方向の変形 |
| Canvas 上で Alt を押しながらクリック | 一時的に色を取得 |
| Space を押しながらドラッグ | Canvas をパン |
| タイムラインのセルをクリック | フレーム／レイヤーを直接選択 |
| タイムラインのセルをドラッグ | 順序を移動。移動中は挿入位置を表示 |

変形は `開始 → プレビュー → 確定 / キャンセル` の一つのトランザクションにする。途中結果を正本へ書き込まず、確定時だけ履歴を一件追加する。

### 3.2 iAUDIO

```text
┌ Project / Undo / Redo ─── iAUDIO ─── BPM  Snap  ● Play ┐
├─Track list──────────┬──── Piano Roll / Arrangement ─┬─選択時Card──┤
│ Track                 │                              │ Note          │
│ Mute / Solo            │  ノートを直接編集            │ Clip          │
│ Instrument chip        │  小節を横に伸ばしすぎない    │ Quantize      │
├───────────────────────┴──────────────────────────────┴──────────────┤
│ Track / Clip strip または選択範囲のプレビュー（必要時のみ）          │
└─────────────────────────────────────────────────────────────────────┘
```

- iAUDIO では「描画モード」「選択モード」の切り替えを常設しない。
- ノート、クリップ、範囲そのものの形とポインター位置で操作を決める。
- 1 小節を常時詳細表示せず、表示幅に応じて小節線だけを間引き、横方向の作業領域を確保する。
- Track list は音源とミュート／ソロの入口に限定し、ノート編集は Piano Roll 上で完結させる。

#### iAUDIO のクリック種別

| 操作 | 動作 |
| --- | --- |
| 空白をシングルクリックして離す | 再生ヘッドまたは単一点の選択位置を更新 |
| 空白をシングルクリックしてドラッグ | ノート／クリップの範囲選択 |
| 空白をダブルクリックしてドラッグ | ノートを作成し、ドラッグ量で長さを決める |
| 既存ノートをシングルクリック | ノートを選択 |
| 既存ノートを押してドラッグ | ノートを移動。縦は音高、横は Tick |
| ノートの左右端をドラッグ | 長さを変更 |
| 選択されたノートを Alt ドラッグ | 複製して移動 |
| 選択範囲をドラッグ | 選択ノートをまとめて移動 |
| クリップの境界をドラッグ | クリップの長さを変更 |
| 再生ヘッドをドラッグ | 任意位置へスクラブ |
| Ctrl / Command + ホイール | ポインター位置を中心に時間ズーム |
| Shift + ホイール | 横スクロール |
| Space + ドラッグ | Piano Roll をパン |

ダブルクリックで作成する場合、最初のクリックだけでノートを作らない。クリックとドラッグによる範囲選択を優先し、二回目のクリックが一定時間内に成立した時だけ作成プレビューへ移る。

#### iAUDIO の選択後操作

- `Delete` は選択されたノート／クリップだけを削除する。
- `S` は選択クリップを再生ヘッド位置で分割する。
- `Q` は選択範囲にクオンタイズのプレビューを表示し、`Enter` で確定する。
- `Cmd / Ctrl + C / X / V` はノートまたはクリップ単位で扱う。
- 複数選択は Shift クリック、範囲選択は空白ドラッグとする。
- 選択中だけ、ノートの開始位置、長さ、音高、ベロシティなどの精密値を Context Card に出す。

### 3.3 iGAME

```text
┌ Project / Undo / Redo ─── Scene  Game ─── Save ─ ● Play ┐
├─Asset Drawer─────────┬──────── Stage ───────────────┬─選択時Card──┤
│ 絵 / アニメ / 音       │                              │ 動き          │
│ My assets / Market     │  ドラッグ配置・直接移動      │ 触れたら      │
│ 検索                  │  何も重ねない                │ 当たり判定    │
├───────────────────────┴──────────────────────────────┴──────────────┤
│ Scene thumbnails / 入口・出口の関係                                 │
└─────────────────────────────────────────────────────────────────────┘
```

- Asset Drawer のカードを Stage へドラッグすると、配置ゴーストを表示してドロップ時に置く。
- Stage 上の対象はクリックで選択、ドラッグで移動、Shift で追加選択する。
- 選択対象の周囲に、動き・接触・会話・削除などの Context Card を出す。
- Scene / Game の切り替えは上部中央に置く。中央 Stage の面積を削らない。
- Scene、階層、Inspector は内部契約として残しても、初心者面では常設しない。
- Scene strip はサムネイル中心とし、Scene 数が少ない場合は高さを自動的に縮める。
- Play 中は Drawer、Context Card、Scene strip を縮退させ、Stage を最大化する。

#### iGAME の直接操作

| 操作 | 動作 |
| --- | --- |
| Asset card を Stage へドラッグ | 素材を配置 |
| Stage 上の対象をクリック | 対象を選択 |
| 選択対象をドラッグ | 配置を移動。グリッド吸着は Shift で切り替え |
| Stage の空白をドラッグ | 範囲選択 |
| Alt ドラッグ | 対象を複製して配置 |
| 対象をダブルクリック | その対象の動き Context を開く |
| Scene thumbnail をクリック | Scene を切り替え |
| Scene thumbnail をドラッグ | Scene の順序を変更 |
| Stage 上の入口／出口ハンドルをドラッグ | Scene 接続を作成 |
| `F` | 選択対象へフォーカス |
| `0` | Stage 全体を表示 |

Play 中は編集用の移動キーを Runtime へ渡す。編集中の Stage では、選択対象がある時だけ矢印キーで位置を微調整する。

## 4. フォーカスとショートカットの所有権

同じキーを全画面で解釈しない。画面を次の `activeSurface` に分け、イベントは一つの所有者だけが処理する。

```text
DRAW_CANVAS       iDRAW Canvas
DRAW_TIMELINE     iDRAW フレーム／レイヤー
AUDIO_ROLL        iAUDIO Piano Roll
AUDIO_ARRANGEMENT iAUDIO クリップ／タイムライン
GAME_STAGE        iGAME 編集 Stage
GAME_SCENES       iGAME Scene strip
ASSET_DRAWER      素材 Drawer
FORM              input / textarea / select / contenteditable
DIALOG            Modal / command palette
RUNTIME           iGAME Play 中
```

イベント処理の優先順位は次の通りとする。

1. IME 入力中、フォーム、ダイアログはブラウザーとその UI を優先
2. Pointer capture 中は、開始した面が終了またはキャンセルまで所有
3. iGAME Play 中は Runtime が所有
4. それ以外は `activeSurface` のコマンドだけを解決
5. 所有者がないキーは `preventDefault()` せず、ブラウザーへ返す

### 共通キー

| キー | 共通動作 | 条件 |
| --- | --- | --- |
| Cmd / Ctrl + Z | Undo | フォーム入力中を除く |
| Cmd / Ctrl + Shift + Z | Redo | フォーム入力中を除く |
| Cmd / Ctrl + C / X / V | 選択対象のコピー／カット／貼り付け | activeSurface が編集面 |
| Cmd / Ctrl + S | 保存 | 保存中は二重実行しない |
| Escape | 現在のプレビューをキャンセル → Context を閉じる → Play を終了 | 優先順位順に一段だけ処理 |
| `?` | 現在の面だけのショートカット一覧 | フォーム入力中を除く |
| Cmd / Ctrl + K | コマンド検索 | ダイアログがない時 |
| Space | Play / Stop | 編集面が所有している時だけ。押下中にパンを始めた場合は再生しない |

### iDRAW

| キー | Canvas に選択範囲がある | Canvas に選択範囲がない |
| --- | --- | --- |
| Arrow | 選択範囲を 1 px 移動 | フレーム移動（左右）／レイヤー移動（上下） |
| Shift + Arrow | 選択範囲を 8 px 移動 | フレーム／レイヤーを一単位移動 |
| `[` / `]` | 前後フレーム | 前後フレーム |
| `P` / `E` / `M` / `H` | ペン／消しゴム／選択／パン | 同左 |
| `Enter` | 変形／選択プレビューを確定 | 下書き選択を確定 |
| `Delete` | 選択範囲を削除 | Canvas 上では何もしない |

矢印キーはモード変更に絶対に使わない。iDRAW のフレーム／レイヤー変更と選択範囲の微調整は、**選択の有無**で分ける。

### iAUDIO

| キー | Piano Roll に選択ノートがある | 選択がない／別面 |
| --- | --- | --- |
| Arrow | ノートを Tick／音高方向に移動 | Piano Roll では再生ヘッドまたは選択位置を移動 |
| Shift + Arrow | 1 小節単位で移動 | 横方向の範囲移動 |
| `S` | 選択クリップを分割 | 何もしない |
| `Q` | クオンタイズプレビュー | 何もしない |
| `Enter` | 保留中の編集を確定 | 何もしない |
| `Delete` | 選択ノート／クリップを削除 | 何もしない |
| Space | 再生／停止 | Runtime へは渡さない |

### iGAME

| 状態 | 矢印／WASD | Space | Escape |
| --- | --- | --- | --- |
| Stage 編集中 | 選択対象を微調整 | Play / Stop | 配置・選択プレビューをキャンセル |
| Scene strip にフォーカス | Scene を移動 | Play / Stop | Scene 操作をキャンセル |
| Play 中 | Runtime のプレイヤー移動 | Project が割り当てた入力だけ Runtime へ渡す | Play を終了 |

モード切り替えは矢印キーに割り当てない。キーボードでの切り替えを追加する場合は `Alt + 1 / 2 / 3` のような専用組み合わせだけにし、ブラウザーの標準ショートカットと衝突しないことを確認する。

## 5. Space が直前のボタンを再実行しない仕組み

「ボタンをクリックした後に Space を押すと、そのボタンが再度押される」問題は、見た目の配置ではなくフォーカス所有権の問題である。

実装時は次の契約にする。

- 上部の Play / Stop 以外のボタンには、操作完了後に元の制作面へ戻るフォーカス先を持たせる。
- Play / Stop は常に同じ DOM 枠で状態だけを切り替える。
- Space は `keydown` で `spaceIntent` を保留する。押下中にポインター操作が始まったら Playback command を発行せず、Space＋ドラッグのパンへ移る。ドラッグせずに `keyup` した時だけ Playback command を一度発行する。
- `keydown` と `keyup` のどちらでもフォーム・IME・ダイアログでは介入せず、ブラウザーの標準動作を優先する。
- Playback を確定したイベントでは `preventDefault()` と `stopPropagation()` を行い、ボタンのクリック合成を止める。
- Space の `keyup` で再生を再発行しない。長押しリピート、ブラウザーのクリック合成、二重イベントを無視する。
- ダイアログを開いた場合はフォーカスを戻さず、ダイアログを閉じた時に開く前の面へ戻す。

これにより、保存・追加・削除など直前に触ったボタンを Space が誤って再実行しない。

## 6. 直接操作を理解させる視覚フィードバック

説明文を常時並べる代わりに、状態を視覚で伝える。

- Asset を持っている時: Stage 上に半透明の配置ゴースト
- 移動中: 元位置は表示上だけ消し、移動先だけを表示
- 変形中: 枠、角ハンドル、回転ハンドル、スナップガイド
- ノート作成中: 始点、長さ、音高、吸着先を薄いプレビューで表示
- 選択中: 強い選択色を一つだけ使い、対象外を少し暗くする
- 再生中: Play 枠を Stop に変更し、再生ヘッドと面の状態を同期
- 操作不可: ボタンを消すのではなく、対象を薄くし、カーソルと短い一時メッセージで理由を示す
- ショートカットの発見: `?` または短いホバー Tooltip で現在の面の操作だけを表示

Viewport 上に常設する長文、モード名だけの見出し、選択状態を文章で繰り返す UI は置かない。

## 7. ボタンの残し方

### 残す

- Undo / Redo
- Save 状態と必要時の Save
- Play / Stop の一体型ボタン
- iDRAW の基本ツール入口（Pen / Eraser / Select / Pan）
- iAUDIO の Record など、直接操作だけでは開始できない操作
- `?`、コマンド検索、必要なダイアログの閉じる操作

### 選択時だけ残す

- 変形の確定／キャンセル
- ノートの Quantize、Split、Humanize
- iGAME の動き・接触・会話の追加
- 精密な数値入力、Pivot、Collision の詳細

### 主面から外す、または統合する

- iGAME の Viewport 上の Add / Focus / Fit ボタン（Asset ドラッグ、`F`、`0` へ統合）
- 「選択中」「オブジェクトを選択」だけを表示するラベル
- iAUDIO の常設ツールモード切り替え
- iDRAW の Timeline と Layer の重複操作
- 直接操作で同じ結果になる重複ボタン

完全に削除する前に、`?`、Context Card、右クリックメニュー、コマンド検索のいずれかに到達経路があることを確認する。

## 8. 内部実装境界

ポインター操作とショートカットは別ロジックにしない。同じコマンドへ変換する。

```text
Pointer / Keyboard
        ↓
Input ownership resolver
        ↓
Canonical command
  select / move / duplicate / delete / split
  openContext / play / cancel / commit
        ↓
Preview transaction or canonical state mutation
        ↓
History / render / persistence
```

### 必要な内部概念

- `activeSurface`: 現在キーを受け取る面
- `pointerCaptureOwner`: ドラッグを終了まで所有する面
- `interactionPhase`: idle / preview / committing / cancelling
- `commandSource`: pointer / keyboard / button
- `returnFocusTarget`: ボタン操作後に戻る制作面
- `perModeViewportState`: モードごとのズーム、スクロール、Timeline レイアウト

モード切り替え時は、前モードの一時ドラッグ状態、Pointer capture、Context Card だけを安全に閉じる。各モードのズームと下部レール寸法は共有しない。これで、前モードの Timeline レイアウトが次モードを削る問題を防ぐ。

現行コードではショートカット定義が [draw2-shortcuts.ts](../../pixiedraw2/src/draw2-shortcuts.ts)、iDRAW の共通キー処理が [draw2-entry.ts](../../pixiedraw2/src/draw2-entry.ts)、iAUDIO / iGAME のワークスペース処理が [wp180-workspace-ui.ts](../../pixiedraw2/src/wp180-workspace-ui.ts) に分かれている。次の実装では、各モジュールの機能を消さずに、最終的な所有権だけを `activeSurface` で一つに解決する。

## 9. 実装順序

### P0: 入力所有権の共通化

- `activeSurface` と `pointerCaptureOwner` の状態を定義
- Form / IME / Dialog の除外を一か所に統合
- Space、矢印、Escape、Delete の優先順位をテスト
- ボタン操作後のフォーカス復帰を共通化

### P1: モードごとのレイアウト状態分離

- iDRAW / iAUDIO / iGAME の下部レール高さ・スクロール・ズームを分離
- モード切り替え時に一時 UI と Pointer capture を解放
- Viewport 上の常設ボタンと長いラベルを主面から外す

### P2: iAUDIO の直接編集

- 空白ドラッグ選択、ノートドラッグ移動、端ドラッグ伸縮
- ダブルクリック＋ドラッグのノート作成プレビュー
- 選択ノートのコピー、カット、貼り付け、複製、分割、削除
- 1 小節を過度に拡大しない時間グリッドとポインター中心ズーム

### P3: iGAME の Stage 操作

- Asset Drawer から Stage へのゴースト配置
- Stage 上の選択、複数選択、移動、複製、削除
- 選択対象だけの Behavior Context Card
- Scene strip の直接切り替え、並べ替え、入口／出口接続

### P4: iDRAW の直接編集

- Canvas の選択枠と変形トランザクション
- Timeline セルの直接操作
- 選択あり／なしで矢印キーの意味を分ける
- パレット、アウトライン、テキストの Context UI 化

### P5: 視覚的な学習補助と検証

- カーソル、ゴースト、ハンドル、スナップ、選択色の統一
- `?` で現在面だけの操作一覧を表示
- PC の主要解像度で、Viewport にボタンや長文が重ならないことを確認

## 10. 受け入れ基準

### iDRAW

- ペンで押してドラッグすると描ける
- 選択範囲をドラッグ移動・拡大縮小・任意角度回転できる
- 変形中に元描画が二重表示されない
- 確定は履歴一件、キャンセルは元状態、Undo / Redo が一致する
- 選択中の矢印は移動、選択なしの矢印はフレーム／レイヤー操作になる

### iAUDIO

- ダブルクリック＋ドラッグでノートを作れる
- シングルクリック＋ドラッグで範囲を選べる
- ノートをドラッグして移動でき、表示を離しても位置が戻らない
- 選択ノートをコピー、カット、貼り付け、複製、分割、削除できる
- Space は再生／停止だけを行い、直前のボタンを再実行しない
- 1 小節の詳細表示が原因で全体の横幅を失わない

### iGAME

- Asset Drawer から Stage へ素材を直接配置できる
- 配置済み対象を直接移動・複製・削除できる
- 選択時だけ動きや接触の設定が見える
- Play 中は Runtime がキーを所有し、編集用操作と混ざらない
- Scene / Game の切り替えが上部中央にあり、Stage を狭めない

### 全モード

- 矢印キーがモード切り替えに使われない
- Space が直前に触ったボタンを再実行しない
- Input / IME / Dialog の入力を壊さない
- モード切り替え後に下部レールのレイアウトが欠けない
- ポインター操作とショートカットが同じ履歴・保存経路を通る
- 常設ボタンを減らしても `?`、Context UI、コマンド検索から到達できる

## 11. 採用理由

PICO-8 の「一つの制作環境内ですぐ試せる」一体感、GB Studio の「Game World 中心で素材を配置する」構造、RPG Maker のマップ直接操作、Scratch の対象中心の操作を採用する。Construct / GDevelop / Flowlab の拡張性は上級面へ、GameMaker / Godot / Unity の Object・Instance・Animation・Delivery の分離は内部データへ取り込む。

調査の詳細と各製品の比較は [iGAME ゲーム制作 UI 調査](./igame-game-creation-ui-research-20260914.md) にまとめている。
