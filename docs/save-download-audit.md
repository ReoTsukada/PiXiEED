# 保存・ダウンロードの確認と文言案（2026-10-06）

今回の確認はローカルコードを根拠にした棚卸し。自動保存機構や全ツールの名称は変更していない。

## かんたんドットの自動保存

- 共通作品管理の `markDirty()` が呼ばれた編集後、最後の呼び出しから **1秒後** に保存する。定期実行ではなく、編集のたびに待ち時間を取り直す。描画確定、Undo/Redo、色変更、コマやレイヤーの編集などが対象。
- 先行する編集のタイマーが描画中に発火しても、Drawの `getProject()` は確定済みのアニメーションを取得する。指離れで描画を確定した後に再度保存を予約する。未確定の選択変形プレビューも確定作品へ混入しない。色編集パネルを開いている間は現在のパレットを取り込む。
- 画像部品、アニメーションのコマ・レイヤー・パレット、ツールの編集状態をPXD作品として同じブラウザー・同じサイトの **IndexedDB (`pixieed-pxd-v1`)** に保存する。ファイルのダウンロードやサーバーへの作品公開ではない。
- 保存済みの作品ID・保存版IDをURLとlocalStorageに記録する。URLに指定された保存版から再読込し、別の新規タブでは作品一覧から保存済みの作品を選ぶ。端末やブラウザーを替えた際の同期は、この端末内保存には含まれない。
- 編集開始前、作品選択待ち、作品切替などのロック中、保存失敗状態、公開作品の参照中には自動保存を予約しない。保存中に内容が変わると、その新しい編集を保存済み扱いにはしない。
- 保存失敗は「保存失敗」とエラー文で表示し、編集内容はタブに保持する。次の編集または手動保存で再試行できる。同じ作品を別タブが先に更新した場合は上書きせず、複製か最新版を開く操作へ案内する。
- タブ終了時は未保存変更・保存中なら `beforeunload` の確認を要求する。終了時に必ず保存を完了させる仕組みではないため、直前1秒以内の編集は「保存済み」になったことを確認してから閉じる。Drawは非表示・終了時に入力と未確定変形を解除する。
- 「作品を保存」の手動操作は共通PXD保存に加えて従来の端末内再開用コピーも保存する。自動保存は共通PXD作品を保存するため、両者をファイルのダウンロードと同じ名称にしない。

根拠：`js/creation/project-workspace.mjs`（`scheduleAutoSave` / `markDirty` / `save` / 初期復元 / `beforeunload`）、`project-session.mjs`（更新競合と保存中の編集）、`pxd-store.mjs`（保存先）、`draw-page.mjs`（描画確定・`getProject`・手動保存）。

## 提案

上部の入口を「ファイル」にそろえ、パネルで形式を選び、実際の取得操作を「ダウンロード」にそろえる案がよい。ただし現行のDraw/Audioは対応スマホでOS共有を開くため、処理を維持したまま全ボタンを「ダウンロード」と呼ぶと動作が名前と合わない。最終操作を「ダウンロード」と「写真・アプリに保存」に分けるCamera方式を共通化する案が適している。

端末内の編集継続は作品名の横の「編集中／保存中／保存済み」で示し、手動保存は「このブラウザーに保存」。公開は「投稿」、プレイURLは「共有／URLをコピー」と分ける。編集用PXDを別端末へ持ち出す操作を今後追加する場合は「編集データをダウンロード（PXD）」とする。現行の「原本PXDを保存」は読み込んだ原本の取得であり、現在の編集内容の汎用PXD出力と混同しない。
