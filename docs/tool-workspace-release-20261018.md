# Dedicated tool workspace entry

The Draw, camera and audio pages retain their static introductions, canonical URLs and search content. Home and tool-directory use links open the selected mode directly in the working view. The introduction starts the editor with one action, and the same editor stays mounted while switching between explanation and work.

The three modes share the existing creation runtime in the page. The explicit `runtime=iframe` fallback and other iframe consumers remain available. Old shared project URLs, duplicate query values and hashes retain their compatibility paths. Existing camera permissions and explicit playback actions remain necessary; returning to explanation stops media without automatically restarting it.

The direct host keeps its draft pointer separate from older workspaces. Explicit project imports preserve their source archive, and recovery or save conflicts retain the current work. Mobile layout follows visual viewport resize and pan, keeps the five bottom operations reachable, and constrains text, project and music controls to the visible area. The existing benefits dialog remains available from both explanation and work without changing advertising, consent or analytics policies.

Identical compatibility preflight code in the three entry documents is shared in one synchronous script. Legacy iframe return channels and independent camera/audio handoff routes retain their existing handling. Game editing keeps both the small-document iframe and large legacy-document engine.

## Local verification before release

- Canonical Node suite: 333 test files, 2,239 passing assertions, no failures.
- Dedicated entry checks: 12 cases / 51 checks in Chromium and WebKit.
- Deep state, conflict, history and export checks: 6 cases / 13 checks in each engine. Final WebKit checks received native PNG and WAV downloads and exited cleanly.
- Mobile visual viewport checks: 6 cases / 40 checks per engine, plus the same 6 cases / 40 checks against the built site. Coverage includes 320px and 390px, landscape, simulated keyboard shrink/pan, unobscured save/output targets and the existing benefits dialog.
- Initialization and synthetic media lifecycle: 12 cases / 13 checks. Legacy project fixtures: 9 cases / 18 checks.
- Retained iframe compatibility: 18 cases. Puzzle editing: two concrete engine paths with edit, Undo/Redo, original comparison and finish checks.
- Real local HTTP cache upgrades from two earlier source snapshots: six variants each, current asset hashes matched, no external requests.
- Pages artifact: 801 static files and 121 event pages before the CI-generated public puzzle pages. Sitemap and canonical consistency are covered by the SEO and generator tests.

Tests use isolated storage and synthetic images, audio and camera streams. External ad requests, real analytics sends, public posts and existing personal projects were excluded. The existing WebKit test adapter handles one unsupported optional protocol setting in memory; installed browser and SDK files are unchanged. Individual page-close waiting also stalled on empty pages with this installed driver/browser pair; awaiting context and browser teardown lets the complete suite finish without dropping assertions.

The canonical test command explicitly selects `tests/**/*.test.mjs`. An additional default-discovery run also found old documentation snapshots and files intended for other runtimes; its failures are recorded separately and are not presented as fixed.

## Limits and retained compatibility

Physical iOS/Safari, OS keyboard behavior, actual device rotation, real camera/microphone permission prompts and production user cache revisits remain unverified. Synthetic visual viewport checks do not replace device testing. No browser settings, permission grants or new dependencies were required.

The earlier controlled local direct/iframe comparison informs retaining the direct default and explicit fallback. Performance was not remeasured for this final layout polish. No general speed or SEO advantage from removing iframes is claimed. Further iframe retirement requires equivalent browser, old-project, media, focus and game-editor coverage for each consumer.

Private local evidence and Library-backed preview images are retained outside Git. The release does not include raw logs, local machine paths, Library identifiers or project backups.
