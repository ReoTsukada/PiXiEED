# ファイル変換の簡素化と対応形式拡張

## 目的・設計判断
利用者は説明を選ぶことではなく、手元のファイルを目的の形式で保存したい。
既存機能・データ受渡し・安全上限のみを設計の入力とした。

独立した3案を比較した。
- 形式一覧から選ぶ辞書型: 珍しい形式の発見には便利だが、入力前から選択肢が多い。
- 手順ごとのウィザード型: 初見には明確だが、往復と画面遷移が増える。
- ファイル先行の一画面型（採用）: 入力を確認してから選べる保存形式だけを提示。詳細設定は必要時に開く。
これは設計判断であり、利用者実験による優位性の証明ではない。

## 契約
- /output/ は短い案内と既存の広告枠。ファイルを扱わない。
- /output/work/ は初期状態を簡易変換にする。作品ID付きの既存URL・詳細モードは従来の作業画面を維持する。
- 読込、準備完了、作成中、保存可能、失敗を明示する。失敗で元ファイルを破棄しない。
- ファイル内容・名前をサーバーや広告・計測へ送信しない。追加コーデックは自サイトのWorkerで処理する。
- 通常の変換エンジンは再利用。対応条件を満たさない派生形式は明示して拒否する。
- 珍しい形式を拡張子だけ変更して作ったことにしない。MIME・実体・外部デコーダーで検査する。
- 既存の動画合成・アニメーション・制作データの受渡しは詳細画面に残す。
- 広告配置・課金条件・制作エディタは変更しない。収益向上の実測を実装完了と混同しない。

## 対応範囲
新規: BMP（非圧縮1/4/8/24/32bit入力、24bit出力）、TGA（グレー/24/32bit、RLE入力・32bit出力）、QOI、PBM/PGM/PPM、TIFF（単一ページ・非圧縮8bit・RGB/RGBA/グレー）、AIFF（非圧縮PCM）、AU（線形PCM）。ICOはPNG内包のみ読み込み、PNG内包の単一サイズで出力。
画像は4096px/800万画素、ファイル64MB、音声120秒/8–48kHz/1–2chまで。多ページTIFF、圧縮TIFF、AIFC、MP3書出し、HEIC等を対応済みとは表記しない。

## 検証記録
- 新規Node単体テスト44件成功。破損データ、過大サイズ、透過、階調、音声サンプルレートとチャンネルを検査。
- Pillowで作成した画像、FFmpegで作成した音声を入力し、画素・PCMサンプルを独立照合。出力もPillow/FFprobeで読み込み確認。
- Chromiumの分離DOM検査95項目成功。実コーデックによる変換・保存クリック、MP3/FLAC入力、WebM音声出力、失敗後の再利用、320～2560pxと横向きを検査。
- 案内の分離DOM検査15項目成功。共通CSS、折りたたみ、キーボード、縦型・矩形の模擬広告枠を検査。広告SDK・実広告は呼ばない。
- 検査環境のネットワーク遷移制限により、コーデックWorkerは検査内だけで同じソースをBlobにまとめて実行した。本番のHTTPモジュールWorker読み込み、共通JS全体、実機Safari/iOSを検証したものではない。アニメーション入力はこの環境で非対応メッセージになることを確認し、全コマ変換の成功とは扱わない。
- 全体テスト・ビルド・本番確認はGitHubの検査結果と別途照合する。旧詳細画面へのファイル引き継ぎは分離テストではコールバックまでで、完全な統合動作の証明ではない。
